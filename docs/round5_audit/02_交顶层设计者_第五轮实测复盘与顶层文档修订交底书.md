## 一、背景补齐：当前插件是怎么实现的？第五轮测试到底发生了什么？

### 1.1 当前插件（`greatwall-v6up/` v3.0）的真实实现形态
在进入第五轮测试前，插件已经按 `04` / `09` / `agent_kb/05` 完成了 v3.0 重构，运行在 **DeepSeek Harness Desktop (`0.2.2-rc.3`)** 上，结构分为两层：
1. **Python 控制面与状态机内核（`core_python/`）**：
   - 使用 SQLite WAL 持久化 17 组核心表 + 3 条硬触发器 + `uq_l3_verified_review` 唯一索引，库文件与快照、隐藏校准集物理隔离在被测工作区之外的 `$PLUGIN_DATA/workspaces/<ws_hash>/`。
   - 暴露 7 大角色共 31 个单一职责窄工具（通过 stdio JSON-RPC 2.0 通信），以及仅供 Node 编排器调用的 `control_plane/*` 单写原语。
2. **DSH Cordis 插件控制面（`dsh_plugin/`）**：
   - 通过 `greatwall_orchestrate` 工具暴露 `init / start / pause / resume / stop / human_stop / status / intervene` 控制入口。
   - **编排器（`orchestrator.js`）**：纯确定性异步轮询循环，每次调 `control_plane/schedule_snapshot` 拉 SQLite 快照，按阶段派发 5 类无状态治理短会话（`library_surveyor`、`logistics_coordinator`、`library_verifier`、`works_engineer`、`supervisory_committee`）与并发探索者槽位（默认 6 槽）。
   - **单节点伴随配对（`pair_lifecycle.js`）**：落实顶层**方案 A**——每个探索节点创建 1 个 `lineage_companion` 会话，`PRE_SPAWN` 写完看板后开启 `keepAliveAfterIdle: true` 挂起保活留在内存 `liveSessions` 中，待 `37%` 与 `70%` 时用 `continueAliveAgent` 续传，节点结束时销毁。
   - **沙箱 Guard（`read_isolated_sandbox.js`）**：在 `agentCtx.tools.guard` 中做同步路径和 Shell 命令拦截，把 `explorer` 与 `lineage_companion` 锁死在各自 `worktrees/<branch_id>/` 内，把 `library_verifier` 锁死在现建现删的 `blind_sandbox_<review_id>/` 内。

## 二、已最终拍板的 8 项修订决议（逐项详述原由与文档修改位置）

经过项目负责人与工程侧多轮对照 `手写project.md`、`04` 白皮书、`09` 工程总说明书与 `agent_kb/01–05` 逐字核查，以下 **8 项决议已全部拍板**，请顶层设计者据此修订对应文档：

---

### 决议 1：彻底砍掉 `Cost Note`，上下文时钟基数改为 `min(500k, 模型真实物理窗口)`，坚持硬性跑满 `37% → 70%`
- **原顶层文档写法**：
  - `04` 白皮书 L199, L321, L343–344、`09` L177–186、`agent_kb/02` L23、`agent_kb/05` L29, L39：写死了固定分母 `500,000`，且将交接条件写为 **`70% (350k) / Cost Note`**（边际成本倒挂提前交接）。
  - `docs/round5_audit/01_顶层复核回复` L35, L96 曾提出“允许探索者在产出完整可验证工件时提前交接”。
- **为什么必须修订（原由）**：
  1. **为什么砍掉 `Cost Note` 且不留任何提前逃跑后门**：遵照 `手写project.md` L11（钱学森原理）与 L29（反 LLM 怠惰）——`Cost Note` 本意虽好，但**在实际运行中根本没有可靠、无感的确定性判定标准**！一旦给探索者留了“自称写完 / 触发模糊 Cost Note 就能在 `<70%` 提前下班”的口子，天生怠惰的大模型就会在跑了 3 轮、写个粗糙脚本后就草率交差，直接破坏长周期深度攻坚机制；反之用各种启发式脚本去猜“算不算乏力”，又会陷入“无数自以为好的小模块互相引发灾难”的泥潭。
  2. **为什么分母改为 `min(500k, 模型真实物理窗口)`**：当初设 `500k` 是因为 DeepSeek 官方 1M 窗口太大（70%=700k 太贵），减半按 `500k`（37%=185k，70%=350k）最实惠有效；但若遇到物理窗口更小的模型（如 272k 或 128k），写死 `500k` 会导致 `70% = 350k` 从数学上**永远无法到达**。取 `min(配置上限 500k, 模型真实物理窗口)` 既保留了 1M 模型按 `500k` 封顶的初衷，又彻底消灭了小窗口模型死锁。
  3. **唯一合法 `<70%` 停下的情形（全为 100% 客观状态）**：仅当发生**外部不可抗终态**（`human_stop`、`closure_allowed`、`abort_node`、DB 中节点已被外部关闭）或**真报错/断线异常中断**（转 `CRASH_RECOVERY` 抢救）时停止；正常探索**必须硬性跑满 `37% 反思 → 70% 清醒交接`**，不设逃避后门。
- **建议顶层修改位置**：
  - `04` 白皮书（L75, L199, L317–321, L343–344）、`09` 工程总说明书（L19, L177–186, L307）、`agent_kb/02`（L23）、`agent_kb/05`（L29, L39, L147, L194–196）：
    - 删除所有 `Cost Note` / `_cache_advice` 提前交接表述，收敛为唯一清晰口径：**有效窗口 `W = min(configured_cap_500k, model_physical_window)`，硬性走完 `37%` 反思与 `70%` 两步清醒交接**（JS 与 Python 共享 SQLite 同步的单一 `W`，不再各算各的）。

### 决议 2：整块删除 `intervene / steer` 实时广播与持久化便签条，回归「公开输入/裁决文档共享 + 极简确定性启停」
- **原顶层文档写法**：
  - `09` L22, L112, L143, L173：要求编排器支持 `interventions` 实时投递运行中会话，并持久化到冷启动时的 `assembleStatelessPrompt` 拼接注入。
- **为什么必须修订（原由）**：
  1. **与多个核心子系统正面相撞**：第五轮实测已证明，向在线会话池广播 `steer` 会直接吵醒保活休眠的只读伴随（抢跑交接 + 刷 6 张 `PAIN_POINT`），若盲审官、监察委或后勤恰好在线，还会直接击穿盲审隔离或打断短事务落库。
  2. **双真源冲突**：公开题面、输入数据和人类补充说明本就该统一放在工作区公开文件夹中供所有角色读取；再额外维护一套内存/消息式的“持久化便签条注入”，只会造出两套互相打架的真源。
  3. **极简原则**：探索者本就是短命可抛弃节点。温和澄清 → 主控往公开输入/裁决文件夹放一份《补充裁决文档》，所有角色自动只读可见；严重跑偏 → 主控 `pause` → 补文档 → `abort_node(node_id)` 精准杀掉跑偏探索者并同步销毁其私有伴随、在 SQLite 标终态 `CLOSED` 释放槽位 → `resume`。零广播、零多余会话池、零串扰。
- **建议顶层修改位置**：
  - `09` 工程总说明书（L22, L112, L143, L173, L338）：删除全部 `interventions` / `steer` 实时投递与冷启动注入要求，改写为「公开输入与《补充裁决文档》共享 + 极简控制动作（`init / start / pause / resume / stop / human_stop / abort_node / status`）」。

### 决议 3：明确沙箱第一性方向——“开放外部到内部（公开题面/裁决只读），严防内部到外部（防 Reward Hacking）”
- **原顶层文档写法**：
  - `09` L192 写要求 Windows 宿主动态配置 `Windows OS DACL Deny ACE` 或创建独立低权限系统账户；`09` L198 虽口头写了“仅限自身 `worktree_abs_path` 与公开题面”，但未规定公开题面/补充裁决文档的物理挂载与路径放行机制。
- **为什么必须修订（原由）**：
  1. **外部 → 内部必须打通**：第五轮因为 `fork_branch` 建完空 worktree 后未挂载公开题面，Guard 又一刀切拦截分支外一切 `read`，导致探索者开局集体盲人摸象做错题。公开题面、公开输入数据与《补充裁决文档》应统一放在工作区公开区（如 `inputs/`、`source_materials/`、`rulings/` 及顶层公开文档），所有角色开箱只读可见，并在 `fork_branch` / `resume` / 盲审沙箱构建时同步至 `<sandbox>/inputs/`。
  2. **内部 → 外部必须严防死守（绝不削弱防 Reward Hacking）**：
     - 探索者写权限死锁在本分支 `worktree`（盲审官 0 写权限、物理断网）；
     - 严禁读取/触碰 `greatwall.db*`、`_hidden_calibrations/`、`evaluators/`、其他分支 `worktrees/`、`final_delivery/` 及工作区外一切非白名单路径；
     - 正式评测与隐藏校准集只在 Python 控制面隔离服务端执行，探索者物理拿不到校准集源码；
     - 修复中层沙箱正则两处误杀 Bug（Windows 盘符正则缺左边界把 `https://` 切成 `s://`；拦截 DSH 自身只读溢出文件 `os.tmpdir()/dsh-spill-*`），但不放宽任何内部向外逃逸防线。
  3. **修正 `09` L192 不切实际的 Windows ACL 要求**：普通 Windows 桌面版动态给目录刷 `icacls /deny` 或建低权限系统账号既需要管理员提权，一旦崩溃残留 Deny ACE 还会把用户本人锁死在目录外。应改写为务实分层表述：**桌面直跑版采用「工作区外 `$PLUGIN_DATA` 隔离 + 环境变量隔离 + 路径/命令同步 Guard + 盲审独立只读临时目录」；未来若需 OS 内核级硬防高阶恶意脚本扫盘，接入 Docker / WSL2 容器隔离（而非篡改宿主机 Windows ACL）**。
- **建议顶层修改位置**：
  - `09` 工程总说明书（L21, L86, L192–204）、`04` 白皮书沙箱章节：明确“开放外部公开输入进内部、严防内部向外部逃逸”双向边界，同步更新 `fork_branch` 与盲审沙箱自动挂载公开 `inputs/` 规约，并将 Windows DACL 改写为务实的桌面隔离 + 可选容器隔离。

### 决议 4：工造司补齐工单闭环工具 `resolve_works_ticket`（全系统窄工具 `31 → 32`）+ 全治理队列统一“入队-出队-2 次熔断”三件套
- **原顶层文档写法**：
  - `09` 表 15（L238）定义了 `works_engineering_queue` 含 `INSTRUMENT_ERROR | PAIN_POINT | DUPLICATE_TOOL | EXPLOIT` 工单，但 `09` §5.2（L321）与 `agent_kb/05` §0.2（L61–65）给 `works_engineer` 定义的 5 个工具**客观上漏了非仪器工单的关闭/结案接口**；
  - 整份 `09` 未规定任何“后台治理角色连续跑空转怎么止损”的熔断机制。
- **为什么必须修订（原由）**：
  - 第五轮 6 张 `PAIN_POINT` 工单因为永远无法从 `OPEN` 变成 `RESOLVED`，叠加编排器正常退出零冷却立即重拉，导致 `works_engineer` 35 分钟狂转 **177 次**；同时 `library_surveyor` 因列名错位 + 无解查新无法核销，狂转 **38 次**。

### 决议 6：显式模型绑定与启动门禁（严禁静默 fallback）+ SQLite 唯一真源（消除内存双账本）+ 禁止静默吞稿
- **原顶层文档写法**：
  - `09` L129–131 骨架代码只写了 `provider: config.provider, model: config.model`，未规定当主控在 DSH UI 切模型时的读取链与缺失拒启门禁；
  - 未明确规定探索循环须每轮回查 DB 实时 `node_status` 以防僵尸占槽；
  - `submit_node_handoff` 未明确“已闭环节点被写入不同内容时必须报错而非静默幂等跳过”。
- **为什么必须修订（原由）**：
  1. **显式模型绑定**：宿主启动 `start` 前必须按“显式参数 > `callerAgent.options` > 主控会话事件流 (`model/selection` / `request/context`) > 插件配置”解析出权威 `{ provider, model, effectiveContextWindow }`；**解析不到直接拒绝启动（`MISSING_MODEL_BINDING`），绝不允许静默跌落到第三方未授权渠道（如第五轮的 `thingo-gpt`）**。启动状态必须明示子代理绑定的模型与真实窗口。
  2. **单一真源防僵尸与双账本脑裂**：
     - 探索循环每轮续推前必须核查 SQLite 实时 `node_status`（通过 `sync_pressure` 顺带返回），一旦节点离开活跃态（被外部关闭或 `abort_node`），立刻销毁探索者与私有伴随、释放槽位；
     - 取消编排器内存 `_pendingSalvageNodes` 双账本，待交接/待抢救状态唯一落 SQLite `pending_handoff_mode`，避免内存与 DB 重复触发两次交接；
  3. **防静默吞稿**：`submit_node_handoff` 仅在提交内容与 DB 已落库内容一致时才允许 `idempotent_skip: true`；若节点早已闭环却试图写入截然不同的新成果，必须硬报错 `ERR_LOCKED`。
- **建议顶层修改位置**：
  - `09` 工程总说明书 §2.2、§2.3 与 §5.2 `submit_node_handoff` 规格。
