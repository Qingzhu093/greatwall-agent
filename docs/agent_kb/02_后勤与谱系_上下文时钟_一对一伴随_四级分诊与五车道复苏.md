## 一、`SLA + Station + AgentDiscover` 时间轴大一统与 `500,000` Token 真实净工作时钟

### 1.1 二轮测试时钟崩盘根因与 `500,000` Token 净工作窗口校正（根治 P3/P4/P7）
在二轮测试中，施工方犯了三个叠加错误：① 把 1M 折半窗口从初版错写的 `357k/250k` 在热修复中再次腰斩为 **`178,500`（`37%` 仅 `66,045` Token、`70%` 仅 `125,000` Token）**；② 未扣除 Step 1 静态系统 Prompt 与全量工具 Schema 基线 $T_{\text{base}}$（开局即已占 ~30k）；③ 逼探索者开局连读 7–11 份行政 `.md` 文件。结果 13/13 名探索者全部在**写出 `candidate.py` 或跑通首测之前就在 Step 12–19 撞上 `37%` 反思线**；更致命的是，施工方把 `first_reflection_unlocked` 绑定在了 `70%` 退场交接工具 `submit_node_handoff` 上，导致**探索者在世期间永远无法解锁图书馆**！

**V6-Up v2.1 物理真时钟硬规约（简化无歧义公式）**：
1. **基准窗口（1M 折半）**：`context_window_tokens = 500,000`（固定 50 万 Token）。
2. **总上下文占比直算（取消分母扣除 $T_{\text{base}}$，消除跨语言同步误差）**：在极简 Push 净室下，首步静态基线已压缩至 ~`25k–30k` Token，系统统一直接按 **`pressure_pct = pressureTokens / 500,000`** 计量触发：
   - **`37%` 反思水位**：`pressureTokens / 500,000 >= 0.37`（即总上下文达 **`185,000` Token**，扣除首步基线后实际净干活增量约 **`155,000 ~ 160,000` Token**）**且当前节点已完成至少 $\ge 1$ 次真实实验/验算评估（`eval_count >= 1`）**！严禁在一枪未发时触发空洞反思。
   - **`37%` 回合间隙顺序控制流（非阻塞式工具套娃）**：当 `run_isolated_eval` 后满足 `37%` 条件时，评估工具**立即正常返回成绩单**（绝不在评估工具内部阻塞套娃调用伴随子代理！），由宿主控制面在**回合间隙顺序暂停探索者 $\to$ 拉起伴随助手问答 2 轮（限 $\le 300$ 字/轮） $\to$ 调用 `record_reflection_and_unlock_pull` 置位 `first_reflection_unlocked = 1` $\to$ 恢复探索者会话**。

3. **按角色分级 `reasoning_effort` 与可配置并发上限（$\le 10$）**：一线 `explorer`、`library_surveyor`、`library_verifier` 设为 `high`；`lineage_companion`、`works_engineer` 设为 `medium`；`logistics_coordinator`、`supervisory_committee` 设为 `low`。并发槽位 `max_concurrent_workers` 设为**可配置字段（默认 `6`，上限 $\le 10$）**，并实行**按子题优先公平调度（Question-Fair Slot Allocation）**，防止 4 子题 $\times$ 2 学派 = 8 路开局抢 3 个槽位引发子题饥饿。

## 二、谱系状态维护系统的四大真实工程内核

### 2.1 为什么取消独立 `L1`，将 `L1` 直接合一为【谱系 DAG（门派私有实验记录本）】？
在早期设计中，既在谱系树里存一份 `<2000` 字节点手记，又去中央图书馆存一份 `L1` 私有账本，导致施工方不知该写哪边、最终两边脱节（`L1=0`）。  
**第一性减法**：
- **`L1` 就是谱系 DAG 本身！** 每个门派（Lineage）拥有一本**只追加（Append-Only）的《门派私有实验记录本（Lineage DAG）》**：每一代探索者退场时，伴随助手写下的那篇 **`<2000` 字客观去人称 A/B 双栏手记 + 科研遗嘱 + 绑定的 `[Obs###]` + `Retained Candidate` 物理快照**，就是这本记录本里新翻开的一页（存储在 SQLite `lineage_nodes` 表中，绝不落盘为共享目录明文 `HANDOFF.md`）。
- **门派私有隔离边界**：A 门派的探索者（在 `37%` 解锁后）可以随便往前翻阅**自己门派记录本**里的任意老祖宗手记（第 1 页、第 5 页……）；但 **B 门派的探索者绝对不能偷看 A 门派的私有记录本**——不同门派之间只准通过投稿进入**中央图书馆内藏（`L3` 黄金账本 / `L2` 失败雷达）**的公共成果进行交流！

### 2.2 增量改写《当前谱系状态看板（`Briefing`, ~2000字）》五段预算规范（根治 P6/P17）
**核心公式（完美还原 [`手写project.md`](../手写project.md) 母本拷贝直觉）**：
$$\text{新看板（}\sim 2000\text{ 字）} = f_{\text{Companion}}\big(\text{上一代旧看板},\; \text{刚退场这一代最新一页 } <2000\text{ 字手记}\big)$$
- **为什么既不丢失历史，又永不超长？** 伴随助手在新探索者开跑前，不需要从第 1 代重新遍历几十万字日志，也不允许用 `"\n".join(rows)[:2000]` 机械拼串后在第 2000 字符处拦腰砍断句子（P6）！她只需拿**上一代传下来的 ~2000 字旧看板**，把**刚退场这一代的最新手记**融合进去，按以下**五段固定字数预算**改写出一份全新的 `~2000` 字看板（服务端校验总长 $\le 2200$ 字且五段标签齐全，严禁 `[:2000]` 硬切片）：
  1. **【段 1：本学派核心思想与主导机制（`~200` 字）】**：一句话锁定本分支所属《方法族谱》的思想内核与数学/物理不变量，区别于其他学派；
  2. **【段 2：迄今已证实前提与 `Retained Candidate` 基线（`~400` 字）】**：本脉经过检验成立的局部结论、当前物理 `Retained Candidate` 快照路径、哈希与基线分解指标；
  3. **【段 3：当前悬而未决的核心矛盾与瓶颈（`~350` 字）】**：当前卡在哪个精确前提、数值奇异边界、未证引理或混杂因素上；
  4. **【段 4：本脉历代全量已踩死胡同与精确失灵边界（`~650` 字，只增不忘！）】**：把刚退场这一代新排除的无效路径/参数区间，合并追加进旧看板的“已踩反例清单”中（去重提纯，保留精确失灵条件边界），确保第 30 代也绝不重踩第 1 代踩过的坑；
  5. **【段 5：上一代（及上两代）《科研遗嘱》待办指令（`~400` 字，完整不截断！）】**：原汁原味保留刚退场上一代留下的最小鉴别实验与判定翻转条件（`若见 X 则支持 H1；若见 Y 则推翻 H1`）。

### 2.3 《方法族谱登记册（`Method Family Registry`）》开局多学派强派发与防自锁查重（根治 P8/P19）
1. **Stage 2 开局强制多学派并发（根治 P8 单分支串行退化）**：
   - 在 Stage 1 结束进入 Stage 2 时，针对每个活跃子课题（或主攻课题），后勤调度总管必须先在 `method_families` 表中登记**至少 $\ge 2$ 个底层数学/物理机理互斥的方法学派**（例如 `2026 CUMCM B 题 Q3` 可同时登记 `Family-A: 先全向覆盖扫掠后交会定位的多巡回 TSP 规划` vs `Family-B: 边探测边定位的贝叶斯信息增益在线协同调度`），并并发拉起正交探索分支，严禁全卷从头到尾只跑一条单线！
2. **派生前防撞车查重与 `exclude_branch_id=self` 防自锁（根治 P19）**：
   - 每次执行 `fork_branch(mode="orthogonal" | "lateral")` 前，系统比对拟建机理签名 `mechanism_signature` 与已有家族/兄弟分支：
   - **关键代码修复**：当对某分支执行 `orthogonal` 换向或派生时，SQL 查重查询**必须显式带上 `WHERE branch_id != :current_branch_id`**（排除当前分支自身及其已关闭祖先），绝不允许把分支自己刚登记的签名当成“与兄弟撞车”而自锁报错！

### 2.4 自动全局停滞看门狗与确定性 `AWAITING_TRIAGE` 调度门禁（根治 P5/P16）
1. **确定性 `AWAITING_TRIAGE` 状态门禁**：
   - 伴随助手完成 `submit_node_handoff` 后，节点状态在数据库中置为 `AWAITING_TRIAGE`。
   - **硬锁**：当某分支存在处于 `AWAITING_TRIAGE` 的节点时，宿主禁止在该分支抢跑启动下一代探索者，必须先自动唤醒 `logistics_coordinator` 调用 `triage_node` 完成分诊并更新 `Retained Candidate` 物理快照后，方准派生下一代节点！
2. **真实数据库停滞看门狗**：
   - `consecutive_non_l1_handoffs`：主线每次交接分诊若非 `LEVEL_1`，计数器 `+1`；一旦产生入库 `L3` 的突破则清零；达阈值（默认 `8`）自动触发五车道自救信号；
   - `all_branches_blocked`：所有活跃分支均处于 `LEVEL_4a / 4b` 且 `Ready Queue` 为空时立即触发。

## 三、【日常默认继续】×【四级认知分诊】×【物理快照保护】×【Stagnation 五车道】

### 3.1 分诊先验核查与单一职责窄工具 `triage_node`
后勤调度总管被 `AWAITING_TRIAGE` 事件唤醒后，调用统一签名的窄工具 `triage_node(node_id, triage_level, action, rationale, barrier_proof_md, reopen_condition)`（全仓统一此 6 字段签名，废除旧版 9 参数五合一 `promote_or_triage_branch`），严格对照以下规则裁决：

- **最高频常态：`ROUTINE_CONTINUATION（日常默认继续）`**：当观测 `VALID`，既未破壁达标（非 L1），也无偏科反常突破口（非 L3），也未把方向彻底证伪（非 L4），仅排除了局部假设或推进了中间步骤。**严禁错判为 L4b 暂停！** 直接在原分支由伴随助手刷新看板后启动下一代会话继续深挖。
- **Level 1（突破晋级送审）**：`VALID` + 达到子题验证指标或完成严密证明 $\to$ **物理备份当前代码为最新 `Retained Candidate` 快照**，并将该节点手稿正式推入中央图书馆 **`STAGE1_BLIND` 两阶段盲审队列**（注意：此时尚未入 `L3`，必须等图书馆 Stage 2 盲审 `PASS` 后才由图书馆事务自动写入 `L3`！）。
- **Level 2（原地修补 + 物理快照回滚 + 超限自动入 `L2`）**：`EXECUTION_ERROR` 使**假说根本还未被检验** $\to$ **锁定研究方向绝不允许趁机换路逃跑**；宿主从磁盘 `<workspace>/snapshots/<branch_id>/retained_candidate/` **物理恢复 `Retained Candidate` 代码文件到该分支 Worktree**；发放修补配额由 `explorer` 原地修补（上限 `3` 次；若连续 $\ge 2$ 次环境/钩子报错，系统自动将痛点单推入 `works_engineering_queue` 交由 `works_engineer` 排查，不另设独立的 `Coding Assistant` 角色）；**一旦满 3 次仍失败，数据库同事务自动将该顽固环境陷阱写入中央图书馆内藏 `L2` 雷达**，并退回最近健康祖先重来。
- **Level 3（偏科反常保护）**：主标量暂低或无单一评分，但 `VALID` 且呈现罕见结构优势、守恒不变量或帕累托单维非支配突破 $\to$ **先过防伪迹双检**（排除恒零退化、漏边界或辅助项诱骗），确系真反常后单开受保护特异核查支线，严防被唯分制早熟淘汰。
- **Level 4（屏障终结 / 条件阻塞）**：
  - **4a（真证伪 / 结构阻碍）**：必须过 **`require_evidence_for_level4a = true`** 硬门槛（无严密反例或阻碍证明一律驳回“不可行”宣称），通过后在同一数据库事务内**自动将《结构阻碍证明（Barrier Proof）》写入中央图书馆内藏 `L2` 雷达**，永久封死该精确条件枝并释放槽位。
  - **4b（条件阻塞）**：卡在暂未攻克的定理级引理（`OpenAI CDC` 规则）或特定前置工具缺位。完整留存 DAG 页、登记 **`Reopen Condition`** 后优雅暂停（退场同时触发图书馆 `Auditor` 废墟打捞扫描）。当上游突破或工造司新钩子使阻塞条件解除时，推入 `Ready Queue` 按《方法族谱登记册》优先级排队复活。

### 3.2 三种分叉（`fork_branch`）与五车道全局停滞自救
- **三种分叉（独立窄工具 `fork_branch`）**：
  1. **`orthogonal`（谱系正交分叉）**：开局及缺口期依《登记册》强制互斥发散（查询时强制 `exclude_branch_id=self`），严禁广播上轮 Leader，构思期可用 `BVSR` 暂屏高分套路；
  2. **`lateral`（邻域侧滑分叉）**：L1 侧滑泛化/紧边界，L3 单独核查，L4a 退回健康祖先重芽，先查兄弟重；
  3. **`cross_pollinate`（延迟交叉授粉）**：中前期隔离；唯独当图书馆 `Cross-Draft Verifier` 在 Stage 2 盲审横向比对中发现“A 脉的结构盲区恰好匹配 B 脉已入 `L3` 的匿名原语”，才提议由后勤核准兼容性，交由伴随助手组装《跨谱系嫁接简报》派生混血分支。
- **全局停滞五车道协议（`Station Stagnation Protocol`）**：一旦触发停滞看门狗且预算尚足，按四阶梯自救：① 全局夜科学假日停止编码反思；② 提请工造司构建降维玩具可解模型；③ 检索内藏 `L2` 与历史 `L3` 孤本；④ **强制将活跃探索分支打散编入 5 条互斥车道**：`Exploration（全新互斥原理）` / `Exploitation（在最高潜力脉深度精耕）` / `Revival（复活被条件阻塞或误杀的反常历史线）` / `Understanding（退一步做纯粹机理解析与归因）` / `Strategy（重构整个问题切分方式与多阶段规划）` + `Multistart` 备选公理重启；若预算已见底，在满足 `L3 >= 1` 硬锁前提下转入 `Stage 3` 诚实收口。
