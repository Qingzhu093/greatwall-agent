## 一、纠偏核心：为什么宿主主循环是【确定性极薄事件总线】，且全员皆为【短无状态调用】？

### 1.1 二轮测试暴露的“常驻官僚总管”与“满地公文”灾难

## 二、极简数据底座：全系统只有“3 个真相（Append-Only）”与“2 个视图（Derived Views）”

二轮测试之所以让人觉得“到处是状态、不知道谁读谁”，是因为把同一份信息在 `L1`、DAG、看板、磁盘 `HANDOFF.md` 里重复存了四遍。  
**V6-Up v2.0 确立铁律：真相只存一份（全部只追加、不覆写）；每个角色启动时只被 Push 一张从真相切出来的干净视图，需要深究时再按 ID 定向 Pull 真相！**

### 2.2 两个派生视图（Views — 为无状态启动量身裁剪的干净窗口）

1. **视图 ①：谱系状态看板 (`Lineage Status Briefing`, `~2000` 字)** —— **谱系 DAG 的“2000 字增量扉页”**：
   - **本质**：它不是独立真相，而是伴随助手在新一代探索者出生前，按 **`新看板 = 旧看板 + 刚退场那一页最新手记`** 增量改写出的 `~2000` 字高信噪比净室简报（并可在看板中织入 1 句与本子题直接相关的内藏 `L2/L3` 编号索引提示）。
   - **自愈能力**：哪怕某次看板生成异常，随时可从真相 ②（谱系 DAG 祖先链）无损重新合成；严禁使用 `[:2000]` 字符硬切片腰斩句子。
2. **视图 ②：图书馆两级目录卡 (`Library Catalog Cards`)** —— **外藏表与内藏表共用的“检索抽屉”**：
   - **第一级（目录卡列表 `query_library_catalog`）**：探索者在 `0–37%` 调用时自动返回**外藏 `[R###]`** 基础文献/算子目录卡；过 `37%` 反思解锁后调用则返回**外藏 `[R###]` + 内藏 `L3 / L2`** 全量匹配目录卡（每张卡 $\le 350$ 字：`[ID | 馆藏翼 | 子题 | 标题 + 真实 abstract_md + 精确前提/边界]`）；
   - **第二级（按 ID 调详情 `get_library_entry`）**：看中 1–2 张卡片后，再按 `entry_id` 定向 Pull 完整推导、算子公式或关联 `[Obs###]`，绝不把几万字馆藏一股脑倒进上下文。

## 四、无状态启动下保持“极高业务熟练度且零认知干扰”的四把手术刀

用户一针见血地指出：**“上下文有两面性：其一是让他更熟悉流程，其二则是干扰其判断。如何在每次无状态启动时保持高度业务熟练性，同时不污染科学判断？”**  
我们结合 `AgentDiscover` 开源仓（`tools_search.py`）与 `GPT-Rosalind` 开源仓（`adaptive.py` / `prompts.py`）的真实工程精髓，确立以下四把手术刀：

### 手术刀 1：角色盲盒隔离与工具面极简裁剪（Role Blind-Box & Tool Surface Minimalism）
- **认知减负**：一个角色不需要知道全系统的宏大叙事！探索者的启动 Prompt 里**完全不出现**“一委三部、五车道、两阶段盲审、RQGM Beta 分位数”等体制词汇，只告诉她眼前的“一米见方闭环”：读看板与遗嘱 $\to$ 提事前预测跑实验 $\to$ `37%` 和搭档聊两句解锁图书馆 $\to$ `70%` 停笔交给搭档。
- **工具白名单硬裁剪**：每个角色只挂载属于自己的 **3–5 个窄工具**。模型看不到无关工具，从根源上杜绝“探索者越权调分诊”或“审稿人乱调派单”。

### 手术刀 2：把流程规矩从“开场背诵”移到“工具回执末尾 JIT 实时导航”（源自 `AgentDiscover` [`tools_search.py#L338-L608`](file:///D:/Documents/deepseek%20harness/论文研读/2610.05334_AgentDiscover_Autonomous_Discovery_with_Minimal_Search_Scaffolding/AgentDiscover/agentdiscover/server/tools_search.py#L338-L608)）
- 传统做法在开场 Prompt 塞几千字“如果遇到 A 就调 B，到了 37% 要注意 C”，模型跑 10 步就忘光了；
- **JIT（Just-in-Time）回执注入**：借鉴 `AgentDiscover` 在每次工具返回 JSON 末尾动态附带 `_noise_phrase` 与 `_cache_advice` 的做法，我们的 MCP 工具在返回结果时，自动根据当前节点状态在 JSON 尾部附上 **`next_step_guidance`（1–2 句精准路标）**：
  - 当探索者刚跑完第 1 次实验且净工作 Token 跨过 `37%` 时，`run_isolated_eval` 返回回执末尾直接提示：`"[JIT-Guidance] 你已完成首轮实测且净上下文达 37%，请立即响应伴随助手的 2 轮简短元反思问答；回答完毕后系统将为你自动解锁 query_library_catalog / get_library_entry 与 read_lineage_graph 权限。"`
  - 当伴随助手调用 `submit_node_handoff` 成功时，回执末尾直接提示后勤总线：`"[JIT-Guidance] 节点 node_xxx 已进入 AWAITING_TRIAGE，请调用单一职责分诊工具 triage_node 完成裁决。"`
- **效果**：模型永远不需要死记硬背长流程图，走到哪个路口，路牌就自动亮在当前最后一条 tool result 里！

### 手术刀 3：百字工具速查表 + 单行合法 JSON 范例 + 窄工具拆分（源自 `GPT-Rosalind` [`官方仓库解析#L68-L115`](file:///D:/Documents/deepseek%20harness/论文研读/Sun2026_Distributed_AI_Agents_Enable_Comprehensive_Discovery_of_Biological_Insights_at_Scale/Sun2026_GPT-Rosalind_DistributedAgents_官方仓库框架与工程架构深度解析.md#L68-L115)）
- **废除五合一瑞士军刀工具（根治 P15）**：严禁再设计 `promote_or_triage_branch`（9 个复杂枚举参数）或 `manage_eval_epoch` 这类大泥球工具！全部拆分为**参数扁平、名字即语义的单一职责窄工具**（如 `triage_node`、`fork_branch`、`submit_stage1_blind_ledger`、`submit_stage2_unblind_verdict`）。
- **单行 JSON 范例直给**：在每个角色的极简 Prompt 尾部，为每个工具配 **1 行真实合法的 JSON 调用示例**与宿主确定性预检摘要（Pre-computed Manifest），彻底消灭参数填错、空 JSON `{}` 或格式重试。

### 手术刀 4：代码与技能的物理接力（`<worktree>/tools/` + `Retained Candidate` 物理快照）
- 无状态指的是“清空聊天历史脑雾”，绝不是“把上一代写好的代码和工具也格式化清零”！
- 本分支验证通过的辅助诊断脚本、符号推导算子与数据加载器，持久化在分支工作树 `<worktree>/tools/` 下（强制带 docstring 说明 `What it does / Interface / What it does NOT do`），并在新探索者启动时由宿主自动扫描生成 **《本分支现成可用 `tools/` 清单》** 随 Push 视图一起递到手上；同时 `Retained Candidate` 由宿主执行**物理磁盘文件快照备份与一键回滚**，让每一代无状态探索者都站在上一代坚实的物理代码肩膀上起跳！

## 五、全系统权力红线与“砍公文铁律”速查

1. **`No Mathematical Opinion`（`Cogentic §2.4` × `AgentDiscover` [`meta.md#L101-L117`](file:///D:/Documents/deepseek%20harness/论文研读/2610.05334_AgentDiscover_Autonomous_Discovery_with_Minimal_Search_Scaffolding/AgentDiscover/harness-instructions/meta.md#L101-L117)）**：系统事件总线、后勤调度总管、监察委员会与过程顾问在调度与审计中**绝不能替探索者指定或猜测数学定理结论、预算配额表、按优先序排列的具体研究方案或直接代写业务求解代码**。
2. **砍公文铁律（Anti-Bureaucracy File Cap — 根治 P2/P9）**：全系统在 Stage 1 与 Stage 2 运行期间，**严禁任何角色在工作区磁盘上创建或读写流程审批类、审计对账类、阶段放行类、元反思报告类或交接手记类 `.md` 文件**（如 `*_AUDIT.md`, `*_RELEASE.md`, `*_RECONCILIATION.md`, `*_CLOSURE.md`, `REFLECTION_37.md`, `HANDOFF.md`）。一切交接手记、看板、反思问答、盲审账本与合规告警**100% 写入 SQLite 数据库对应结构化表**；磁盘工作树只准存放可执行科学代码、测试脚本、图表数据与 Stage 3 最终交付的学术论文！
3. **结题硬锁铁律（Hard Closure Lock — 根治 P9/P27）**：任何必答子题（`Q1..Qn`）若在数据库中满足 `SELECT COUNT(*) FROM internal_research_ledger WHERE question_id = ? AND ledger_type = 'L3_VERIFIED'` 为 **`0`**，代码层硬性拒绝将该子题标记为完成，且硬性锁死 Stage 3 终稿合成入口！
4. **双轨客观暴露对账原则（`AgentDiscover` [`schema.cypher#L85-L90`](file:///D:/Documents/deepseek%20harness/论文研读/2610.05334_AgentDiscover_Autonomous_Discovery_with_Minimal_Search_Scaffolding/AgentDiscover/schema.cypher#L85-L90) & [`exposure.py#L72-L106`](file:///D:/Documents/deepseek%20harness/论文研读/2610.05334_AgentDiscover_Autonomous_Discovery_with_Minimal_Search_Scaffolding/AgentDiscover/agentdiscover/orchestrator/exposure.py#L72-L106)）**：数据库中明确区分探索者**主观声称边**（`DERIVED_FROM / USES_IDEA`）与宿主中间件自动记录的**客观暴露边**（`RETRIEVED / READ / USED_TOOL`）——两者的差异由 SQL 自动对账生成结构化告警行。
5. **伴随单向透明读取与读隔离新沙箱插件规约**：伴随助手与探索者非平级 P2P，宿主直接将探索者分支 Worktree 的**只读权限与实时滚动的工具调用轨迹/代码 Diff 黑匣子摘要**单向透明 Push 给伴随助手（支撑零损耗打捞与交接）；同时，鉴于 DSH 原生 `windows-acl` 仅限制写删不限制读，长城在 DSH 之上**独立新造支持读隔离的沙箱与编排插件**（不篡改 DSH 核心 `subagent` 源码），将 `greatwall.db` 数据库本体及其他分支目录隔离在探索者 `read/pwsh` 不可直读的物理边界之外。
