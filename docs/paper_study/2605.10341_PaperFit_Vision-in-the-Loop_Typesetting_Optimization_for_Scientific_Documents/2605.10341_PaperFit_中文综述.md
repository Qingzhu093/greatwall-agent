## 0. 一句话概括

本文指出文档自动化流水线中长期缺失的一环——**"可编译"不等于"可发表"**，并把"让一份能编译的 LaTeX 论文变成视觉精美、页数合规的 PDF"这一任务正式定义为 **视觉排版优化（Visual Typesetting Optimization, VTO）**；随后提出 **PaperFit**——一个"感知（Sense）—行动（Act）—验证（Verify）"的视觉闭环智能体，以及配套基准 **PaperFit-Bench**（200 篇论文 × 10 个会议模板 × 13 类缺陷注入）。

## 1. 研究背景与问题动机

### 1.1 从"结构性排版"到"视觉排版"

过去十年的文档自动化进展集中在**结构性格式转换**：Pandoc 之类的格式转换工具、从 PDF 反推 LaTeX 的文档理解模型、以及从自然语言直接生成完整 LaTeX 框架的大模型。这一阶段的共同目标只有一个——**产出能编译的 .tex**。

但作者指出一个被普遍忽视的事实：**编译成功不保证视觉质量**。一份语法正确的 LaTeX 工程产出的 PDF 仍可能存在：

- 浮动体（float）错位，图表远离其引用位置；
- 公式溢出行宽；
- 表格缩放不一致（\resizebox 导致的字号畸形）；
- 孤行与寡行（widow / orphan）；
- 页面留白失衡，末页大量空白显得内容不完整；
- 多出半页导致违反会议严格页数限制。

目前解决这些问题**完全依赖人工**：反复"编译 → 看 PDF → 找视觉缺陷 → 改 .tex → 再编译"。这个循环在投稿截止前的最后几小时尤为密集，而它依赖的恰恰是**没有任何现有工具能完全自动化的视觉判断**。

### 1.2 现有方案失败的三点根本原因（对应 Figure 1）

| 局限 | 表现 | 后果 |
| --- | --- | --- |
| **(i) 可观测性不完整** | 基于规则的工具与编译日志只提供一维的代码级信号，能发现 overfull hbox 警告，但无法判断这个溢出在视觉上是否严重、图表位置是否影响阅读流、白空间如何在页面上分布 | 排版质量本质上是**二维空间判断**，源码与日志无法支撑 |
| **(ii) 修复空间无约束** | 模型发现问题后面对巨大的动作空间，其中大部分是**伪修复（pseudo-fix）**：\vspace、\resizebox、\newpage 能编译通过，却通过扭曲字形、掩盖问题或把缺陷转移到别处来违反隐式排版规范 | 模板文件只规定字体/页边距/标题格式，**不编码"合法修复"与"化妆式规避"的区别** |
| **(iii) 级联效应未验证** | LaTeX 编辑高度非局部：图宽的小改动会触发全文分页重排；纯文本 LLM 处于**开环**状态，改完源码既不渲染也不检视 | 无法确认一次编辑究竟改善还是恶化了全局版面 |

作者由此得出核心论断：**排版是一个闭环控制问题**，需要"视觉感知 + 约束动作 + 每次编辑后的全局验证"。

### 1.3 关键洞察

VLM 的进步使自动化这个闭环成为可能——**能同时理解渲染页面并生成 LaTeX 修改的模型，原则上可以复现人类的"编译—检视—编辑"工作流**。但作者强调一个反直觉的结论：

> 简单地把页面图像在多轮里喂给 VLM **并不足够**。缺少结构化诊断、约束修复与门控验证时，模型倾向于引入新缺陷或忽略页数约束。

这正是全文最重要的实验设计动机——**"看得见"是必要条件，但不是充分条件**。

## 2. 问题形式化：VTO

### 2.1 定义

给定可编译的 LaTeX 工程 $x$、目标模板 $\tau$、可选页数预算 $b$，执行编译—渲染流水线得到日志证据 $\ell$、PDF $P$、页面图像 $I$ 与页数 $p$。VTO 寻找修改后的源码 $x^*$，在硬约束下最小化残余视觉缺陷：

$$\mathbf{x}^{*}=\arg\min_{x'}\ \underbrace{\sum_{d\in\mathcal{D}(x')} w_{c(d)}\,s(d)}_{\text{视觉缺陷分}}+\ \lambda_e\,\Delta(x,x')$$

$$\text{s.t.}\quad \mathrm{COMPILE}(x',\tau)=\text{success},\quad \mathrm{RENDER}(x',\tau)=\text{success}$$
$$\mathrm{CONTENT}(x')\supseteq \mathrm{CONTENT}(x),\quad |\mathrm{PAGES}(x',\tau)|=b\ (\text{当 } b \text{ 指定时})$$

其中 $\mathcal{D}(x')$ 是在模板 $\tau$ 下渲染页面中检测到的缺陷集合，每个缺陷由类别 $c(d)$ 与严重度 $s(d)$ 刻画；$w_{c(d)}$ 按 VTO 分类法加权；$\Delta(x,x')$ 度量源码级编辑距离以鼓励**最小化、可审计**的改动；$\lambda_e$ 平衡"编辑保守性"与"视觉改善"。

### 2.2 约束优先级（重要设计）

作者明确了严格的**字典序优先级**：

> **内容保真 > 编译/渲染成功 > 页数预算 > 视觉质量 > 编辑最小化**

这一优先级贯通全文，也是后续 gatekeeper 三项决策（DONE / CONTINUE / BLOCKED）的判定基础。

### 2.3 为什么不能单遍生成

目标函数**只有在编译并渲染之后才可观测**，且微小的源码改动会触发非局部版面级联。因此 VTO 被形式化为**带视觉验证的迭代式证据驱动搜索**。

## 3. 五类缺陷分类法（VTO Taxonomy）

论文提出覆盖五类、共 13 种扰动的缺陷体系，作为诊断、修复、评估三阶段的共同语言：

- **Class A — 空间利用（Space Utilization）**
  - A1 孤行/寡行（widow/orphan）
  - A2 尾部白空间（trailing whitespace）
  - A4 双栏失衡（column imbalance）
  - A5 栏内空洞（column void）
- **Class B — 浮动体位置（Float Placement）**
  - B1 浮动体被推至独占页（float-to-page）
  - B2 图形过大 / 图形过小（oversize / shrink graphics）
- **Class C — 表格宽度（Table Width）**
  - C1 \resizebox 压缩表格（table resizebox）
  - C2 表格超宽（table oversize）
- **Class D — 溢出（Overflow）**
  - D1 长不可断词元溢出（long token overflow）
  - D2 超宽公式（long formula）
- **Class E — 跨模板迁移（Cross-Template Migration）**
  - E1 模板不匹配（图片宽度不合理）
  - E2 模板迁移导致页数漂移（\textheight 缩小）

每类缺陷实例记为结构化记录 $d=(c,o,r,e)$：$c\in\{A,B,C,D,E\}$ 为类别，$o$ 为位置（页码 + 空间区域），$r\in\{$blocking, degrading, cosmetic$\}$ 为严重度，$e$ 为支撑证据。**该记录是"诊断"与"修复"之间的接口**：每次编辑都可追溯到显式的多源证据，严重度字段决定下一阶段的修复优先级。

## 4. 基准：PaperFit-Bench

### 4.1 定位

与评估"编译成功"或"内容正确"的既有基准不同，PaperFit-Bench 把评估操作化为**从系统性扰动源恢复视觉版面**：每个实例配有"扰动后的 LaTeX 源 + 作为金标准的原始可编译版本"。

### 4.2 数据规模与构成

- **200 个实例**，覆盖 **10 个会议/期刊模板**，单栏与双栏格式兼有；
- 模板与页数限制：AAAI(2栏,7页)、ACM MM(2栏,8页)、CVPR/ICCV(1栏,8页)、ECCV(1栏,14页)、ICLR(1栏,9页)、ICML(2栏,8页)、IEEE Trans(2栏,12页)、IJCAI(2栏,7页)、IJCV(2栏,10+页)、NeurIPS(1栏,9页)，每会 20 篇；
- 平均每样本 **6.3 张图 + 5.3 张表**，浮动体密度高，能充分压测版面修复能力；
- 语料取自 arXiv，跨 NLP / CV / RL 等子领域，以缓解对单一排版风格的评估偏置。

### 4.3 构建流程

1. **采集**：从 arXiv 获取已发表论文的 LaTeX 源码；
2. **预处理**：在受控构建环境中做标准化编译测试，剔除编译失败或依赖私有宏包的样本；统一移除附录；人工+自动双重质检，保证每样本至少 3 图 2 表；
3. **扰动设计**：13 种扰动策略归入 5 大类（见第 3 节表）；
4. **装配与终检**：组装为完整问题实例，最终质检确保编译成功且视觉扰动确实被实现。

### 4.4 难度分层

按**共现扰动的数量**分层：Easy（1–2 个，60 例）、Medium（3–4 个，80 例）、Hard（5–8 个，60 例），比例约 3:4:3。跨模板扰动（E1、E2）在更难实例中愈发突出。

一个重要设计原则是**「现实优先于简单」**：

> PaperFit-Bench 是**混合扰动**基准，而不是单缺陷玩具样例的集合。难度桶是经验分组而非确定性配方——Hard 用例可能同时叠加模板迁移压力、表格溢出与页数漂移；Easy 用例仍可能含不可忽视的局部表格或浮动体问题。

作者还记录了**「扰动意图」与「源码级实现」两层信息**：同一高层缺陷可以以不同 LaTeX 形式出现（如"过宽图"可能来自显式 width 超过 \linewidth，而"页数漂移"可能来自模板迁移叠加文本高度变化）。评估以 manifest 作为扰动意图的来源，以编译/渲染产物作为**实际发生故障**的证据。

### 4.5 与既有基准的对比（Table 4）

| 基准 | 任务 | 扰动注入 | 视觉评估 | 多模态 | 迭代修复 |
| --- | --- | --- | --- | --- | --- |
| Im2Latex-100K | 公式重建 | ✕ | ✕ | ✕ | ✕ |
| TeXpert | LaTeX 代码生成 | ✕ | ✕ | ✕ | ✕ |
| RoDLA | 版面鲁棒性 | 有限 | 部分 | ✓ | ✕ |
| DocReward | 质量评估 | ✕ | ✕ | ✕ | ✕ |
| LATTE | 元素级精修 | ✕ | ✕ | ✓ | ✓ |
| **PaperFit-Bench** | **视觉排版修复** | **13 种策略** | **✓** | **✓** | **✓** |

结论：PaperFit-Bench 是**唯一同时支持系统性扰动注入、基于渲染页面的视觉评估、多模态证据链与全文迭代修复**的基准。

## 5. 方法：PaperFit 的 Sense–Act–Verify 闭环

### 5.1 总体（Figure 3）

PaperFit 从 **source / log / PDF / page-image** 四类证据诊断版面缺陷，在**修复偏好档案（repair preference profile）**约束下施加修复，并通过**清单门控的多轮循环**验证输出。

### 5.2 Sense：多源证据融合

核心论点：**没有任何单一证据源能可靠捕获所有排版缺陷**。

> 一张表可以编译无警告、使用标准 tabular 环境、落在正确页码——**却溢出了分栏边界**。只有页面图像层能揭示这个缺陷；也只有源码层能定位修复目标。

四层证据分工：

| 证据层 | 提供内容 | 独特作用 |
| --- | --- | --- |
| **Source（.tex）** | 文档结构、模板配置、宏定义、浮动环境、表格结构，以及图/表/题注/标签/引用/参考文献命令的计数 | 识别可编辑区域、保护关键科学对象、暴露模板迁移导致的结构不匹配 |
| **Log（.log）** | 编译失败、未定义控制序列、未解析引用、缺失引用、overfull/underfull 警告、模板兼容性错误 | 当输入无法编译或渲染时，作为**恢复可执行状态的首要证据** |
| **PDF（.pdf）** | 最终页数、页序、浮动体落点 | 判断页数预算是否满足、浮动体是否远离首次引用 |
| **Page-image** | 稀疏末页、双栏空洞、浮动体堆叠、超大表格、局部白空间、跨页失衡、视觉不一致 | 揭示源码与日志**无法可靠检测的二维视觉缺陷** |

诊断阶段把这些证据转换为结构化缺陷记录 $d=(c,o,r,e)$。

### 5.3 Act：约束修复策略

面对"大部分是伪修复"的巨大动作空间，PaperFit 用**修复偏好档案 $\pi$** 施加控制，其中编码了动作分层、按缺陷类别的策略、禁止操作与受保护内容。

#### 5.3.1 修复动作三层（Repair Action Tiers）

| 层级 | 具体动作 | 策略 |
| --- | --- | --- |
| **布局原生（首选）** | 浮动体重锚定（[htbp] 参数调整）、公式拆分为 align/multline、用 tabularx / table* 等宽度感知环境重构表格、图宽归一化到模板安全值 | 直击缺陷根因，**无副作用** |
| **间距操纵（受限）** | 局部 \vspace 调整、\setlength 修改、columnbreak 提示 | 仅在**有显式局部理由**时允许，且必须通过再验证 |
| **伪修复（禁止作为主要手段）** | 表格用 \resizebox、用 \newpage/\pagebreak 控制页数、图形用 \scalebox、删除内容 | 可能暂时掩盖缺陷，但扭曲排版、违反模板规范或把缺陷转移到其他页面 |

#### 5.3.2 缺陷感知的修复选择

修复优先级排序为：

1. **编译错误（最高）**：通过日志引导的源码修复恢复编译；
2. **溢出 D**：拆分长公式、断开不可断词元；
3. **浮动体位置 B**：将浮动体重新锚定到首次引用附近、归一化图宽；
4. **表格一致性 C**：用 tabularx 替换 \resizebox、重构超宽表格；
5. **空间利用 A**：调整浮动体位置与参数以消除孤行/寡行与白空间；
6. **跨模板 E**：调和模板迁移带来的宽高不匹配。

每一轮，系统从 $\mathcal{D}_t$ 中选出**优先级最高的未解决缺陷**，施加该类别排名第一的布局原生策略；若布局原生选项耗尽，才在受限策略下尝试间距操纵动作。

#### 5.3.3 内容保真与语义润色兜底

- **保护机制**：施加任何修复前，系统快照所有受保护对象的数量与位置（图、表、题注、标签、引用、参考文献条目）；修复后校验没有任何受保护对象被删除、跨越章节边界移动或改动题注。**违反即自动回滚到修复前状态**。
- **语义润色兜底**：当布局原生修复耗尽，但仍存在轻微页数缺口、孤行寡行或稀疏末页时，允许**有界语义润色**——最小化措辞调整（压缩冗长句、用简洁表达替换长短语），且不得改变主张、结果、数字、引用或事实含义。该兜底**仅在布局原生手段失败后启用**，并仍受内容保护守卫约束，定位是"最后手段"而非主要策略。

### 5.4 Verify：清单式质量控制

单次修复后的编译检查**无法保证全局版面**——LaTeX 编辑高度非局部。PaperFit 在**每次编辑后重新编译、重新渲染、重新检视全文**，状态记为：

$$\mathcal{S}_t=(x_t,\ \ell_t,\ P_t,\ I_t,\ \mathcal{D}_t,\ \mathcal{H}_t,\ a_t)$$

即当前源码、编译日志证据、PDF、渲染页面集合、结构化缺陷报告、硬约束信号与下一步动作。

每轮六步：**(1)** 编译并收集日志；**(2)** 解析确定性信号（错误、引用、overfull box）；**(3)** 渲染全部页面；**(4)** 从多源证据构建结构化缺陷记录；**(5)** 按缺陷类别与修复偏好档案施加约束修复；**(6)** 重新编译/渲染，交由**门控器（gatekeeper）**裁决。

门控器输出三种决策：

- **DONE**：所有约束通过，无阻塞性残余缺陷；
- **CONTINUE**：安全但仍存在问题；
- **BLOCKED**：修复不安全或不可行。

DONE 清单要求：编译成功、渲染成功、页面级视觉检视完成、无阻塞性缺陷、页数预算满足、受保护内容完整保留。

## 6. 实验

### 6.1 设置与基线

所有方法接收**同一份 LaTeX 工程与同一目标页数预算**，输出统一编译、渲染，并用程序化检查 + VLM 视觉评估双重打分。六条基线覆盖三种反馈范式：

| 范式 | 基线 | 能力边界 |
| --- | --- | --- |
| 规则 | **Perturbed** | 未修改的扰动输入；度量基准的原始难度，并作为 VLM 成对比较的视觉参照 |
| 规则 | **RuleLog** | 由源码与编译日志驱动的确定性规则修复；不使用模型视觉反馈。测试"仅靠执行与日志修复"能走多远 |
| 纯文本 | **TextST** | 单轮把 LaTeX 源码交给模型修复，不看渲染页面；测试"纯源码推理"能否修复版面缺陷 |
| 纯文本 | **TextMR** | 多轮文本/日志反馈，能对编译错误与日志做出反应，但**仍不以页面图像为视觉证据** |
| 视觉 | **VisualST** | 接收源码 + 渲染页面图像，只做**一轮**视觉修复；隔离"加入页面图像"的价值与局限 |
| 视觉 | **VisualMR** | **固定轮数的朴素多轮视觉智能体**；可检视源码/日志/页面图像并直接修复，但**被明确禁止**使用 PaperFit 的缺陷分类法、结构化诊断记录、约束修复策略、修复计划产物、回滚感知门控器与运行时 |

> **关键对照设计**：VisualMR 与 PaperFit 的区别**不是模型是否看到页面图像，而是多轮过程是否围绕"显式缺陷、约束修复、验收门控"组织**。附录 B 进一步说明所有基线都配固定提示模板并保存运行产物（VisualMR 写入 reports/agent_prompt.txt，PaperFit 写入 reports/claude_prompt.txt），且提示中**显式禁止** VisualMR 触碰任何 PaperFit 结构化产物——以保证基线边界可审计，避免"隐藏的提示差异"被当作实现细节。

### 6.2 评估协议

四项二值主指标：**Compile 成功率、Render 成功率、Page hit（页数精确匹配）、Win rate（视觉上优于 Perturbed 的比例）**。

两个互补综合分：

- **Program（0–5）**：非视觉的执行可靠性与内容保真综合分，为 5 个等权维度的均值：编译可靠性、内容完整性、引用质量、页数精确度（对过度改写源码施加惩罚）、内容嵌入相似度。**刻意不是视觉分**——可以靠"可编译、忠实、页数受控"拿高分，即使版面上仍有可见白空间或浮动体质量问题；反之，截图好看但丢失受保护内容、违反页数或遗留未解析引用的输出会被扣分。
- **VLM（0–5，带门控）**：基于渲染页面的视觉质量分，两种模式：**成对比较**（Perturbed 可渲染时并排比较）与 **render-rescue**（Perturbed 不可渲染时，可渲染的候选获得"从不可渲染状态恢复"的信用）。

$$\mathrm{VLM}_{\text{raw}}=0.35\,S_{\mathrm{abs}}+0.40\,S_{\mathrm{repair}}+0.25\,S_{\mathrm{final}}$$

其中 $S_{\mathrm{abs}}$ 度量绝对修复质量（缺陷解决、约束对齐、视觉质量、新缺陷规避、发表就绪度）；$S_{\mathrm{repair}}$ 度量相对 Perturbed 的成对修复质量（或 render-rescue 质量）；$S_{\mathrm{final}}$ 度量最终成稿美学（专业性、空间利用、浮动体位置、排版一致性、视觉平衡）。

**严格门控封顶**：不可渲染的候选封顶到最低分；可渲染但"编译脏"的输出被惩罚并封顶；页数失败、未解析引用或引入重大新视觉缺陷同样触发封顶。

三条核心结论：

2. **朴素多轮视觉修复提升了可用性，但页数控制仍然薄弱。** VisualMR 在编译与渲染上都达到 0.975，说明多轮视觉+日志反馈能消除大部分执行失败；**但 Page hit 只有 0.549，Win rate 只有 0.650**。缺少显式规划、约束修复与门控验证时，多轮视觉编辑仍难以满足页数预算并避免新引入的视觉缺陷。
3. **PaperFit 取得视觉质量与约束满足的最佳折中。** 编译/渲染双 1.000，VLM 3.391、Win 0.895、Page hit 0.805，Program 4.579 与 VisualMR 基本持平。**所有方法的内容嵌入相似度都 >0.97**，说明这些增益来自版面结构修复而非语义漂移。

### 6.8 错误分析（Figure 11–12）

**A. 全局页数预算违规**

- **Case A（页数门控失败）**：ACM MM 目标 10 页，产出 16 页。迭代修复制造了多个稀疏尾页——说明**局部编辑有效但全局页数控制不足**。
- **Case B（多一个浮动体密集页即破坏预算）**：ECCV 目标 19 页，产出 20 页，末页只有一张大图和大片白空间。说明**即使只偏差一页，只要新增页近乎空白，就构成硬失败**。

**B. 残余视觉缺陷与无效输出**

- **Case C（视觉缺陷未被修复）**：ACM MM 编译与页数（10/10）都达标，但**超大且被裁切的图基本没被修好**。
- **Case D（编译渲染成功但输出异常）**：ICLR 编译成功、页数正确（13/13），但**渲染页面发灰、视觉上无效**。这条直接支撑全文的一句警示：**LaTeX 层面的编译成功不足以作为唯一质量指标**。

### 6.9 结论与局限

**结论**：本文把视觉排版优化认定为文档自动化中缺失的一环，提出 PaperFit——通过多源证据融合、约束修复策略与清单门控验证，弥合"可编译"与"可发表"之间的鸿沟。在 PaperFit-Bench（200 篇、10 模板、13 缺陷）上，PaperFit 取得完美编译成功、最高 VLM 分与 80.5% 的页数命中率。

**局限（作者自述 + 附录 D）**：

1. **视觉检视依赖 VLM 评估器**：细微或模糊的版面问题（微观排版缺陷、字体级字距错误）仍可能被现有视觉模型漏掉；
2. **困难用例页数命中率降至约 70%**：5–8 个共现扰动的高度复杂多缺陷场景仍具挑战；
3. **仅限 LaTeX 工程**，且**仅在英文论文上评估**，其他语言的覆盖留待未来工作；
4. **多轮重编译与重渲染的计算开销高于单遍方法**，在保持修复质量的前提下降低这一开销是重要的实践方向。

## 7. 批判性评述

### 7.1 主要贡献

1. **提出并形式化了一个新任务（VTO）**。把"从可编译源码到可发表 PDF"这一长期被当作"工程琐事"的环节，提炼为带硬约束的迭代优化问题，并给出缺陷分类法。**任务定义本身就是本文最有价值的产出**。
2. **Sense–Act–Verify 的架构分解具有可迁移性**。三层修复动作分层（布局原生/间距操纵/伪修复）与"内容保真 > 编译 > 页数 > 视觉 > 编辑最小化"的字典序约束优先级，是对"LLM 面对巨大动作空间易做化妆式修复"这一通病的通用解法，可迁移到 HTML/CSS 排版、PPT 生成、海报合成等相邻任务。
3. **反直觉的核心实证结论**："视觉反馈必要但不充分"——通过 VisualMR 这个**刻意削平能力、却保留页面图像与多轮循环**的对照，把增益精确归因到"结构化诊断 + 约束修复 + 门控验证"，而不是"模型看到了图"。这个对照设计是全文实验部分最扎实的地方（附录 B 还专门用提示记录保证基线边界可审计）。
4. **评估协议的工程严谨性**：Program 与 VLM 双分并置、异常输出的"封顶"而非"丢弃"（不可渲染/编译脏/页数失败一律计入分母）、以及 r=0.857 的人机一致性验证，比多数"只报成功率"的文档类工作更可信。
5. **诚实的错误分析**：专门用两组图展示自己的失败模式（页数违规、达标但视觉未修复、编译成功但输出发灰），而非只展示成功案例。

### 7.2 可质疑之处

1. **VLM 既是"被优化的判据"又是"评分者"**。VTO 的目标函数依赖 $w_{c(d)}$ 与 $s(d)$，而这些缺陷检测与打分由 VLM 完成；VLM 评估分同样是 VLM 给的。**同一类模型既当运动员又当裁判**，存在自我一致但与他人标准偏离的风险。r=0.857 缓解了这一点，但人工评分的样本量、评分者数量与一致性（如 Krippendorff α）未在正文给出，建议补充。
2. **页数命中率 80.5% 意味着仍有约 1/5 的用例不满足硬约束**——而页数是学术投稿中最"生死攸关"的约束。作者把它归因于困难的全局控制，方法层面确实缺少**显式的全局页数规划器**（如"预计删减 X 行 ≈ 减少 Y 页"的预算模型），修复仍是贪心式缺陷优先级驱动。这可能是最值得后续工作补强的一点。
3. **E 类（跨模板迁移）与传统"排版修复"性质不同**。模板迁移更接近"重排版/内容重适配"，把它并入同一基准可能让任务边界略模糊——不过作者在 4.4 节说明了意图与实现的分离，评估以"实际发生的故障"为准，处理是合理的。
4. **基线的公平性边界**：VisualMR 被显式禁止使用分类法、修复计划、门控器等一切 PaperFit 结构化产物，这使它更接近"裸 VLM + 工具外壳"而非"最强的通用视觉编码智能体"。作者在 5.3 节用能力矩阵替代直接跑外部系统（如 OpenHands、Aider）也说明外部系统接入成本很高。**"结构化闭环带来的增益"这一结论方向可信，但具体数值差距不能直接外推到与成熟编码智能体的对比**。
5. **计算成本未量化**。"多轮重编译重渲染开销更高"只作为局限陈述，没有给出轮数分布、token 消耗、wall-clock 时间或与单遍方法的成本比。对追求实用的读者，这是关键缺失。
6. **App 中 Table 5 的页面 hit 与文本叙述有轻微张力**：正文称 VisualMR "Page hit is only 0.549"，表格为 0.5487，属四舍五入；但 RuleLog 的 compile 0.52 / render 0.76 低于 Perturbed 的 0.58 / 0.82，说明"确定性规则修复"反而**破坏了原本可渲染的输入**——这一现象值得单独分析（规则误伤），论文仅一笔带过。
7. **语义润色兜底存在伦理与可复现风险的灰区**。允许 LLM 微调措辞来"挤出"半页空间，虽有"不改变主张/结果/数字/引用"的守卫，但在 LLM 环境中这类守卫是提示级而非形式化验证的。作者自己也把它定位为「最后手段」，态度是谨慎的，但实际触发频率与回滚率未报告。

### 7.3 方法论上值得学习的设计

- **用"逐层加能力"的基线阶梯（Perturbed → RuleLog → TextST → TextMR → VisualST → VisualMR → PaperFit）做归因**，而不是随意挑几个基线，使每个组件（日志、多轮、图像、结构化）的价值都能被单独读出。
- **把门控器（gatekeeper）与 DONE/CONTINUE/BLOCKED 三态显式化**：把"什么时候算做完"变成可检查的清单，而不是让智能体自行判断停止时机。这是 agent 类工作普遍缺失的一块。
- **失败不删除**：非编译、非渲染的输出**不被静默丢弃**，而是按统一的失败记账规则计入分母。
- **意图与实现的分离记录**：manifest 记"我们想注入什么缺陷"，编译/渲染产物记"实际发生了什么缺陷"。这避免了"注入了但没生效"的样本污染指标。

## 8. 对后续研究的启示（可跟进方向）

1. **显式全局页数规划**：引入"源码行数/浮动体面积 → 页数"的可学习或可解析预算模型，把贪心的缺陷优先级驱动升级为带全局预算约束的规划，直击 80.5% → 更高命中率的瓶颈。
2. **可形式化的内容保真守卫**：目前内容保护依赖对象计数与快照回滚；若能把"主张/数字/引用不变"变成结构化 diff 校验（如引用键集合、数字集合、图表标签集合的严格等价），闭环会更可靠。
3. **超越 VLM 的视觉判据**：把微观排版指标（字距、行距、行末、河流/峡谷 river/gutter）交给确定性算法，把宏观版面判断留给 VLM，形成混合判据，规避"自己评自己"。
4. **成本-质量权衡曲线**：报告轮数-质量-成本的 Pareto 前沿，并研究"何时停止修复"的最优策略（early-stop）。
5. **泛化到相邻排版域**：把 VTO 的形式化与约束修复档案迁移到 HTML/CSS、Slides（Beamer / pptx）、海报（Paper2Poster 类），验证"布局原生 > 间距操纵 > 伪修复"的分层原则是否为跨域常量。
6. **把 PaperFit-Bench 当基础设施**：13 种扰动 + 5 类缺陷 + 3 难度分层的结构，很适合作为"文档智能体"研究的标准压测集，也适合用来评测本文 5.3 节提到的通用编码智能体（OpenHands / Aider / SWE-agent）在视觉闭环任务上的真实短板。
