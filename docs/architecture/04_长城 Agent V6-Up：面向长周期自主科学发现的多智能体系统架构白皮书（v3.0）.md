## 摘要（Abstract）

**长城 Agent V6-Up** 是一套构建在开源 **DeepSeek Harness（DSH）** 与标准 **Python MCP（Model Context Protocol）** 之上的通用、面向长周期（10–20 小时级设计目标）、高并发、无人值守自主科学发现（AI for Science）多智能体系统架构，原生设计用于兼容**纯解析数学推导与构造性反例、形式化定理证明（如 Lean 4）、多保真数值物理仿真、多目标 Pareto 前沿优化以及无客观标量尺度的开放机理探索**。（注：本文所述的 10–20 小时运行周期与第五章四类异构走查为 v3.0 系统的架构设计目标与拟议验收场景；第一章表 1.4 引用的实证数据均保持其原文献实验范围。）

针对大模型长程科研中必然爆发的四大结构性病灶——**长上下文注意力退化与过早停滞、高并发群体思维坍塌、缺乏统一标量评估尺、以及静态验证器导致的能力饱和**——长城 V6-Up 提出了一套以 **“极薄无偏见事件总线 × 一委三部扁平制衡 × 3 真相 + 2 视图 × 沙箱平权 × 科研仪器科”** 为核心的系统架构：
1. **短生命周期会话解耦（治理层单次无状态 × 伴随单节点续传）**：宿主仅充当确定性事件总线；全部 5 个治理角色每次唤醒均为独立一次性短无状态会话，一线探索单元的一对一伴随助手仅在**单个探索节点内部**暂停续传（节点完结即随探索者一同销毁，绝不跨代常驻），将持久化研究状态彻底托管于外部 SQLite WAL 数据库与 Git Worktree，杜绝长对话“脑雾”与行政公文膨胀；
2. **数据真相与派生视图严格解耦**：全系统只维护 3 份只追加（Append-Only）唯一真相（观测账 `Obs`、门派私有谱系 DAG + 死胡同表、中央图书馆内外两翼）与 2 个轻量派生视图（`<= 2200` 字定额滚动重压缩看板、两级图书馆目录卡）；
3. **双向沙箱边界与工具平权**：严格区分“开放外部到内部（工作区公开题面、输入数据与《补充裁决文档》向所有角色只读挂载）”与“严防内部到外部（探索与盲审通过工作区外 `$PLUGIN_DATA` 隔离、环境变量隔离、路径/命令同步 Guard 与可选容器级隔离防 Reward Hacking）”；在各自受控沙箱内，不仅向一线探索者开放本地 Shell 与计算环境，也向同行盲审官开放独立的空白实测沙箱（支持 `pwsh/bash`、Python/SymPy、Lean 4），实现“跑着验证审稿”；
4. **科研仪器科（Plugin Is Everything）**：将所有评测脚本、仿真环境与诊断探针统一抽象为“仪器（Instrument）”，实行同一份代码三档调用（`probe / official / heavy`）、四态错误物理隔离（`OK / CANDIDATE_ERROR / INSTRUMENT_ERROR / INFRA_ERROR`，判不了绝不判负）与校准集回归驱动升版；
5. **制度化防盲从与严苛交付闭环**：通过单节点 `0–37%` 极简净室 $\to$ `37%` 伴随先扫目录再做外部专家元反思（给盲区诊断与撞车/参考编号指针，严禁代做科研决断）并当场解锁 $\to$ `37–70%` 开放检索 $\to$ `70%` 探索者先亲笔整理成果与《科研遗嘱》、退场后伴随核对客观证据单写落库的时间轴，叠加运行期 `>50%` 无豁免学派聚拢打散、三态两阶段同行盲审、以及“最短投入时间 + 诚实部分交付 + 两步联合终核”的双段终局门禁，保障系统在漫长无人值守运行中持续产出可独立复核的真科学成果。

## 第一章：问题定义、第一性原理与前沿理论基石

### 1.1 长周期自主科研必须正面攻克的四大结构性难题

将大语言模型从“单轮写一段代码或解一道竞赛题”推进到“10–20 小时、多路并发、无人值守地探索未知科学问题”，会立即撞上四堵彼此叠加的墙：

1. **长上下文注意力退化与“虚假繁荣”停滞**：当单一智能体的对话跨越数十万 Token 后，它不仅承受二次方膨胀的推理成本，还会被自己早期的错误直觉牢牢锚定，最终进入“反复自我合理化、宣布当前解已接近理论极限、拒绝继续实质探索”的怠惰空转。
2. **高并发下的群体思维坍塌（Diversity Collapse）与通信踩踏**：单纯把智能体数量从 1 个拉高到 6 个或 64 个，如果共享同一个未经审定的公告板，不出几轮全体分支都会蜂拥向同一个“表面容易出分、但存在根本结构天花板”的局部方案，高并发瞬间退化为无意义的算力重播。
3. **非标量化科学问题的“梯度缺失”与路灯效应**：软件打榜和算法竞赛往往有现成、快速的标量打分器；但真正的科学发现（如证明一条数学定理、构造几何反例、分析复杂动力学机理、求解 Pareto 多目标前沿）常常**没有单一实数分数**。失去标量指引后，模型会本能地躲到“路灯下”——专挑代码好写、容易出图的琐碎分支，或者不断造监控工具逃避核心科学难题。
4. **静态验证脚手架天花板与评测器自身缺陷**：在底层模型权重冻结的条件下，如果诊断工具、观测视角和验证脚本固定不变，搜索必将陷入严格的边际收益递减；与此同时，评测脚本本身也会出现读取漏洞或被智能体钻空子（Reward Hacking），如果系统分不清“工具坏了”和“算法错了”，就会把科学突破埋没在零分里。

### 1.2 对基座大模型的真实画像与《工程控制论》品味律

长城 V6-Up 的全部制度设计建立在两条清醒的认识论前提之上：
- **基座模型的真实画像**：当代前沿大模型本质上是一位**“符号推演带宽极高、预训练知识浩瀚，但缺乏长程学术品味、受长窗口注意力脑雾困扰、天生伴随怠惰与过度声称倾向的天才科研新人”**。因此，架构的使命绝不是用繁复的官僚公文或脆弱的正则脚本去“管死”她，而是像一座成熟、严谨的**人类学术共同体**一样：帮她挡住冗余噪声、在关键时刻请外部严苛专家敲醒她、给她透明精准的实验仪器、并对她提交的每一项硬核成果给予独立公正的同行评议。
- **钱学森《工程控制论》品味律**：*“一个真正优秀的系统，并不一定是大量最优子系统的强行拼凑，而是由配合良好、边界清晰的组件构成的和谐整体。”* 本架构宁要**简单、正交、可机械验证的硬约束**，坚决拒绝堆砌几十个状态锁、玄学数学公式和重型自动审批流。

### 1.3 五大架构刚性不变量（System Invariants）

以下五条是全系统的最高宪法，任何控制面代码、MCP 工具或课题插件都不得违背：

1. **判不了，绝不准判负（Error Attribution Separation）**：任何仪器自身崩溃、数据键位缺失或宿主基础设施异常，**绝对禁止**折算为 `0` 分、科学失败（`FAIL`）或“算法无改进”，更不得消耗探索者的修补配额或推高全局停滞计数。
2. **隔离靠沙箱，绝不靠砍工具（Sandbox Parity）**：防止泄密、越权或作弊的手段是清晰的双向隔离沙箱边界（工作区公开题面与裁决文档开放只读进内部；数据库、隐藏集与他脉隔离在工作区外 `$PLUGIN_DATA`，辅以同步路径/命令 Guard 及可选容器级隔离严防内部逃逸），而非把需要干活的角色阉割成零工具的“纯文本盲人”。一线探索者与同行盲审官各自在受控沙箱内，均享有完整的本地 Shell 与计算验证工具。
3. **跨版本指标不可比，工具修复走校准回归（Version-Scoped Comparability）**：科学观测的指标仅在同一个健康仪器版本 `(instrument_id, version)` 内可比；修复仪器 Bug 或封堵刷分漏洞，只需将复现案例加入校准集并全部通过即可上线，绝不要求“修 Bug 的补丁必须在旧考卷上刷出更高分”。
4. **常规争议制度自闭环，口径歧义亮红灯续跑（Unattended Continuity）**：常规分支合并、论证漏洞退回返工（`REVISE`）、结论适用边界收窄均由系统内置流程自动消化，不打断无人值守运行；仅当发现用户原始题目目标或验收口径存在根本性歧义时，向监控面亮起 **`ALERT_AMBIGUOUS_SPEC` 红灯**留待人类事后裁决，同时**严格按原已签口径继续推进**，绝不整夜死等停摆。
5. **高并发路径多样性优先于局部早熟繁荣（Unconditional Diversity Guard）**：在任意子题中，一旦同一思想学派聚拢了多个活跃分支且占比超过半数（`>= 2` 分支且 `> 50%`），系统立即强制将多余算力正交分流，不设任何“近期出分高即可豁免”的后门。

## 第二章：顶层系统架构——极薄总线、一委三部、“3 真相 + 2 视图”与沙箱平权

### 2.1 为什么采用“确定性极薄事件总线 + 全员无状态短会话”？

如果让一个总管 Agent 长期常驻对话、不断通过“父子派单树”把所有汇报拉回主会话，必然导致两大工程崩溃：一是父会话在几百步后上下文彻底腐烂，开始疯狂写几百 KB 的行政审批 `.md` 文件、甚至越权亲自下场改代码；二是宿主原生的嵌套子代理机制通常存在并发槽位上限（如最大活跃子代理为 8、嵌套深度为 1），无法支撑高并发并行探索与后台治理同时运转。

因此，长城 V6-Up 采用彻底扁平化的**外部编排事件总线架构**：
- **宿主编排器（DSH Control Plane）是 100% 确定性的薄代码**：它不调用大模型做主观决策，只监听 SQLite 状态变化与 Token 水位事件（如 `Parse 0` 签发、探索者到达 `37% / 70%`、节点进入 `AWAITING_TRIAGE`、盲审队列入单、学派占比超过 `50%`、仪器连续报错熔断）。
- **跨代零常驻短会话原则**：5 个治理角色每次唤醒均为独立一次性无状态短会话（注入极简 Push 视图 $\to$ 按需 Pull 真相并调 1–3 次窄工具写库 $\to$ 立即销毁释放槽位）；一线探索单元中的一对一 `lineage_companion` 在**单个探索节点生命周期内**以暂停续传方式复用同一会话（`PRE_SPAWN` $\to$ 暂停 $\to$ `37%` 续传 $\to$ 暂停 $\to$ `70%` 续传），**节点完结即彻底销毁，绝不跨代常驻**（若遇进程重启或异常断线，仍支持从 SQLite 无状态冷启动兜底）。**全过程严禁在工作区磁盘生成任何过程审批、汇报或审计类 `.md` 公文文件。**

### 2.3 数据底座：“3 个唯一真相 + 2 个派生视图”

多智能体系统最容易失控的原因，是把同一份科研进展同时抄录在日志、私有文档、公共库和看板里，导致多源脱节、谁该读谁彻底混乱。长城 V6-Up 实行极简的**“单一数据源（Single Source of Truth）”**原则：**全系统只存 3 份只追加（Append-Only）唯一真相，任何角色启动时只接收由真相投影出的 2 个轻量视图**。

| 分类 | 数据实体 | 物理表 / 载体 | 唯一写者 | 读写隔离与核心语义 |
|---|---|---|---|---|
| **真相 ①** | **观测账 (`Obs`)** | SQLite `observations`（另配 `probe_diagnostic_logs` 与 `async_eval_jobs`） | 隔离执行容器自动写入 | 只追加不篡改。仅 `official` / `heavy` 档仪器调用写入正式 `[Obs###]`，绑定 `(instrument_id, instrument_version)` 与四态 `status`。`probe` 档仅记轻量诊断日志，不污染正式账本。 |
| **真相 ②** | **谱系 DAG 与死胡同表** | SQLite `lineage_nodes` + `lineage_dead_ends` + Git Worktree 物理快照 | 一对一 `lineage_companion`（**独占单写权**） | **每个研究门派私有的实验记录本**。每一页节点记录一代探索者的 `<2000` 字客观 A/B 双栏手记、`<100` 字纯核心机制摘要、`evidence_grade` 与物理快照路径；所有已排除条件边界同步只追加写入 `lineage_dead_ends` 表（承担“历代全量只增不忘”的物理归档）。**跨门派物理不可互看**——不同门派之间只能通过中央图书馆交流。 |
| **真相 ③** | **中央图书馆（两翼分表）** | • 左翼：`external_literature_cards` (`[R###]`)<br>• 右翼：`internal_research_ledger` (`L3` / `L2`) | • 左翼：`library_surveyor`<br>• 右翼：`library_verifier` 审定事务自动写入 | **左翼外藏 `[R###]`** 存外部论文/教材摘要，显式标注为“未复验参考先验”，**从 `0%` 起全程开放 Pull**；<br>**右翼内藏 `L3` 确证库 & `L2` 否定雷达** 存本社区经隔离盲审实测通过的正反硬科学事实与确证失败经验，**`0–37%` 物理锁定，`37%` 元反思后当场解锁 Pull**。 |
| **视图 ①** | **谱系状态看板 (`Briefing`)** | SQLite `lineage_briefings`（`<= 2200` 字） | `lineage_companion` 在下代探索者启动前定额重写 | 谱系 DAG 的“最新一页扉页摘要”，采用**定额滚动重压缩** $\text{Rewrite}_{\le 2200}(\text{旧看板},\; \text{刚退场这一页最新手记})$（非字符串拼接：输入恒定 $O(1)$，输出按规则替换旧遗嘱、折叠旧过程并将旧死胡同下沉至 `lineage_dead_ends`）。它是派生视图而非真相——即使损毁也可随时从真相 ② 无损重建。 |
| **视图 ②** | **图书馆两级目录卡** | MCP 查询视图 `query_library_catalog` $\to$ `get_library_entry` | 查询接口动态投影（附 FTS5 全文索引） | **第一级**按每张 `<= 350` 字的独立摘要目录卡快速筛选，**第二级**仅针对选中的 1–2 条按 `entry_id` 拉取全文公式、推导与关联 `[Obs###]`，避免上下文被海量文献淹没。 |

### 2.4 双向沙箱平权与 7 大角色工具权限矩阵

**核心安全哲学：开放外部公开输入进内部、严防内部向外部逃逸；隔离靠沙箱边界，绝不靠阉割计算工具。**  
在早期多智能体实践中，人们常因害怕探索者偷看答案或盲审官偷看作者信息，而直接剥夺角色的 Shell 与脚本执行能力——这会让盲审官退化为只能“瞪眼读文字猜公式对不对”的橡皮图章，极易被大模型流畅的学术辞令欺骗。

长城 V6-Up 采用**双向分层沙箱隔离 + 平台感知工具平权**：
- **开放外部 $\to$ 内部（公开题面与版本化裁决只读共享）**：工作区公开输入区（`inputs/`、`source_materials/`、`rulings/` 及顶层公开题面文档）对有文件权限的角色开箱只读可见；在 `fork_branch` 与构建空白盲审沙箱时，宿主自动同步挂载公开输入与该任务绑定 `spec_revision` 对应的《补充裁决文档》至 `<sandbox>/inputs/`（同时将最新 `spec_revision` 与裁决摘要同步写入 SQLite，供 0 工具的后勤与监察委直接通过数据库视图读取）；
- **严防内部 $\to$ 外部（桌面分层隔离 + 可选容器级硬隔离）**：数据库本体 `greatwall.db*`、持久化产物 `eval_artifacts/`、物理快照 `snapshots/`、`evaluators/` 以及隐藏测试/校准集 `_hidden_*` 全部存放在被测工作区之外的独立目录 `$PLUGIN_DATA/workspaces/<ws_hash>/` 中；桌面直跑版通过**工作区外目录隔离 + 环境变量隔离 + Cordis `tools.guard` 路径/命令同步拦截（基于 `realpathSync`，并合法放行 `os.tmpdir()/dsh-spill-*` 溢出文件） + 空白只读盲审临时沙箱**构成完整防线；需要内核级硬防恶意脚本扫盘的高安全场景可直接切换至**可选 Docker / WSL2 容器隔离后端**（绝不篡改宿主机 Windows ACL）；
- 在严格封闭的受控沙箱内部，按操作系统平台自动开放真实执行工具（Windows 平台挂载 `pwsh`，类 Unix 平台挂载 `bash`）：

|---|:---:|---|---|:---:|

### 2.5 无状态启动下保持高业务熟练度的“四把工程手术刀”

每次无状态启动都清除了对话历史，如何让刚唤醒的 Agent 既不受前人脑雾污染，又立刻熟练掌控流程、零参数试错？系统依靠四把手术刀协同解决：
1. **角色盲盒裁剪**：每个角色的启动 Prompt 里完全剥离与自己无关的系统宏观制度术语（例如探索者只需理解“看看板与遗嘱 $\to$ 调仪器与推演 $\to$ 37% 反思解锁图书馆 $\to$ 70% 停笔交接”），且工具列表在 Schema 层物理裁剪至 3–6 个单一职责窄工具。
2. **JIT 工具回执动态路标（`next_step_guidance`）**：不要求 Agent 在开局死记硬背长篇 SOP；而是由服务端在每一次 MCP 工具返回 JSON 的尾部，根据当前实时水位与数据库状态确定性地附带 1–2 句下一步提示（例如刚跨过 `37%` 时自动亮起元反思提示，仪器报错时明确告知已自动报修工造司、非探索者算法问题）。
3. **百字工具速查表 + 单行合法 JSON 范例**：每个角色模板中为全部挂载工具提供一字不差的完整入参类型、枚举清单与单行合法 JSON 示例，从源头消灭参数名猜错与重试循环。
4. **代码与资产的物理代际持久化**：无状态销毁的只是聊天废话，探索分支 `<worktree>/tools/` 下的可复用工具清单会在下代启动时由宿主自动扫描注入，已证实的代码里程碑则通过物理快照（`Retained Candidate`）在磁盘代代接力。

### 3.1 Parse 0 六项启动表单与“人机分工”边界

科学任务的成败往往在开跑前 5 分钟就已注定——如果系统对题目的意图、完成定义和证据形态理解出现偏差，后面 10 小时的算力全都会跑偏。但试图用复杂的自动门禁脚本去校验“AI 是否理解了人类意图”只会导致官僚死锁。因此，长城 V6-Up 在 Stage 1 采取**最简单、最可靠的极简人机协同**：由工造司起草一份仅含 6 项核心字段的启动表单，人类花 2 分钟修改并签发确认，即进入全自动无人值守：
1. **问题陈述与“什么算完成”**：清晰界定目标，明确回答两件关键事——“阶段性/部分进展算不算数？”“严格证伪或给出反例算不算完成？”
2. **子题划分与可选策略题序（`question_order`）**：默认为 `[]`（全子题并行推进）；仅当任务本身要求先答 Q1 再答 Q2（如某些串行赛题或阶段实验）时填写。
3. **已有仪器、已知校准样本与指标方向**：列出人类手头已有的模拟器、数据集、Lean 检查器、金样本或已知毒样本（**允许全部留空**，无标尺开放探索可以 0 判定器开局）。
4. **已知候选思路提示**：人类若已有想试的方向可填入，**允许留空**，不强迫系统凑齐固定条数。
5. **总预算与最短投入时间（`min_commitment_window`）**：例如最少持续探索 8 小时或总预算的 80%，防止模型一遇难题就急着交差。
6. **预期交付形态**：如完整学术论文 + 可复现代码套件 + 阻碍证明汇编。

### 3.2 无人值守运行期治理边界：制度自闭环 vs 红灯续跑

进入 Stage 2 后，系统默认处于**无人值守模式**：
- **制度自闭环（绝不打扰人）**：探索分支分叉、论证不严被审稿退回返工（`REVISE`）、结论成立范围收窄（`ACCEPT_NARROWED`）、代码报错原地修补、仪器内部读数 Bug 修复，全部由“一委三部”既定协议自动闭环消化。
- **口径歧义红灯续跑与版本化公开裁决共享（绝不整夜死等、绝不按旧题答对却按新题判错）**：仅当工造司、后勤或监察委在深水区发现**人类在 Parse 0 签署的题目核心目标或验收标准本身存在重大歧义**（超出内部工具修复范畴）时，写入 `compliance_alerts(status='ALERT_AMBIGUOUS_SPEC')` 并在监控界面亮起红灯提醒人类事后裁决；与此同时，**事件总线严格维持当前已签口径继续调度探索，绝不挂起停摆**。人类如需事后澄清题意或补充规则，直接将《补充裁决文档》放入工作区公开目录（`rulings/`），控制面自动递增单调版本号 **`spec_revision`** 并同步版本号与摘要至 SQLite（供 0 工具的后勤与监察委通过 DB 视图读取）：已启动的旧节点按其创建时绑定的旧 `spec_revision` 自然跑完，新派节点绑定最新 `spec_revision`；盲审官 Stage 1 按手稿绑定口径 `vK` 客观判定科学真伪（若已有更新口径 `vM > vK`，仅在 Stage 2 如实标明成立口径且不得标最新 `FULL_GOAL`）；若需强制改走新口径，执行确定性 `pause -> 补裁决文档 -> abort_node(node_id) -> resume`，彻底避免向在线会话广播指令造成休眠伴随误醒或盲审击穿。

### 3.3 双段式终局门禁与两步联合核签

参照 OpenAI 解决圈双覆盖猜想（CDC）的实战经验——*“未满最短时长绝不轻言放弃；结束时要么交出经对抗审计的完整成果，要么只诚实交付最强的严密已证结论与精确剩余缺口”*——长城 V6-Up 设立严格的双段式结题与两步终核机制：

1. **三类合法终局模式（`check_stage2_closure_gate`）**：
   - **`FULL`（完全结题）**：Parse 0 契约中每一道必答子题均在 `internal_research_ledger` 至少拥有 1 条活跃且 **`goal_coverage == "FULL_GOAL"`** 的 `L3_VERIFIED` 条目（局部引理、范围缩窄特例 `ACCEPT_NARROWED`、等价归约 `EQUIVALENT_REDUCTION` 均不得标为 `FULL_GOAL`；若契约明确允许证伪结题，对应子题确证的 `NEG_COUNTEREXAMPLE / BARRIER_PROOF` 方可标为 `FULL_GOAL`）。
   - **`PARTIAL_ON_BUDGET`（预算耗尽诚实部分交付）**：在到达 `min_commitment_window` 之前，**物理禁止任何 Agent 主动申请此模式退出**（遇阻只能触发五车道停滞复苏）；唯有跨过最短投入时间且总预算耗尽时，才准许导出当前已通过盲审的 `L3` 成果，并逐题如实写明未完成子题的精确剩余缺口（Remaining Gaps）。
   - **`PARTIAL_ON_HUMAN_STOP`（人类显式紧急叫停）**：当人类用户通过控制面 UI/CLI 显式触发紧急叫停并由宿主写入不可伪造的 **`project_closure_state.human_stop_requested_at`** 后，不受 `min_commitment_window` 约束，立即停止新派单并导出当下所有已通过盲审的 `L3` 与剩余断点（**服务端强校验控制面真实人类叫停记录，严禁轻信 Agent 自行传入 `human_aborted = true` 绕过最短投入时间**）。
2. **五件套交付物与绑定导出版本的两步联合核签（`DELIVERY_EXPORTED` $\to$ `CLOSED_VERIFIED`）**：
   - `library_surveyor` 调用 `export_stage3_final_delivery`，**仅允许引用已入库 `L3` 条目（严禁混入任何未过盲审的草稿或自吹总结）**，生成五件套落盘至 `<workspace>/final_delivery/`（① 正式研究报告/论文；② 最小可运行复现套件；③ 阻碍证明与否定清单；④ 谱系探索路线图；⑤ 后续研究断点笔记），同事务签发唯一 **`delivery_id` 与整包 `delivery_sha256`** 并重置终核状态为未签，将系统置为 **`DELIVERY_EXPORTED`**（待核签）。
   - 控制面随即自动唤醒 **`library_verifier` + `supervisory_committee`** 执行绑定该具体导出版本的联合终核：`library_verifier` 在空白验证沙箱只读核对当前 `delivery_id` 五件套与全部被引 `L3` 的 `exact_verified_scope_md`（严打撰稿扩写时把局部特例吹成全称定理！）并实跑复现套件，无误后落签绑定 **`verifier_audited_delivery_id / sha256`**；监察委签发 `CLOSURE_GATE(PASSED)` 时服务端硬校验已核签版本与当前最新导出版本完全一致，方晋升 **`CLOSED_VERIFIED`**（若审过报告 A 后馆员重新导出报告 B，A 的核签自动失效不可放行 B；人类紧急叫停时允许直接带走当前已导出的部分五件套）。

## 第四章：四大核心子系统深度机理设计

### 4.1 工造司（科研仪器科）：统一仪器、三档四态与校准升级

#### 1. 第一性定位：仪器提供商，而非科学判官
工造司的本质是实验室里的**“科研仪器科”**——它的职责是打造透明、隔离、可信的测量工具与计算环境，**而不是强行给每一道科学问题捏造一个标量打分器**。
- 通用底座坚持纯粹的 **`plugin is everything`**：领域验证规则（是否需要参考基线、某题是否允许全零解、物理仿真分布容差指标是什么）全部由具体课题的仪器插件自行实现，通用执行容器一条都不硬编码；
- 对于纯数学证明或无标尺开放探索，Parse 0 完全允许**不注册任何判定器（0 `VERDICT` 仪器）**，探索方向由同行盲审、`37%` 元反思与人类检查点引导，工造司专攻搭建计算环境与诊断探针；
- 根据 `Audit the Scaffold` 与 `RQGM` 的实证结论（冗长复述报错效应量为 0；83%–90% 有效演化发生在全员共享基建），工造司日常工作的最高杠杆优先级是：**① 修复故障工单 $\to$ ② 扩展科研可观测性（把黑盒模拟器拆成按种子耗时、长尾分布、守恒残差等透明诊断探针） $\to$ ③ 加固防作弊（Reward Hacking）与收编多分支重复手写的轮子**。

#### 2. 唯一核心抽象：仪器（`Instrument`）与统一调用协议
系统中一切验证器、模拟器、证明检查器与诊断脚本统一抽象为 **Instrument**，分为三类 `instrument_role`：
- **`VERDICT`（判定器）**：能够产出正式科学结论 `verdict` 与 `[Obs###]` 收据（如数值验证器、Lean 4 编译检查器、通用反例复核器、学习型审稿插件）；
- **`PROBE`（只读诊断探针）**：只产出结构化多维诊断剖面（`tracks` + `details`），`verdict` 恒为 `null`；
- **`ENV`（计算环境与数据集）**：提供模拟器运行时、基准算例数据或符号计算依赖。

所有仪器实现**唯一标准化调用接口**：
```python
evaluate(artifact, spec, tier) -> {
    "status":  "OK" | "CANDIDATE_ERROR" | "INSTRUMENT_ERROR" | "INFRA_ERROR",
    "verdict": "PASS" | "FAIL" | "UNDECIDED" | None,     # 仅 VERDICT 填写；PROBE 恒为 None
    "tracks":  dict[str, float | int | str | bool],      # 0..N 条独立进展轨道，不假设单一标量
    "details": str                                       # 面向探索者的结构化诊断文本
}
```
其中 `artifact` 的形态由仪器插件自声明（可以是含 `run(public_input)` 的 Python 模块、`.lean` 源码目录、构造反例 JSON 数据包或文本手稿），通用容器不将其锁死为单一文件格式。

#### 3. 同一份代码、三档调用（消除“自测与正式两张皮”）
科研人员既需要高频、便宜、信息详尽的快速试错，又需要隔离防作弊的正式科学凭证。如果让探索者自己写一套本地脚本测、生产沙箱又跑另一套接口，必然导致契约割裂（自测全过、正式全挂）。因此，长城 V6-Up 规定**同一份仪器代码原生支持三档调用**：

| 档位 (`tier`) | 目标与数据隔离 | 凭证记账与约束 |
|---|---|---|
| **`probe`**（快速探索档） | 挂载公开/开发样例，返回详尽诊断剖面，供探索者高频调试 | 仅写轻量 `probe_diagnostic_logs`，**不记入正式 `observations` 科学账本** |
| **`official`**（正式受控档） | 在受控隔离沙箱中不可篡改执行：**有保留/隐藏判定集的题跑隔离保留集；无隐藏集的开放发现题跑固定公开配置 + 多种子复现集（允许产出 `OK + UNDECIDED`，由盲审沙箱做独立变种子复现核验，绝不为过审强造假隐藏集）** | 写入正式 `[Obs###]`，绑定 `(instrument_id, instrument_version)`，作为分诊与盲审凭据 |
| **`heavy`**（重型实验档，*可选高级特性*） | 针对超长耗时高成本仿真或大规模搜索（常规科研以 `probe` + `official` + 四元复合缓存为主力） | 调用前强制填写事前预期 `linguistic_prediction`，入队 `async_eval_jobs` 时冻结候选与 `tools/` 快照、原仪器版本与验证规格；支持宿主重启后按原冻结规格续跑并凭同一 `job_id` 幂等取回、仅扣一次预算 |

*(注：探索者在自身 Worktree 依然保留随时使用 `pwsh/bash` 写一次性微验证脚本的科研自由；但凡涉及正式仪器调用，统一走上述三档同码接口。)*

#### 4. 四态物理隔离与“判不了绝不判负”铁律
仪器和宿主出错是平台工程问题，绝不是科学假说被证伪：

| `status` | 精确语义归因 | 平台确定性处理动作 |
|---|---|---|
| **`OK`** | 仪器健康跑完并给出有效观测 | 按 `verdict`（`PASS` / `FAIL` / `UNDECIDED`）映射为 `VALID_PASS` / `MEASURED_REJECTION` / `VALID_UNDECIDED` 登记科学账本 |
| **`CANDIDATE_ERROR`** | 候选产物自身语法错、运行时崩溃、缺入口、超时 | 归属探索者工程缺陷，后勤可判 `LEVEL_2` 原地修补（上限 3 次）；不计入科学否定 |
| **`INSTRUMENT_ERROR`** | 仪器自身抛异常、漏读 `public_input`、协议不合规 | **严格零处罚探索者**（不打 0 分、不扣修补配额、不增停滞计数、不进永久缓存）；**同事务自动开单 `works_engineering_queue`** 并向探索者回传“平台仪器故障已报修”；连续出错达 `3` 次自动熔断置为 **`UNHEALTHY`**，拒绝新的 `official` 调用 |
| **`INFRA_ERROR`** | 容器异常、磁盘 IO 或 RPC 传输超时等底座故障 | 同样**零处罚探索者**、穿透幂等缓存允许直接重试，并写系统告警 |

#### 5. 校准集回归驱动升级与版本域可比性
仪器在长程运行中必须能够持续修 Bug、堵刷分漏洞或演进严格度（如先提供宽容部分得分轨道保护早期萌芽，成熟后升级严苛口径）。长城 V6-Up 采用清晰、零死锁的**校准集驱动版本演进**：
1. **上线与升版唯一门控——独立校准集（Calibration Suite）**：
   - `PROBE` / `ENV` 类仪器可免配校准集（`null`）；**任何 `VERDICT` 仪器上线或升版，必须附带 `>= 1` 条独立校准用例**（JSON 数组，含 `{case_id, expected_status, expected_verdict, artifact_rel_path, public_input}`）；
   - **每个校准用例自声明预期 `(expected_status, expected_verdict)`**：例如空文件/缺入口用例预期 `("CANDIDATE_ERROR", null)`；照抄输入或已知作弊毒样本预期 `("OK", "FAIL")`；已知参考正解（或在该问题物理定义下合法的零解/常数基态）作为金样本预期 `("OK", "PASS")`——**底座绝不把全零解硬编码为全局非法**！
   - **修 Bug 与堵漏零死锁流程**：发现仪器读数缺陷或刷分漏洞 $\to$ 先把复现案例写成校准用例并确认旧版违背预期 $\to$ 修复仪器代码 $\to$ **服务端在独立子进程实跑全量校准集，100% 匹配所有用例的自声明预期即直接升版上线**（绝不要求修 Bug 补丁在旧指标上“严格赢分”）。
2. **版本域隔离与诚实重评**：
   - 所有 `[Obs###]` 永久锁定产出时的 `(instrument_id, instrument_version)`；不同版本的分数禁止跨版本混排比较；
   - 需要对比历史产物时，工造司通过 `get_works_engineering_queue` 查看待重评队列并调用 `recompute_stage_b_only` 读取外部持久化的候选原始输出按新版重算：**永久保留旧 `[Obs###]` 收据不覆写**（置 `SUPERSEDED_REVALIDATED`），重评成功生成一条绑定 `(instrument_id, new_version)` 的新 `[Obs###]` 收据并结案队列项（`DONE`）；若老产物缺少新口径所需字段或测试输入本身已变更，**诚实将旧收据与队列项标记为 `INCOMPATIBLE`（不可比）**，绝不做出“重算必能恢复 `VALID`”的虚幻承诺。
3. **工具沉淀账本（`SKILL_LEDGER.json`）**：当多个分支重复手造同类实用脚本时，系统自动开单工造司收编为全社区共享只读探针，经可执行与文件实存校验后登记入 `skills/SKILL_LEDGER.json`（保留原始成功/失败计数、适用范围、校验产物路径与回滚指针）。

### 4.2 后勤工作部与谱系系统：自适应时钟、看板解耦、分支依赖与学派分流

#### 1. 自适应真时钟（`W = min(500k, 模型窗口)`）、单节点同会话伴随与四幕生命周期
为了在保留深度专注力的同时彻底杜绝长对话“脑雾”、小窗口死锁与早期怠惰逃跑，每一位一线探索者（`explorer`）与专属一对一伴随助手（`lineage_companion`）沿统一的自适应上下文压力时钟 **`pressure_pct = pressure_tokens / W`**（其中有效窗口 **`W = min(500,000, 模型真实物理窗口)`**，数据由宿主 `TokenMeter` 权威采样并连同 `W` 一并原子同步至 SQLite）硬性走完四个清晰阶段：

```text
  PRE_SPAWN    0%                 37%                                70%（硬性跑满，无提前交接后门）
     │         │                   │                                          │
     ├─伴随重写►├──第一幕：独思净室─┼──第二幕：情报型元反思───┼──第三幕：开放 Pull ──┼──第四幕：两步清醒交接
     │ 看板后暂停│ • Push看板+inputs │ • 续传同伴随(无eval门槛)│ • 解锁全馆(L3/L2/R)  │ • Step1: 探索者停码，最后1轮
     │ (同会话  │ • 仅开外藏 [R###] │ • 先扫dead_ends与L3/L2  │ • 解锁本脉 DAG 与    │   只读亲笔整理成果与《遗嘱》
     │ 挂起待命)│ • 锁L3/L2与深层DAG│   目录再切专家 2 轮问答 │   dead_ends 全表     │ • Step2: 探索者退场，续传伴随
     │         │ • 自由pwsh与三档仪 │ • 给诊断+<=2指针+夜科学 │ • 深化推导/反例/验证 │   核对Diff/[Obs]独占单写落库
     │         │                   │   (禁给算法/代码/排序)  │                      │ • 置AWAITING_TRIAGE后双销毁
     │         │                   │ • 置unlocked=1伴随再暂停│                      │
```

- **单节点内“一探索者配一伴随”的暂停续传机制（绝不跨代常驻）**：
  - 在单个探索节点生命周期内，宿主以保活挂起方式（`keepAliveAfterIdle` + `continueAliveAgent`）仅创建**一个** `lineage_companion` 会话：`PRE_SPAWN` 写完行前看板后暂停挂起（Idle 零开销）$\to$ `37%` 传入消息续传完成元反思后再次挂起 $\to$ `70%` 探索者亲笔总结退场后再次续传完成核对与单写落库 $\to$ **随本代节点完结一同彻底 `dispose()` 销毁**。
  - **为什么既不“每次现拆 3 个碎片伴随”，也严禁“跨代常驻伴随”？** 单节点内伴随拢共只交互 3 次（上下文远不会膨胀），复用同一会话既让 UI 与心智模型高度清晰，又能让伴随在 `70%` 验收落库时天然记得行前看板与 `37%` 探索者亲口作出的反思承诺；而节点结束即销毁则彻底杜绝跨代常驻造成的记忆漂移。若中途宿主进程重启或保活句柄失效（含 `< 70%` 崩溃抢救），控制面保留**从 SQLite 无状态冷启动兜底伴随**的能力。
- **为何 `0–37%` 必须锁死内藏 `L3/L2` 与深层 DAG？** 维持这一段极简独思净室，是为了让每一代探索者带着自身独立的数理视角先撞一次真墙、暴露出真实的个人困惑，防止刚启动就去抄兄弟门派的作业导致群体思维坍塌。与此同时，工作区公开 `inputs/` 题面与外藏 `[R###]`（基础文献与标准定理参考）从 `0%` 起全程开放，不阻碍正常阅读原题与教科书公式。
- **`37%` 情报赋能型元反思与《诊断师 + 情报员》尺度红线（无数值 `eval_count` 门槛）**：
  - **无数值门槛**：纯数学推导、反例构造或开放理论探索在前 `37%` 窗口内可能全程在做严密推导而非数值跑分。只要水位达到 `37%`，控制面即在当前回合间隙顺序暂停探索者，续传其伴随助手进入 `REFLECT_37`。如果探索者到了 `37%` 仍一枪未发、只做空谈，这场元反思恰好起到当头棒喝的纠偏作用。
  - **情报前置扫描（告别空泛哲学拷问）**：伴随调用 `get_companion_context(mode="REFLECT_37")` 时，服务端同步提供探索者的去思维链轨迹摘要、**本脉 `lineage_dead_ends` 摘要、中央图书馆同题 `L3/L2` 目录卡摘要**，以及从 29 题夜科学题库 `1–28` 条中随机抽取的 1–2 道候选。
  - **严格的顾问尺度边界（融合 `Station v2` 外部学者视角与 `AgentDiscover meta.md` 禁令）**：伴随切换为外部严苛领域学者，角色定位死死卡在**《临床诊断师 + 避坑情报员》**，绝不越界成《代打军师》：
    - **允许提供的真帮助（决定“怎么想”与“看什么线索”）**：① **基于事实的盲区诊断**（必查 `Station` 第 7 类 `Attractor Tasks` 路灯效应 + 1 项对症元反思，直指当前实验/推导与反常现象的矛盾）；② **撞车预警与编号指针**（最多指出 **1–2 条**与当前方向高度相关的 `[L2-###]`/`[L3-###]` 或本脉旧死胡同编号，提醒探索者解锁后优先自行 Pull 核对，**不直接代读全文塞爆问答**）；③ **1 道贴合当前卡点的夜科学停码追问**。
    - **严禁越界（`AgentDiscover meta.md` 三不给红线）**：绝对禁止替探索者给出① 候选算力配额；② 排好序的执行方案表/菜单；③ 任何具体算法修改、公式推导、伪代码或代码块。下一步改不改方向、具体试什么，100% 归 `explorer` 自行拍板。
  - 双方完成 **$\le 2$ 轮、每轮 $\le 300$ 字**短问答后，伴随当场调用 `record_reflection_and_unlock_pull` 置位 **`first_reflection_unlocked = 1`** 并重新暂停挂起，控制面恢复探索者进入 `37–70%` 开放 Pull 攻坚。
- **硬性跑满 `70%` 两步清醒交接（探索者亲笔立遗嘱 $\to$ 伴随核对客观单写）**：
  - **绝不留提前交差后门**：正常科研探索必须硬性跑完 `37%` 反思并深推至 **`pressure_pct >= 0.70`**（不设任何主观提前下班判定，根治模型跑几轮即草率宣称完成并离场的怠惰倾向）；仅当遭遇外部不可抗终态（`human_stop`、`closure_allowed`、`abort_node`、DB 节点被外部关闭）或真报错/断线异常时才在 `< 70%` 停止。
  - **Step 1（科研思想与《科研遗嘱》归 `explorer`，先持久化后销毁）**：水位到达 `70%` 时，控制面在当前回合间隙**首先向仍保有完整工作记忆的 `explorer` 发出最后一轮只读纯文本收官指令**——禁止再改代码或运行耗时脚本，命令其亲笔整理本代核心成果、反常线索，并撰写《科研遗嘱》（明确下一步最小鉴别实验、关键怀疑点与判定翻转条件）。**控制面先将亲笔原文可靠持久化至 SQLite `lineage_nodes.will_md` 后，再销毁探索者句柄**（若中途重启，`will_md` 非空即原样交伴随续跑 Step 2，为空则转 `CRASH_RECOVERY` 并如实标注原文缺失）。
  - **Step 2（客观化核验与数据库单写权归 `lineage_companion`）**：接近高水位时探索者容易过度自我合理化，因此数据库写入权（`submit_node_handoff`）由一对一伴随助手独占。探索者退场后，控制面续传伴随助手进入 `HANDOFF_70`，对照**探索者亲笔总结与《科研遗嘱》**、Worktree Diff 与客观 `[Obs###]` 日志，完成去人称、将客观事实与主观猜想严格分拆为 **`<2000` 字 A/B 双栏手记**（A 栏仅含客观实测与推导事实，供 Stage 1 盲审；B 栏含主观猜想与下代《科研遗嘱》，Stage 1 物理屏蔽）、提取 `<100` 字纯核心机制 `mechanism_summary`、标注 **`evidence_grade`**（`NONE` / `ARTIFACT_ONLY` / `MEASURED`）并同步追加写入本代结构化 `dead_ends`，落库置 `AWAITING_TRIAGE` 后随本代节点一同销毁（且 `submit_node_handoff` 严防静默吞稿：仅同内容重试才幂等跳过，对已闭环节点写入不同内容必硬报错 `ERR_LOCKED`）。
- **未满 `70%` 意外断线抢救（`CRASH_RECOVERY`）**：若探索者会话在 `< 70%`（甚至 `< 37%`）意外断开或超时（来不及执行 Step 1 亲笔遗嘱），控制面立即标为 **`interrupted_unclaimed`**（状态唯一落 SQLite `pending_handoff_mode`）并续传或无状态冷启动伴随助手接管工作区——只要探索者**不是一字未产的空崩溃**（`is_empty_crash == false`，即便 `eval_count == 0` 只要留有推导证明稿、反例脚本或阶段代码），一律抢救写入一页正式 DAG（如 `evidence_grade = "ARTIFACT_ONLY"`）并置 `AWAITING_TRIAGE`；仅一字未写的空崩溃归入 `scratch_log`，防止空白记录污染谱系。

#### 2. 客观双栏手记契约与看板解耦（真相全量归档 vs 定额滚动重压缩视图）
系统严格区分“历代全量记忆”与“单代启动视图”的物理职责：
- **历代全量只增不忘 $\to$ 底层 `lineage_dead_ends` 只追加表**：伴随助手在每次 `submit_node_handoff` 时，将本代已排除的条件边界与失败机理结构化追加写入 `lineage_dead_ends` 表，明确区分三类：`SCIENTIFIC_REFUTATION`（科学证伪）、`IMPL_FAILURE`（代码/实现失败）、`ENV_FAILURE`（环境故障）。第 30 代探索者在 `37%` 解锁后仍可一键调阅第 1 代的完整排除记录。
- **表层《谱系状态看板（Briefing）》 $\to$ `<= 2200` 字定额滚动重压缩视图（非字符串叠加！）**：
  - 在新一代探索者启动前，伴随助手以**恒定 $O(1)$ 输入**（仅读旧看板 + 刚退场这一页最新手记，不回读前 $N$ 代）执行**有界滚动重写**：
    $$\text{新看板} = \text{Rewrite}_{\le 2200}(\text{旧看板},\; \text{刚退场这一页最新手记})$$
  - 服务端硬约束**总长度 `<= 2200` 字**（严禁静默截断切片，五段配比仅作软参考允许按需挪用）。为确保迭代几十代后依然逻辑自洽、不爆字数也不误删核心前提，伴随重写时必须遵守**四条腾笼换鸟压缩规则**：
    1. **段 1（核心机制）保持稳定精炼**：一句话锁定本学派底层数理不变量与思想路线；
    2. **段 2（已证实前提、快照与 `REVISE` 异议）合并覆写**：已被超越的旧基线和中间过程细节直接淘汰，仅保留最新 `Retained Candidate` 快照、一句话压缩后的已证实前提，以及仍活跃的审稿 `REVISE` 返工异议（置顶高亮）；
    3. **段 3（当前核心矛盾）覆盖刷新**：已经解开的旧矛盾折叠并入段 2，段 3 仅留眼前尚未突破的最新卡点；
    4. **段 4（死胡同精选）Top-K 淘汰下沉 + 段 5（上代《科研遗嘱》）整体替换**：段 4 仅保留与当前段 3 核心矛盾最直接相关的 Top-K 条排除边界，被挤出 2200 字预算的旧死胡同**不会丢失**（已永久保存在 `lineage_dead_ends` 真相表），段 4 末尾附一行索引（如 `本脉共沉淀 N 条历史排除边界，37% 解锁后可调 read_lineage_graph(view="dead_ends") 查全量`）；**段 5 直接移除上一代已执行的旧遗嘱，整体替换为刚退场这一代的新《科研遗嘱》**。

#### 3. 极简两机制依赖控制（绝不跨分支锁死）
真实科研中，依赖是某条具体方法分支的属性，而非整道题的全局枷锁。系统只保留两套清晰简单的前置机制：
1. **可选全局策略题序（`question_order`）**：仅在 Parse 0 由人类按需填写（默认空，全子题并行）；若填写，前序子题产出至少 1 条 `goal_coverage="FULL_GOAL"` 的活跃 `L3`（或被人类显式放行）后自动解锁下一子题。
2. **分支级确定性前置（`requires: list[str]`）**：后勤建分支或执行 `fork_branch` 时可选填系统可确定性查库的前置 ID，**仅限两类**：`L3-###`（须为活跃态）或 `OBS:<instrument_id>:PASS`（须存在有效通过观测）。调度器**仅阻断声明了未就绪 `requires` 的那一条分支，绝对禁止把同一子题下不同学派的依赖取并集锁死整题**！若某分支在运行期间其依赖的前置 `L3` 被撤回，控制面标记该分支 `premise_revoked = true`（不强杀正在跑的会话，待其自然交接时转入 `LEVEL_4B` 处理）。

#### 4. 动态方法族谱与无豁免 `> 50%` 聚拢刚性打散
为了避免高并发算力在运行中途自发聚拢到同一个“表面容易微调出分”的套路里：
1. **核心思想归类权归后勤**：每次交接必填 **`mechanism_summary`（`< 100` 字，只陈述核心数学/物理机制、不变量或归约框架，严禁写指标分数）**。后勤在 `triage_node` 时对照《方法族谱登记册（`method_families`）》，依据底层思想（而非表面措辞）决定归入已有 `family_id` 还是新立正交学派。
2. **开局不硬凑，运行期持续刚性保障**：Stage 2 开局按人类 Parse 0 提示思路起步（无提示时正常起手），不设“开局必凑 2 条互斥路线”的官僚门禁；多样性由控制面在运行中**确定性强制执行**——每当任意子题出现**同一学派下聚拢了多个活跃分支（`branch_count_in_family >= 2`）且该学派在当前子题的活跃分支占比超过半数（`branch_count_in_family / total_active_branches_in_question > 0.50`）**时，控制面立即发出 `FAMILY_CONCENTRATION` 事件唤醒后勤总管，强制将超额分支正交分流（`fork_branch(fork_mode="orthogonal")`）至节点最少的学派、阻塞已解除的旧学派或新立正交学派。**此规则不设任何“近期高产豁免”后门**，彻底斩断局部微调刷分吞噬全题并发槽位的通道。
3. **两级公平槽位调度 & 延迟交叉授粉**：并发槽位（默认 `6`，硬上限 `10`）先按子题公平、再在子题内按学派公平分配。`LEVEL_4B` 默认只阻塞触发缺引理的本分支及其同前提子支，仅当后勤确认该 `blocking_lemma` 属全学派共同前置时才标记全学派 `BLOCKED`（日后任何分支声明实质绕开机制 `new_mechanism_note` 即可随时重开）。跨学派交叉授粉（`cross_pollinate`）仅在**双方学派各自至少已有 `>= 1` 条已入库 `L3`** 后才予放行，保证各路线充分独立演化后再嫁接。

#### 5. `AWAITING_TRIAGE` 禁抢跑硬锁、四级认知分诊与五车道复苏
节点进入 `AWAITING_TRIAGE` 后，**在后勤调度总管完成 `triage_node` 裁决并由宿主刷新 `retained_candidate` 物理快照之前，宿主严禁在该分支抢跑启动下一代探索者**。后勤总管先过滤所有平台误差（`INSTRUMENT_ERROR / INFRA_ERROR` 零处罚），再按六类分诊精确裁决：

| 分诊类别 | 适用科学情形 | 宿主与数据库确定性动作 |
|---|---|---|
| **`ROUTINE_CONTINUATION`** | 正常渐进探索、局部假设排除，尚未达送审标准也未被彻底证伪 | 保持分支 `ACTIVE`，伴随刷新看板后启动下一代继续深化 |
| **`LEVEL_1`（突破送盲审）** | 产出满足对应主张形态的可核验载体（不限于布尔 `passed=1`） | 备份代码至 `<workspace>/snapshots/<branch_id>/retained_candidate/`；分支置只读冻结 **`PENDING_REVIEW`**，推入图书馆 `STAGE1_BLIND` |
| **`LEVEL_2`（候选代码原地修补）** | `CANDIDATE_ERROR` 导致科学假说本身尚未被检验 | 锁定研究方向禁止逃跑；宿主从物理快照恢复工作区，允许原地修补上限 **`3` 次**；满 3 次仍败写入本脉 `lineage_dead_ends(IMPL_FAILURE)` 并回退健康祖先（**严禁污染图书馆 `L2`**） |
| **`LEVEL_3`（偏科/反常特异保护）** | 主标量暂低或无标量，但呈现罕见守恒律、结构反常或 Pareto 单维非支配优势 | 经防伪迹双检后单开受保护特异核查支线，防止被单一指标过早淘汰 |
| **`LEVEL_4A`（严密证伪 / 结构阻碍）** | 构造出严密反例或完成路径不可行的《结构阻碍证明》 | 同事务将分支置为只读冻结 **`PENDING_REVIEW`** 送盲审：若盲审返 `REVISE` 则切回 `ACTIVE_REVISING` 补全反例/证明；唯有终判确证 `ACCEPT*`（入 `L3`）、`REFUTED`（入 `L2`）或 `REVISE` 超限才永久 **`SEALED`** |
| **`LEVEL_4B`（缺失引理条件阻塞）** | 卡在暂未攻克的定理级缺失引理或待就绪前置条件 | 留存 DAG 页、登记 `reopen_condition` 进 `Ready Queue` 暂停，并通知图书馆 `Auditor` 按需打捞残骸中的有效局部引理 |

当全局连续非突破交接达停滞阈值（默认 `8` 次）或全部活跃分支阻塞时，控制面唤醒后勤执行 **`dispatch_stagnation_five_lanes`（Station 五车道自救）**：将活跃分支强制打散编入 `EXPLORATION`（新原理）/ `EXPLOITATION`（深耕最优脉）/ `REVIVAL`（复活被阻或冷门线）/ `UNDERSTANDING`（退一步做机理解析）/ `STRATEGY`（重构问题切分）五条互斥车道持续突围。

### 4.3 中央图书馆与沙箱盲审：两翼分表、可核验准入、三态裁决与非连坐引用

#### 1. 两翼物理分表：参考先验 vs 确证资产与否定雷达
- **左翼·外藏表 `external_literature_cards` (`[R###]`)**：由 `library_surveyor` 在 Stage 1 预查新或 Stage 2 响应 `request_literature_survey` 采编入库，`0%` 起全程对全员开放两级 Pull。外藏明确标定为**“带出处但未经本系统独立复验的外部参考摘要”**；入库校验元数据、公式与前置假设、`read_depth`（`full_text / specified_sections / abstract_only`）、5 选 1 英文 `support_scope` 枚举及独立撰写的 `abstract_md`（建议 120–300 字，服务端硬限 60–1500 字）；**严格区分“馆员完成查新劳动”与“图书馆获得一篇文献”**：当委托资料客观不存在或违背合规边界时，馆员在同一入口提交 `outcome = "UNAVAILABLE_REPORT"` 与已查范围说明——**不向 `external_literature_cards` 插入任何不存在的伪 `[R###]` 卡、不强迫虚填 `read_depth`**，仅将对应 `survey_requests` 结案为 `CLOSED_UNAVAILABLE` 并保存不可得说明；**学术正确性由引用该文献的手稿作者与盲审官在实际推导/计算中自行核验**，绝不把外部摘录当免死金牌。
- **右翼·内藏表 `internal_research_ledger`（`L3_VERIFIED` 确证库 & `L2_FAILURE_RECORD` 否定雷达）**：`0–37%` 物理锁定，过 `37%` 元反思后开放两级 Pull：
  - **`L3_VERIFIED` 确证库**不仅收录正向定理与算法（`POS_THEOREM`），也堂堂正正收录通过盲审实测、逻辑无懈可击的**严格构造反例（`NEG_COUNTEREXAMPLE`）**与**结构阻碍证明（`BARRIER_PROOF`）**！每条 `L3` 同时标明 **`goal_coverage`**（`FULL_GOAL` | `PARTIAL_OR_LEMMA` | `EQUIVALENT_REDUCTION`），供后续免证引用与 Stage 3 撰文使用。
  - **`L2_FAILURE_RECORD` 否定雷达**保持高度纯净，只收录两类科学否定经验：① 经盲审实锤证伪、发现致命反例或不可修复矛盾的假说路线（`REFUTED`）；② 经最多 `2` 轮 `REVISE` 退回仍无法解决的审稿异议（`UNRESOLVED_OBJECTION`）。**一切工程崩溃、代码修补超限与沙箱故障均留在工单和本脉 `lineage_dead_ends`，绝不污染图书馆 `L2`。**

#### 2. 按主张形态匹配可核验性准入（通吃数值、形式化、反例与纯解析）
后勤在 `LEVEL_1` / `LEVEL_4A` 送审时，只检验“材料形式与主张类型是否匹配”（不判真伪），并由单节点最多送审 1 份手稿与超限降权机制防灌水：

| 手稿科学主张形态 | 送审必需可核验载体（至少齐备一项） | 盲审官核验方式 |
|---|---|---|
| **数值 / 物理仿真 / 优化主张** | 合法 `official` / `heavy` 档 `[Obs###]` 收据（含 `VALID_PASS` / `VALID_UNDECIDED`；无隐藏集的开放发现题附固定配置多种子 `[Obs###]`）及脱敏核心代码 | 盲审沙箱复跑代码，做独立变种子/扰动边界复现核验 |
| **形式化定理证明主张** | 证明检查器（如 Lean 4 `lake build`）仪器 `PASS` 凭证与源码文件 | 盲审沙箱核对原命题防篡改、审计公理并实跑编译校验 |
| **构造性反例主张** | 具体反例对象参数/数据 + 最小可运行复核校验脚本 | 盲审沙箱亲手运行校验脚本验算反例条件与目标破坏 |
| **纯解析数学推导主张** | 自包含分步推导正文 + 前提公理边界声明 + 极端特例自检说明 | 盲审沙箱借助 Python/SymPy 逐行验证代数恒等式、边界特例与 7 类结构漏洞 |

#### 3. 隔离沙箱两阶段实测盲审状态机与三态终判
每次评审拉起全新无状态 `library_verifier`，控制面为其现建**空白临时盲审沙箱 `blind_sandbox_<review_id>/`**（自动挂载只读公开 `inputs/`，按平台开放 `pwsh/bash` + Python/SymPy/Lean 4，0 写权且物理隔离 DB、B 栏、隐藏集、探索分支 Worktree 与外网）：

  - **`REFUTED`（确证否定）**：发现致命反例或不可修复矛盾，直接短路或终判写入 `L2(REFUTED)` 并置 `SEALED`。唯有对于此类已关闭分支（或 `LEVEL_4B` 阻塞、`REVISE` 超限分支），才允许唤醒 `Auditor` 调用 `propose_salvaged_lemma` 将残骸中有价值的局部引理剥离重写，作为新审稿单投入 `STAGE1_BLIND`，强制由**另一独立盲审会话**（服务端硬校验 `session_id != proposer_session_id`）跑完标准两阶段盲审后入 `L3`。
- **参考性阅读审计与非连坐引用传播**：
  - 探索者查阅馆藏时宿主自动记录 `FACT_LOG (READ)`，但在 Stage 2 **仅作为参考信息展示**，绝不因作者未调用读卡工具引用常规公理（如勾股定理或题面公式）就机械降级或拒稿；
  - 所有手稿声明的 `declared_refs` 默认写入 `epistemic_edges` 时边类型为 **`MOTIVATING_REF`（背景启发参考，不传播级联撤回）**；唯有 Stage 2 盲审官通过 `edge_type_overrides` 显式认证某上游 `L3` 为当前结论承重基石（**`REQUIRED_PREMISE`**）时，日后该前置被推翻才会精准级联重审下游依赖，彻底避免“随手一引就全军连坐”。

### 4.4 监察委员会：超然流程正义与零公文结构化审计

监察委员会（`supervisory_committee`）是全局最轻量的超然流程哨兵（`reasoning_effort = low`，单次唤醒 $\le 5$ 步，0 原生文件/Shell 工具）：
1. **零磁盘 `.md` 公文铁律**：所有巡检结论、阶段门禁与告警只写 SQLite `compliance_alerts` 表，严禁在磁盘生成任何审计报告文件；
2. **四大核心巡检职责**：
   - ① **`PARSE0_GATE`**：核验 Parse 0 六项启动表单已由人类签发（不干涉具体科学内容，不强求纯理论题挂数值基线）；
   - ② **仪器健康与口径红灯监控**：追踪 `UNHEALTHY` 熔断仪器；当无人值守期间捕获根本性题意/验收口径歧义时记录 **`ALERT_AMBIGUOUS_SPEC`** 供人类事后处理，同时确保总线按原口径不中断运行；
   - ③ **多样性与停滞看门狗**：核查学派 `>= 2 && > 50%` 聚拢信号与全局停滞阈值是否被后勤及时调度响应；
   - ④ **双段式终局门禁与最终核签**：执行 `check_stage2_closure_gate`，并在五件套导出至 `DELIVERY_EXPORTED` 且 `library_verifier` 核对正文无范围夸大、复现脚本一致后，签发 `CLOSURE_GATE(PASSED)` 将系统正式推进至 `CLOSED_VERIFIED`。

## 第五章：四类异构科学任务的端到端设计走查与拟议验收场景（Worked Walkthroughs）

以下用四类完全不同性质的科研任务作为**设计走查与目标 E2E 验收蓝本**（用于校验通用底座零偏科），手把手展示同一套架构如何无缝适配：

### 走查 1：纯解析数学推导与构造性反例（无预设数值基线）
- **Parse 0**：人类签署表单，问题为“判定平面有限点集直径圆是否总能覆盖点集，若否给出紧界证明与反例”；判定器栏留空或仅挂一个轻量“通用计算复核器”；`question_order = []`。
- **Stage 2 探索**：探索者 `0–37%` 仅凭外藏 `[R###]` 与沙箱内 `pwsh + python` 做几何微试探，构造出一个具体反例点集（附复核脚本），未跑任何数值打分器即到达 `37%`（185k，本例取 `W = 500k`）$\to$ 续传本节点伴随助手，先扫本脉死胡同与馆藏目录再做 2 轮专家元反思（给出盲区诊断与相关参考编号指针）并当场解锁内藏 $\to$ `37–70%` 探索者自主 Pull 已证引理补全一般位置证明 $\to$ `70%` 探索者停码并在最后 1 轮只读回合亲笔整理成果与《科研遗嘱》后退场 $\to$ 续传伴随核对遗嘱、Diff 与产物，以 `evidence_grade = "ARTIFACT_ONLY"` 独占单写 DAG 页并标定 `mechanism_summary`，随后双会话销毁。
- **分诊与盲审**：后勤见“构造反例对象 + 复核脚本 + 自包含证明”齐备，判 `LEVEL_1` 送审（分支冻结 `PENDING_REVIEW`）$\to$ `library_verifier` 在独立空白盲审沙箱内亲手运行 `pwsh` 跑反例脚本并拿 SymPy 核验不等式，确认反例成立但一般情形尚缺边界步，判 **`REVISE`** 退回原分支返工（切回 `ACTIVE_REVISING`）$\to$ 下代探索者补齐边界步后重审 **`ACCEPT`**，以 `l3_entry_kind = "NEG_COUNTEREXAMPLE"`、`goal_coverage = "FULL_GOAL"` 入库 `L3`。

### 走查 2：Lean 4 形式化定理证明（二值编译验证）
- **Parse 0**：工造司注册 `VERDICT` 仪器 `inst_lean4`（调用 `lake build` 禁 `sorry` 并校验原命题声明哈希，配 1 条含 `sorry` 的毒样本预期 `OK+FAIL`、1 条语法错用例预期 `CANDIDATE_ERROR+null`）。
- **Stage 2 探索**：探索者用 `tier="probe"` 快速编译本地子引理获得精准 Lean 报错信息；成型后用 `tier="official"` 取得 `VALID_PASS` `[Obs###]`。若探索中卡在一个定理级中间引理，后勤判 `LEVEL_4B` 阻塞该支，并允许 `Auditor` 从残骸中抽出已证子引理送另一盲审会话入 `L3`。
- **盲审与交付**：盲审沙箱内运行 Lean 检查器与公理审计（`#print axioms`），确证零作弊公理后入库 `L3(POS_THEOREM, FULL_GOAL)`。

### 走查 3：多保真数值物理仿真与多目标 Pareto 优化
- **Parse 0**：工造司注册多轨道 `VERDICT` 仪器（`tracks` 同时输出效率、能耗、守恒残差与尾部分位点，无单一强制标量）与透明诊断 `PROBE`（按随机种子分解耗时）。若中途发现仪器漏读输入字段返回 `INSTRUMENT_ERROR`，探索者零处罚、系统自动开单工造司；工造司先将该漏读场景写入校准集确认旧版报错，修补代码通过 100% 校准集后直接升级至 `v2`。
- **分流与保护**：当 4 个并发分支中有 3 个扎堆在贪心启发式学派（`3/4 > 50%`），控制面立刻触发 `FAMILY_CONCENTRATION` 强制将冗余分支正交分流至数学规划或贝叶斯新学派；某分支虽然综合指标暂低但 100% 保持能量守恒，后勤判 `LEVEL_3` 单开保护支线培育。

### 走查 4：无客观标尺的开放科学机理探索（如神经网络可解释性）
- **Parse 0**：无任何现成打分器，允许 0 个 `VERDICT` 判定器开局，仅挂 `ENV`（模型推理/微调运行时）与 `PROBE`（特征 SVD/探针分析脚本），或仅配固定公开配置 + 多种子复现的 `official` 仪器（允许返回 `OK + UNDECIDED`）。设定最短投入时间 `min_commitment_window = 8h`。
- **探索与防路灯效应**：每次 `37%` 伴随切换外部严苛专家强制拷问第 7 类 `Attractor Tasks`（严防模型沉迷画无洞察的浅层统计图），迫使其推进到因果干预实验；送审时 `library_verifier` 在隔离盲审沙箱内**独立变种子重跑干预脚本**复现因果效应，确证后入 `L3`；即便 8 小时预算耗尽未能完全穷尽机理，仍按 `PARTIAL_ON_BUDGET` 诚实导出已确证机理 `L3` 与精确未解断点，经联合终核无夸大后正式结项。
