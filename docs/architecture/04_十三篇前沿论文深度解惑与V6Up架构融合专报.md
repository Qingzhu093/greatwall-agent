## 第一章：系统哲学、理论基石与核心文献专题微综述

### 1.1 最高第一性与《工程控制论》学术共同体哲学

1. **AI for Science 最高第一性**：长城 Agent V6-Up 的全部架构决策彻底摆脱“单一标量打榜”惯性，原生面向长周期（10–20 小时）、多并发、无人值守的开放式 **AI for Science** 攻关——无缝兼容“形式化数学证明、多保真物理仿真、多目标帕累托前沿”及无统一打分尺的科学机理探索。
2. **钱学森《工程控制论》指导律**：*“一个真正优秀的系统并不一定是大量最优子系统的强行拼凑……真正优秀的系统往往是由并非最优、但配合良好的子系统构成的和谐整体。”* 本项目坚决追求高性价比的 **Engineering Taste（工程品味）**：用简单、配合良好、极难崩溃的机制解决核心问题，严禁堆砌几十个错误码、繁琐状态锁、20 位高熵密码预注册与假想 CTF 黑客式过度防御。
3. **对基座大模型的真实画像与治理准则**：
   - 基座 LLM 是**符号推导带宽近乎无限、知识浩瀚，但缺乏学术品味、受长上下文注意力脑雾困扰、天生倾向怠惰与自我合理化的“天才科研小白”**。
   - **治理哲学**：不要把“一委三部”建成拿着皮鞭监工、防探索者像防黑客一样的官僚堡垒，而要建成**机制严密、职责平行、互相制衡、各司其职且温柔护航的学术共同体服务机构**——把机械跑腿、上下文整理与反思规范交给专属伴随助手，让探索者 100% 释放科学创造力。

### 2.2 广义无标尺科学任务的三类评估适配与“通用底座 vs 按子题可插拔钩子”解耦铁律

1. **纯理论建模 / 解析几何 / 常微分方程推导任务（如 `2026 CUMCM B 题` 的纯几何覆盖推导 `Q1/Q2`，或一般热-电化学 ODE 推导 — 根治 `P10`）**：严禁放任纯理论子题无验证钩子或裸跑 `0 VALID`！工造司必须为理论子题挂载独立数学、符号与边界检验钩子，自动核验：① **量纲与单位矩阵齐次性 / 解析几何约束核验**；② **极限边界渐近行为**（如几何极端角度边界，或在热-电化学通用示例中低温极值阿伦尼乌斯内阻发散、$\text{SOC} \to 0^+$ 电压截止坍塌、$t \to 0/\infty$）；③ **`SymPy` 符号导数单调性、守恒恒等式或全局敏感度指数和 $\sum S_i \le 1$ 核验**；④ **形式化证明任务的原命题 SHA-256 锁定与 Lean 4 `lake build` 禁 `sorry` 累积编译验证**。
2. **多保真度物理与随机仿真（如 `2026 CUMCM B 题` 实测暴露的 `Q3/Q4` — 根治 `P24/P25`）**：`Tier-1` 粗筛 $\to$ `Tier-2/3` 高精度；各子题零号基线物理隔离（严禁如二轮实测般在 Q3 单遍巡航基线里混入 Q4 的 `second_pass` 复扫逻辑！）；**仿真器本身必须先通过与题面锚点分布最大误差 $<5\%$ 的保真门禁（Simulator Fidelity Gate，杜绝二轮实测 `simulator/core.py` 中 `24.8%–29.9%` 测点饱和于误差边界的失真环境），方准锁定纪元**。
3. **多目标帕累托前沿**：Stage 1 锁定各维底线 $\mathbf{r}_{\text{nadir}}$ 拦截退化奇异解；全维达标且局部突出者可入 `Level 3` 保护。

   - `Stage 2`：探索者净室启动（`0–37%` 纯 Push 看板 + 遗嘱 + `<worktree>/tools/` 清单，零行政文件读取），跑出首轮 `[Obs-003]`；达 `37%` 净工作水位（约 `160k` Token）时，与伴随助手完成 2 轮 $\le 300$ 字短问答，**当场置位 `first_reflection_unlocked = 1`**；进入 `37–70%` 后，探索者主动两级 Pull 图书馆外藏 `[R002]` 与内藏 `L2/L3` 目录卡，修正低温耦合项跑出 `[Obs-006] (VALID)`；`70%` 时由伴随助手单写者调用 `submit_node_handoff` 写入**谱系 DAG 新页**，后勤 `triage_node` 判为 `LEVEL_1` 备份物理快照并送盲审，图书馆 Stage 1 锁账本 $\to$ Stage 2 解盲 `PASS` 同事务自动写入**内藏 `L3-001`**！
2. **走查二 — 盲审拒稿 / 修补超限自动入 `L2` 雷达与跨代五段增量看板避坑**
   - 某分支尝试线性老化近似，在低温高倍率下被图书馆 Stage 1 盲审根据 `Evidence Ledger` 判定 `REJECT`——数据库**在同一事务内自动生成 `[L2-001]`（记录被证伪的精确温度与倍率区间）写入内藏 `L2` 失败雷达**；另一分支 `Level 2` 原地修补奇异雅可比矩阵满 3 次仍报错，后勤分诊事务自动将其写入 `[L2-002]` 并从物理快照恢复健康祖先。伴随助手按 `新看板 = 旧看板 + 最新手记` 五段定额改写看板（段 4 完整收录已踩死胡同，段 5 完整保留遗嘱不截断），下一代探索者一眼避开旧坑。
3. **走查三 — 子题钩子局部升版、细粒度 `DEPENDS_ON` 重评与 `L3 >= 1` 结题硬锁**
   - `Stage 2` 中期工造司升级了 `Q4` 的验证钩子 `hook_Q4.py`（通过 $BB_\epsilon$ 锚点门禁）：系统沿 `DEPENDS_ON` **仅将绑定了旧 `hook_Q4` 的 3 条 Q4 观测在同一事务内置为 `PENDING_REVALIDATION` 并入队，而 Q1、Q2、Q3 已有的 12 条 `VALID` 观测和已入库的 `[L3-001..003]` 丝毫不受影响**！工造司随即调用 `recompute_stage_b_only` 读取持久化的 `stage_a_output.json` 秒级完成 3 条 Q4 观测重评，送盲审通过产出 `[L3-004]`。此时 Q1–Q4 均满足 `INTERNAL_L3 >= 1`，监察委核验结题硬锁全绿，顺利开启 `Stage 3` 论文撰写！

### 7.1 宿主架构总决断：开源 DeepSeek Harness (DSH) 确定性事件总线 × 读隔离新沙箱插件 × 标准 Python MCP 内核

在彻底放弃闭源 Antigravity 插件方案、全面转向**开源 DeepSeek Harness (DSH)** 后，结合二轮实机测试对 DSH 运行时的深度审计（参见 [`audit_E_dsh_native_and_sla_theory.md`](./第二轮测试分析/audit_E_dsh_native_and_sla_theory.md) 与 [`08_审阅质询与架构重整报告`](./第二轮测试分析/08_审阅质询与架构重整报告_面向设计者与施工方.md)），V6-Up v2.1 确立以下**开源 DSH 原生对齐规范**：

1. **独立新造科研编排插件 & `ctx.agents.create()` 确定性事件总线（不走受限于 8 槽位的 `dsh-subagent / allowedAgentPresets` — 根治 P1/P12/P13）**：
   - **架构拍板 1（采用 `ctx.agents.create()` 独立无状态编排）**：鉴于实测 `DSH 0.2.2-rc.3` 原生 `dsh-subagent` 存在 `maxDepth = 1`、`maxActiveSubagents = 8` 硬上限且结果强制回流父会话，长城事件总线**不通过 `dsh-subagent` + `allowedAgentPresets` 派单，亦不修改一行 DSH 原生源码**，而是直接基于 Cordis 插件扩展面调用 **`ctx.agents.create({ sessionId, meta: { cwd }, setup })` + `agentCtx.tools.restrict()` + `handle.dispose()`**（配合 `agent/turn-stopping`），从外部控制面直接拉起 **7 大角色契约模板**（`explorer`、`lineage_companion`、`logistics_coordinator`、`library_surveyor`、`library_verifier`、`works_engineer`、`supervisory_committee`）的单次无状态会话，突破 8 并发死锁并彻底消灭父会话回流！
   - **`37%` 反思采用标准回合间隙顺序控制流（非阻塞式工具套娃）**：`run_isolated_eval` 评估结束立即返回成绩单，由控制面在回合间隙顺序暂停探索者，从 29 条夜科学静态题库（第 `1–28` 条）中**随机抽取 1–2 条候选**推送伴随助手问答 2 轮（限 $\le 300$ 字） $\to$ 置位 `first_reflection_unlocked = 1` 后放行探索者（第 `29` 条专作全局停滞/Supervisor 锚点）；
   - **严禁使用未注册 Mustache 模板变量（根治 P12）**：角色 Markdown 中严禁出现 `{{cwd}}` 等非法占位符（工作树路径统一由 `meta: { cwd }` 与启动消息确定性 Manifest 显式传入）。
2. **`pressure_tokens / 500,000` 物理时钟、分级 `reasoning_effort` 与可配置并发上限（$\le 10$）（根治 P3/P4/P8）**：
   - 接入 DSH 原生 `@deepseek-ai/dsh-token-meter` 实时读取会话 `pressure_tokens`，直接按总上下文占比 **`pressure_tokens / 500,000`** 精准触发 `37%`（`185k`，扣基线后净干活 ~`155k–160k`，且须满足 `eval_count >= 1`）与 `70%`（`350k`，净干活 ~`320k–325k`）水位；
   - 按角色分级配置 `reasoning_effort`：`explorer`、`library_surveyor`、`library_verifier` 设为 `high`；`lineage_companion` 与 `works_engineer` 设为 `medium`；`logistics_coordinator` 与 `supervisory_committee` 设为 `low`；
   - 并发槽位 `max_concurrent_workers` 设为**可配置字段（默认 `6`，上限 $\le 10$）**，配合按子题优先公平调度（Question-Fair Slot Allocation），彻底消除多子题 $\times$ 多学派开局抢槽饥饿。
3. **保留探索者自由 `pwsh` + OS 内核/DACL 级读隔离沙箱（方案 A 拍板）+ 伴随单向透明读取 + DB 内嵌脱敏代码 Diff（根治 P14/P16/P21）**：
   - **架构拍板 2（选择方案 A：完整保留 `explorer` 的 `pwsh` 能力 + OS 内核/DACL 级物理读隔离）**：向 `explorer` 完整开放本分支 Worktree 内的 `read/write/edit/pwsh` 自由度；为防止通过 `pwsh` 越界偷读，施工侧必须将 `greatwall.db` 数据库本体、`_hidden_*` 隐藏测试集以及兄弟分支目录纳入 **OS 独立低权限账户 / Windows DACL 显式拒绝探索者进程读取**（并将隐藏验证集与 SQLite 连接托管于独立权限的 MCP/Evaluator 后端服务进程内存中，配合 `tools.guard` `realpathSync` 白名单双保险）；

4. **Stage 3 终局收官与四项窄工具协作拍板（架构拍板 3/4/5）**：

> 6. **插件化评估底座（`plugin is everything`）+ 按子题 `domain_hooks_by_question` + `<5%` 仿真保真门禁**：通用容器只约定 `{passed, metrics, details}` 协议；纯理论子题（`Q1/Q2`）与仿真子题（`Q3/Q4`）均须挂载独立验证插件与物理隔离基线；仿真器最大分布误差 $\ge 5\%$ 时锁死 Stage 2 派单；
> 7. **细粒度 `DEPENDS_ON` 作废 + 同事务入队 `pending_revalidation` + `STAGE_B_ONLY` 秒级重评**：彻底废除全局 `state_version` 连坐作废；`isolated_runner.py` 持久化 `stage_a_output.json` 并采用 `(candidate_hash, spec_hash, domain_hook_sha256)` 三元幂等键；
> 8. **开局多学派公平并发（`max_concurrent_workers <= 10`）& `orthogonal` 排除自身**：Stage 2 开局每题至少登记 $\ge 2$ 个互斥方法学派并按子题公平分配并发槽位；`orthogonal` 查重 SQL 强制 `WHERE branch_id != :self`；
> 9. **读隔离新沙箱插件、数据库显式 `worktree_abs_path` 映射 & `Retained Candidate` 物理磁盘快照备份/回滚**：隔离 `greatwall.db` 防探索者直读，废除 `n\d{1,5}` 正则猜路径；
> 10. **各子题 `L3_VERIFIED >= 1` 结题硬锁**：查询 `internal_research_ledger WHERE ledger_type = 'L3_VERIFIED'`，任何必答子题为 `0` 时代码层硬性阻断结题与 Stage 3 转换。
