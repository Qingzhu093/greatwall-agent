## 第一章：V6-Up 核心架构演化思辨录

### 1.1 基石复位：为什么 `Cogentic`、`The Station` 与 `AgentDiscover` 才是三大本体，`Stagnation` 绝不是 `Phase 2` 阶段？
在早期构想与前期 `teamwork` 报告（`03`）演进中，曾出现两个容易让人产生错觉的偏差：
1. **错误把“全局大萧条停滞复苏（GDRP / Station Stagnation Protocol）”画成了与 `Phase 0` 并列的 `Phase 2` 阶段**：这在动力学语义上完全说不通——科研攻关不可能规定“第 1 阶段启动 $\to$ 第 2 阶段固定去闹大萧条 $\to$ 第 3 阶段收尾”。真实生命周期只有**三段**（参考 `Cogentic` §2 & `The Station` §2–4）：**开局启动与人机对齐（`Stage 1 / Parse 0`）$\to$ 主体探索演进（`Stage 2`）$\to$ 终局综合与审校封箱（`Stage 3 / Consolidation`）**；而 `Holiday（夜科学假日）` 是常驻每个科研节点日常节律中的周期暂停（Station 原文中每 10 Ticks 第 9–10 Ticks 停跑实验做夜科学隐喻思考，出处 [`2608.23691_原文解析.md`](file:///D:/Documents/deepseek%20harness/论文研读/2608.23691_Autonomous_Mathematical_Discovery_in_an_Open-World_Multi-Agent_Environment/2608.23691_AutonomousMathematicalDiscovery_原文解析.md#L1061-L1063) 与开源库 [`holiday_prompts.yaml`](file:///D:/Documents/deepseek%20harness/论文研读/2608.23691_Autonomous_Mathematical_Discovery_in_an_Open-World_Multi-Agent_Environment/station/example/station/default/holiday_prompts.yaml#L1-L66)），`Stagnation Protocol（停滞自救）` 则是全局长期零突破时触发的**系统级抗停滞中断机制**（分派 5 条车道 + `Multistart`）。
2. **`Cogentic`、`The Station` 与 `AgentDiscover` 不应被隐没为默认背景**：实际上，“一委三部”中关于科研共同体形态、探索动力学与 AI for Science 研究品味的灵魂机制均扎根于这三大本体文献：
   - **`Cogentic` (`arXiv:2609.40324`)**：`Orchestrator` 调度但严守 `No Mathematical Opinion`（零数学偏见）；每个方向独立派生 `Summarizer` 提供差异化 `Briefing`；`Literature Reviewer` 开局扫描与遇阻定向二次调度；`Individual + Cross-Draft Verifier` 双层对抗审查；`The Record`（失败案卷）+ `The Verified Ledger`（由独立 `Auditor` 提纯并二次独立复验的引理账本）；`Process Advisor` 跨轮日志审计；以及 `Comparator -> Formal Writer -> Final Verification Audit` 三段式收尾。
   - **`The Station` (`arXiv:2608.23691` & `arXiv:2610.08927`)**：`Lineage` 代际传承与私有笔记隔离（学徒隔离）；`Coding Assistant` 减负写实验代码与 `Archive Surveyor` 按需综述文献；深挖承诺精神防遇错即逃；常驻节点的 `Holiday（夜科学假日）` 与切换外部专家视角的 `Meta-Reflection（71.7% 引导深化研究）`；全局停滞后的五车道 `Stagnation Protocol` 与 `Multistart`；以及接近上下文上限时刷新会话的机制。
   - **`AgentDiscover` (`arXiv:2610.05334`)**：在思想品味与搜索哲学上与前两者并立——基于 Sutton《苦涩的教训》深刻批判传统进化框架（`FunSearch`/`AlphaEvolve`/`OpenEvolve`/`MCTS-AHD`）由人类在运行前写死外环搜索策略、把本应超越人类设计的 LLM 降格为被动 Proposer（并引用 Gupta et al. 2026 证明 30 种固定脚手架均未稳定跑赢简单基线、`OpenEvolve` 垫底）；从而将搜索的元认知监控与控制权（Monitoring & Control）归还给探索智能体本身，把演化历史沉淀为单条查询可达的图数据库，使 MAP-Elites、UCT 等均退化为探索者可自由调用、组合或改写的单次图查询，同时配以提交前预测、`Cost Note` 会话重置、`FACT_LOG vs CLAIM_DECLARED` 双轨及 Appendix C 隔离防作弊。

### 1.2 从“第一人称认知母本”到“客观去人称双栏《节点科学交接手记》”
原 [`手写project.md`](./手写project.md#L75) 设想由谱系助手每代写入一篇 `<2000` 字、带强烈学术直觉的**第一人称** append-only 认知母本。经过推演发现：第一人称（“我直觉认为…”、“我虽败犹荣…”）在 LLM 上会强烈诱发**人物角色扮演、自我合理化辩护，以及后代无状态节点对前代语气的权威盲从**，还会把实测事实与未验证脑洞混在一起。
- **收敛方案**：100% 保留 **“每代 `<2000` 字无损追加挂载于演化树节点（绝不把 30 代全压成单一 `2000` 字）”** 与**“保留敏锐学术直觉和反常嗅觉”**两大精华；但取消第一人称叙事，改用客观去人称化的双栏结构——**A 栏【实测事实与已排除项】**（硬事实、观测 ID、预期对照、`EXECUTION_ERROR` vs `MEASURED_NON_IMPROVEMENT`）与 **B 栏【机理反常线索与 `[UNVERIFIED_HYPOTHESIS]` 遗嘱提案】**（留住直觉，但显式标为待验假说而非前辈定论）。

### 1.3 “谱系总助手”与“分身伴随助手”为什么合而为一？
前期设想在“长会话常驻记忆”前提下，才迫不得已拆分出居中的“谱系总助手”和进沙箱的“分身伴随助手”。一旦采用外置演化图（DAG）+ `SLA` 无状态会话重启：
- 所谓“谱系总助手”本质上就是一套持久维护的外置基础设施——**【谱系状态维护系统】**（真相 ② 谱系 DAG 门派实验记录本 + 视图 ① 表层 `~2000` 字《当前谱系状态看板》+ 防兄弟节点撞车查重）；如果再专门常驻一个独立传话 LLM 扮演“总助手”，反而会制造类似 Anthropic Multi-Agent 报告警示的“传话游戏直觉磨损”与双倍协调开销；
- 每个具体探索节点则配备 **1 名一对一专属【谱系伴随助手 (`lineage_companion`)】**，伴随该具体节点的终身，并在三个确定性事件点作为短无状态会话被唤醒：① 新探索者开跑前按 **`新看板 = 旧看板 + 最新一页手记`** 增量合成 `~2000` 字净室看板；② `37%` 净工作 Token 反思点切换外部严格人类学者视角与探索者进行 2 轮 $\le 300$ 字短对话并当场解锁 `37–70%` 图书馆与本脉 DAG 检索权限；③ `70%` / `Cost Note` 或异常中断 `interrupted_unclaimed` 时，**作为唯一单写者**提炼 `<2000` 字客观双栏交接手记写入谱系 DAG 新页。

### 1.4 为什么放弃人工“实验 Tick”和多余的“跨会话代数时钟”，只保留“单会话 `500,000` 净工作上下文时钟 + 原生门禁”？
原 [`手写project.md`](./手写project.md#L72) 提出按 `37%` 上下文做元反思、`70%~80%` 上下文强制停笔写遗嘱；而 `The Station` 因为既无中央调度、又无四级分诊和上下文水位机制，所有科研纪律全绑在离散房间响应 **`Tick`** 上（包括 `40 Ticks` 学徒孤立、每 `10 Ticks` 假日、每 `25/50 Ticks` 元反思、`60 Ticks` 导师预承诺与 `320 Ticks` 停滞协议）。在推演中曾先后试过“把实验次数折算为长城 Tick”与“按无状态会话交接次数做一套跨会话谱系代数时钟（`Gen`）”，经第一性原理检视后**两者均被坚决砍掉**：
- **放弃“实验 Tick”**：复杂定理或大型仿真可能跨好几代上下文都在完成**同一个大实验**，根本无法准确切分“1 个完整实验”。
- **放弃“跨会话代数时钟（`Gen`）”**：纯属把 Station 多余的外部计数锁搬进长城，实际全部功能早已被更朴素的原生机制接管——① 每代 `37%` 已合流元反思与夜科学 `Holiday` 思考（不用数第几代放假）；② [`手写project.md`](./手写project.md#L71) 原生规定**“首轮 `37%` 元反思完成独立建构后当场开通图书馆/本脉 DAG 权限”**；③ **【日常默认继续 + 四级分诊（Level 4a 须带硬反证才准终结）】** 直接替代机械的 3 代承诺锁；④ 全局停滞只需看“全员阻塞或连续 `8` 次主线交接分诊零 Level 1 突破”两条朴素条件。
- **最终收敛（含二轮实机校准）**：全系统有且仅有一套物理真时钟——**单会话 `500,000` Token（1M 折半）净工作上下文长度（扣除首步静态基线 $T_{\text{base}}$：`37%` $\approx 150\text{k}$ 净增量且须完成 $\ge 1$ 次实验执行触发元反思与当场解锁；`70%` $\approx 320\text{k}$ 净增量或 `Cost Note` 触发伴随助手单写者停笔交接）**；谱系库只存纯粹的树结构深度（`tree_depth`），再无玄乎的人造时钟。

### 1.5 从“M2/初版产物中心化回退与高熵密码伪防御”到“极薄总线 × 一对一分身伴随助手 × Agent 专属知识库”
在审计完 Teamwork 基于旧版简略 `04` 产出的初版 `greatwall-v6up-plugin` 后，我们抓出并确立了三次决定项目品味的纠偏思辨：
1. **为什么把宿主主循环降格为“极薄无偏见系统事件总线”，打破后勤总管集权？**：初版实现把主协调器包装成了统管四部、独占密钥、连监察委和图书馆都要听它派单的传统星型太上皇，完全背离 [`手写project.md`](./手写project.md) “一委三部平行制衡”的宪法。最终明确主循环仅作无主观意志、零数学偏见的客观事件路由总线，后勤总管严格收束在后勤部内政范畴，四部门平行制衡、各自独立。
2. **为什么废除“20 位高熵 `session_id` 密码预注册”和“伴随助手双模阉割”，恢复真正的一对一分身伴随助手？**：用 20 位高熵随机令牌防探索者，实质是把容易脑雾的“天才科研小白”当成 CTF 黑客防御，平白增加上下文摩擦；真隔离应由宿主 `tools` 白名单 + MCP 查询语义隔离 + 可读节点标识完成。同时，探索者不该既做科研又分神去做看板总结、文献摘要摘录和手记压缩，因此废除平时仅吐模板串的“双模阉割”，确立**每个探索节点配一名一对一专属伴随助手**：包办启程跨代《状态看板》合成、探索期跑腿与 `Coding Assistant` 协同、`37%` 时引 `Station` 11 类元反思与夜科学引导、以及 `70%`/崩溃时 `<2000` 字客观双栏提炼与看板更新。
3. **为什么必须在当前工作区建立专供 Agent 看的知识库（[`agent_kb/`](./agent_kb/00_INDEX_Agent知识库总导航与必读映射.md)）？**：面向人类读者的长综述难以直接充当编码与 Prompt 团队的工程手册，容易导致团队偷懒不读 `D:\Documents\deepseek harness\论文研读\` 原文而交出 `[:120]` 字符串切片充当摘要、30 行保安式干瘪 Prompt 和空壳 CRUD。工作区自带的 7 份高密度 `agent_kb/` 知识卡将原论文机制、Prompt 武器库与本机精确文件行号直接喂到团队手边，彻底打通最后一公里。

### 1.6 二轮实机测试（2026 CUMCM B 题）复盘后的终极减法收敛：“3 真相 + 2 视图 + 时间轴大一统 (`0–37% Push -> 37–70% Pull`)”
在完成第二轮全链路实机测试（课题为 **2026 CUMCM B 题：无线电干扰源快速自动定位与清除**，详见 [`07_V6Up第二轮测试全链路复盘与设计归因档案.md`](./第二轮测试分析/07_V6Up第二轮测试全链路复盘与设计归因档案.md) 与 [`08_审阅质询与架构重整报告_面向设计者与施工方.md`](./第二轮测试分析/08_审阅质询与架构重整报告_面向设计者与施工方.md)）后，我们直面了“为什么精心设计的顶层架构落到底层却变成一场行政公文灾难（ROOT 连跑 644 步、名义总管 `be302832` 连跑 476 步、监委 `ac0de7c2` 连跑 365 步、满地 1.12 MB 过程 `.md` 公文、`178.5k` 缩水时钟致 13/13 探索者未出 `candidate.py` 先触 `37%`、全局 `state_version` 降级误将 `N_Q3` Epoch 2 全部 3 条 `VALID` 观测 `[Obs009]/[Obs010]/[Obs011]` 打成 `PENDING_REVALIDATION` 却漏入重评队列，最终全卷 `0 L3`、0 盲审收场）”的根本原因：**不是规则写得不够多，而是底层状态存在重复冗余（`L1` 与谱系 DAG 叠床架屋）、Push 与 Pull 时间边界错位（把 `37%` 解锁绑到了 `70%` 退场交接上）、且未把“全员无状态短调用 + 禁写流程公文 `.md`”定为物理铁律**。经过三轮第一性原理大讨论（原稿已归档于 [`归档/第二轮测试前_顶层设计原稿备份_20261119/`](./归档/第二轮测试前_顶层设计原稿备份_20261119/)），V6-Up v2.0 完成了四项最干净的顶层收敛：
1. **数据底座大减法（“3 个唯一真相 + 2 个派生视图”）**：
   - **取消中央图书馆里的 `L1`，将 `L1` 直接合一为【真相 ②：谱系 DAG（门派私有实验记录本）】**！每一代退场时由伴随助手单写者追加一页 `<2000` 字客观 A/B 双栏手记（只存 SQLite 表，严禁写共享目录明文 `HANDOFF.md` 防 Stage 1 盲审穿帮；零实测崩溃节点记入 `scratch_log` 绝不污染主 DAG）；
   - **【视图 ①：谱系状态看板 (`~2000` 字)】 = 谱系 DAG 的增量扉页**：伴随助手在新探索者开跑前，严格按 **`新看板 = 旧看板 + 刚退场那一页最新手记`** 五段定额预算增量改写（既完美还原 [`手写project.md`](./手写project.md)“每次复制并增量更新一份 $\le 2000$ 字状态母本”的直觉，又因底层有 Append-Only 的谱系 DAG 托底，30 代也绝不膨胀到 6 万字，更严禁 `[:2000]` 字符切片腰斩遗嘱！）；
   - **【真相 ③：中央图书馆】消解五大底层冲突，清晰划分为【左翼·外藏表 `external_literature_cards` (`[R###]` 外部资料与定理算子卡)】+【右翼·内藏表 `internal_research_ledger` (`L3` 黄金验证账本 & `L2` 公共失败雷达)】物理分表，共用【视图 ②：两级按需 Pull 目录卡 (`Catalog Card -> Full Detail`)】**：
     ① **借阅时机解耦**：左翼外藏 `[R###]` 从 `0%` 起全程对探索者开放 Pull（并支持 `request_literature_survey` 委托补查），右翼内藏 `L3/L2` 在 `0–37%` 物理暂锁防抄兄弟作业、`37%` 反思后当场开放 Pull；
     ② **采编与审稿工具面物理分离**：拆分为 `library_surveyor`（挂载检索/PDF 工具写外藏，无审稿权）与 `library_verifier`（物理剥离通用磁盘 `read` 工具与外网工具，纯 DB MCP 盲审）；
     ③ **两阶段合流物理盲审 + `Auditor` 直入盲审队列**：将 `Cogentic`（单篇+跨篇）与 `Station`（两阶段盲审）合流为单一状态机——Stage 1 为单篇盲态硬核验（锁死 `Evidence Ledger`，若 `REJECT` 直接短路同事务自动入内藏 `L2`），Stage 2 为解盲机理核对 + `Cross-Draft` 跨篇横向比对与交叉授粉提名（`PASS` 同事务自动入 `L3`，`REJECT` 同事务自动入 `L2`）；`Auditor` 打捞出的自包含局部引理直接作为 `STAGE1_BLIND` 新审稿单投入 `review_queue`，强制由另一独立 `library_verifier` 会话（`session_id != proposer_session_id`）按标准盲审复验入 `L3`。
2. **单节点时间轴大一统（兼容 `SLA` + `The Station` + `AgentDiscover`）**：
