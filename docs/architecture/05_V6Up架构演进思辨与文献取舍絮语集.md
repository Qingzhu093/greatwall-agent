## 第一章：V6-Up 核心架构演化思辨录

### 1.1–1.6 历史演进基石（V4 $\to$ v2.2，摘要保留）
- **基石复位**：`Cogentic`、`The Station`、`AgentDiscover` 确立科研共同体与三阶段（`Stage 1–3`）生命周期，取消把 `Stagnation` 错划成独立阶段；
- **交接与时钟简化**：去第一人称散文为客观去人称双栏手记；合并“谱系总助手”与“伴随助手”；放弃人工 `Tick` 与 `Gen`，收束为 `500,000` Token 单会话真时钟；
- **二轮减法（v2.0/v2.2）**：`L1` 退出中央图书馆并入谱系 DAG、全员 `ctx.agents.create()` 无状态调用、磁盘零流程 `.md` 公文、`0–37%` 外藏开放 / 内藏锁定 $\to$ `37%` 元反思当场解锁 `37–70%` Pull。*(二轮前及四轮前全量原稿已分别归档于 [`../../archive/`](../../archive/)。)*

### 1.7 第四轮实机复盘与三轮思辨收敛（v2.2 $\to$ v3.0 彻底去竞赛过拟合）
第四轮现场测试（基准 `3dfa211`）暴露了**中层接口割裂**与**顶层过拟合 CUMCM B 题**的双重碰撞（31 条 Q1 观测全报错无效、`Obs-031` 因 `spec.public_input` 漏读判 0 分埋没算例 D 直径圆反例、`hook_Q1` v4 修掉空输入漏洞却因 `tie -> incumbent` 被驳回、`0.7169 vs 0.9757` 无同源样本硬比大小）。经由三轮深度碰撞，确立 v3.0 六大根本性正本清源：

1. **为什么工造司必须从“科研判官”降维回【科研仪器科】？**
   - 此前把竞赛仿真题特例写死进通用底座（每题必有零号基线、全局 `<5%` 误差门槛、拦截全零/常数解、AST 禁 `second_pass`），一旦遇到纯数学证明或无标尺探索立刻卡死；
   - 剥离 `RQGM` 论文中为万次带噪采样的 Beta 分位数与平局保在位后，留下真正普适的工程骨架：**统一三档四态 `evaluate(artifact, spec, tier)`（判不了绝不判负）+ 校准集金/毒样本回归升级 + 只在同一版本口径内比对 + 工造司主攻扩展可观测性探针**。
2. **为什么不废除 `[Local-Sweep]` 就会产生割裂、不废除 `eval_count >= 1` 就会卡死纯推导？**
   - `AgentDiscover` 强推本地自测是因为它没有工造司且提交次数受限；而在 V6-Up 里，把同一个仪器拆出 `probe`（公开开发样快速诊断）与 `official`（正式凭证）两档，跑同一套代码，自然消除两套契约打架——保留探索者随时用 `pwsh` 写微校验脚本的自由，只拿掉“强制写 `[Local-Sweep]`”的教条负担。
   - 废除 `eval_count >= 1` 门槛，使纯数学推导/反例构造同样能正常跨过 `37%` 元反思与沉淀完整 DAG 一页。
3. **为什么要恢复 `library_verifier` 的执行工具（沙箱平权）？**
   - 源码核查证实 v2.2 把盲审的原生工具砍成了空数组 `[]`，这和过去怕泄密想砍探索者 `pwsh` 如出一辙（因噎废食）。正确解是给盲审配上**隔离空白审稿沙箱**（OS 封死 DB、B 栏、隐藏集与探索者 Worktree），在沙箱内大方开放 `pwsh/bash`/SymPy/Lean 4，实现“跑着代码审，而非瞪眼猜着审”。
4. **为什么既要保留 `37%` 元反思前锁定内藏、又要把 `REVISE` 和 `确证反例` 剥离干净？**
   - 经反复检验，`0–37%` 必须保持极简且严守“先过 37% 元反思（第 7 类路灯效应排查）再解锁内藏”，否则轻量及中高端模型都极易在未经提神前直接投机跟风或 Reward Hacking；
   - 同时把审稿裁决精确拆成 `ACCEPT* / REVISE(<=2轮返工，禁打捞插手) / REFUTED`，并将严格证伪的反例/障碍定理打标送入 **`L3` 确证库**、工程崩溃踢出图书馆，彻底打通正反成果入正文与返工流。
5. **为什么学派聚拢分流要删去 `>= 4` 与“高产豁免”、为什么无人值守遇口径歧义要亮红灯继续跑？**
   - 任何“近期高分就豁免分流”的口子，都会变成早期局部微调刷分制造“虚假繁荣”吸干并发槽位的后门；而删掉多余的 `>= 4` 前置数，只要出现同题同流派聚集多个分支且占比 `> 50%` 即刚性打散，最简单也最硬朗；
   - 无人值守第一性是不允许整夜停摆：常规分支合并与审稿边界由制度自闭环，真正遇到题干目标歧义时，亮起 **`ALERT_AMBIGUOUS_SPEC` 红灯**等人事后处理，同时严格按原已签口径继续跑完。
6. **G3 看板为什么采用定额滚动重压缩解耦文字矛盾？**
   - 把“历代全量只增不忘”的真相义务归位底层 **`lineage_dead_ends`** 表，让看板 `<= 2200` 字只承担当前焦点摘要与全表索引，避免在尚未实测出瓶颈前提前叠加“代码拼接+局部AI重写”的双轨对齐复杂度。

### 1.8 第五轮实机复盘与八项《工程控制论》收口（v3.0 工程硬化）
第五轮实战测试（2026 国赛 B 题，35 分钟运行，解压全部 254 个原始会话做黑匣子法医还原）暴露了一组极具价值的**“局部看似贴心、实则与其它子系统正面相撞”**的控制论失配：DSH UI 切模型未进入 `exec.agent.options` 导致 252 个子会话静默跌落至 272k 中转站、探索沙箱误拦截工作区公开题面、`intervene(steer)` 无差别广播踢醒保活休眠的只读伴随引发抢跑交接与 6 张无法关闭的 `PAIN_POINT` 工单、探索循环未回查 DB 终态造成 6 个僵尸占槽、工造司与采编队列缺乏结案/熔断机制导致 177 次 + 38 次空转自旋、以及 `submit_node_handoff` 误将已闭环节点的新稿当作幂等跳过静默吞稿。依据钱学森《工程控制论》原则，最终拍板以下 **8 项收口**（全部以零历史前提的正面规范写回 `04`、`09` 与 `agent_kb/00–05`）：

1. **砍掉 `Cost Note`，动态窗口 `W = min(500k, 模型真实物理窗口)`，硬性跑满 `37% -> 70%`**：消除模糊提前交接后门以根治大模型怠惰，并解决 272k/128k 小窗口模型按 500k 算 `70% = 350k` 永远无法到达的数学死锁（JS 与 Python 共享 SQLite 同步的单一 `W`）。
2. **整块删除 `intervene / steer` 实时广播与冷启动便签注入**：回归「版本化 `spec_revision` 公开《补充裁决文档》共享（摘要同步入 SQLite 供零工具的后勤/监察可见；节点锁定作答口径、盲审按手稿原口径判真伪并在 Stage 2 标明适用性） + 极简确定性启停（含精准销毁探索者与私有伴随的 `abort_node`）」，杜绝踢醒休眠伴随、击穿盲审、双真源冲突以及“按旧题答对却按新题判错”。
3. **沙箱双向第一性边界 + 务实分层隔离**：明确“开放外部公开区（`inputs/`、`source_materials/`、`rulings/`）只读进内部，严防内部向外部逃逸防 Reward Hacking”，`fork_branch`/盲审沙箱按绑定 `spec_revision` 自动挂载只读 `inputs/`，放行 `os.tmpdir()/dsh-spill-*` 并修复 Windows 盘符正则左边界；放弃篡改宿主机 Windows ACL（`icacls /deny`）的不切实际幻想，桌面版采用工作区外 `$PLUGIN_DATA` + 环境变量隔离 + 路径/命令同步 Guard + 空白盲审目录，高安全需求采用可选 Docker / WSL2 容器隔离。
4. **工具面 `31 -> 32`（增 `resolve_works_ticket`）+ 无解查新不造伪卡 + 单条待办项 2 次无客观进展熔断**：工造司补齐 `resolve_works_ticket(ticket_id, resolution, resolution_note)`（队列 `status` 统一置 `RESOLVED`，原因存入 `payload_json`）；采编不加第 33 个工具，通过 `publish_external_literature_card(outcome="UNAVAILABLE_REPORT")` 将无解查新诚实结案为 `CLOSED_UNAVAILABLE` 且绝不插入伪 `[R###]` 文献卡；编排器按单条待办项独立追踪可核验客观进展，连续 2 次无进展即单条挂起熔断（既不误杀分步推进中的工单，也不被其他工单进出掩盖，且不连坐健康项）。
5. **Stage 1 固定统一核查一次 `works_engineer`**：定义为“一次完整的初始仪器核查责任”，控制面经 SQLite 确认全部初始仪器就绪（或空清单正常确认返回）才置 `stage1_works_checked = 1`，中途部分失败恢复仅续做未完成项。
6. **显式模型绑定拒启（`MISSING_MODEL_BINDING`）+ SQLite 单真源防僵尸（先落库 `will_md` 后销毁探索者）+ 防静默吞稿（`ERR_LOCKED`）**：启动前严格按“显式参数 > `callerAgent.options` > 会话事件流 (`model/selection`/`request/context`) > 插件配置”解析权威绑定；探索每轮回查 DB 实时 `node_status` 消灭僵尸，待交接状态唯一落 SQLite `pending_handoff_mode` 消除内存双账本，且 `70%` 必先可靠持久化探索者亲笔 `will_md` 再销毁探索者句柄；`submit_node_handoff` 仅内容一致才幂等跳过，已闭环节点写入不同新内容硬报 `ERR_LOCKED`。
7. **废除“一律零 Mock 巨型 E2E”，升级为三层分层验收**：L1 单元测试 + L2 零费用假模型全链路沙盘（秒级速度目标，按真实组件与数据库结果断言）+ L3 同版本真 DSH（`0.2.2-rc.3`）低预算真 API 冒烟（日常大改跑单子题冒烟，发布级验收跑四类异构闭环）。
8. **`heavy` 异步冻结队列克制原则**：保留既有实现与表结构保向后兼容，文档降格为可选高级特性，常规科研以 `probe` + `official` + 四元复合缓存为主力，不再叠加新复杂度。

同时坚决捍卫四项经实战检验的核心底线一条不动：① **方案 A 单节点挂起/唤醒伴随**；② **防上下文爆炸硬字数约束（`<=2200` / `<=300` / `<100`）与 `support_scope` 5 枚举**；③ **两阶段物理盲审 3 触发器 + `uq_l3_verified_review` + `STAGE3_FINAL_AUDIT:<delivery_id>` 版本绑定终核 + `human_stop_requested_at` 控制面真源**；④ **科学质量准入门槛不放水（不引入本地模拟器直通盲审降级通道）**。
