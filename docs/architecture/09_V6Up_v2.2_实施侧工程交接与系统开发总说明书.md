## 三、DSH (`0.2.2-rc.3`) 独立控制面新插件实施规格（`dsh_plugin/`）

### 3.1 Bundle 规范与零私有包硬依赖

插件置于 `greatwall-v6up/dsh_plugin/`，通过 `plugin_manager(action: "install_bundle", target: "<abs_dir>")` 挂载至 Profile。因外部 `link:` 挂载无法 `import '@deepseek-ai/dsh-*'`，所有宿主能力必须通过 Cordis **`export const inject = [...]`** 注入使用：
- `agents`（`ctx.agents.create`, `ctx.agents.resume`）：拉起、唤醒与 `handle.dispose()` 销毁独立科研会话；
- `tools`（`agentCtx.tools.restrict`, `agentCtx.tools.guard`）：Schema 级工具裁减与调用前实时拦截；
- `systemPrompt`（`agentCtx.systemPrompt.section`）：动态分段注入精简 Push 上下文与看板；
- `tokenMeter`（`ctx.tokenMeter.contextPressure`, `ctx.tokenMeter.measure`）：唯一权威 Token 水位读取器；
- `sessionProjections` / `sessionQuery`：纯函数状态投影与事件流提取（**严禁**往官方 Session Log 写未注册自定义事件）。

```text
greatwall-v6up/dsh_plugin/
├── package.json                  # "type": "module", "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
├── cordis.patch.yml              # 仅注册本插件服务；禁用 {{cwd}} 及 @deprecated 包
├── lib/
│   ├── index.ts                  # Bundle 入口与生命周期注册
│   ├── orchestrator.ts           # External Orchestrator：ctx.agents.create() + Question-Fair 槽位调度(<=10)
│   ├── clock_and_turn_gap.ts     # TokenMeter (500k) 采样 + 回合间隙顺序控制 37% 两轮问答
│   ├── blackbox_projection.ts    # 从 sessionQuery 抽取去思维链的黑匣子轨迹与代码 Diff 摘要 Push
│   ├── read_isolated_sandbox.ts  # 方案 A：OS DACL/低权限隔离外部 DB/藏集/兄弟目录 + realpathSync Guard
│   ├── worktree_and_snapshots.ts # DB 显式 worktree_abs_path 映射 + Retained Candidate 物理快照备份与重置
│   ├── fact_log_middleware.ts    # tools/result 确定性写入 FACT_LOG（传真 session_id/unit_id）
│   └── skillpack.ts              # 复用修正版 SKILL.md 挂载加载器
```

### 3.2 External Orchestrator：`ctx.agents.create()` 无 Root 编排（拍板 1）

不改动原生 `dsh-subagent`，亦不通过 `tool-subagent`（8 并发上限 + 父会话回流）派单。编排器监听 SQLite / 事件状态并拉起单次短无状态会话：
1. **标准拉起与销毁循环**：
   ```ts
   const handle = await ctx.agents.create({
     sessionId: `gw-${epochId}-${role}-${unitId}-${gen}-${shortUuid}`,
     meta: { cwd: unitWorktreeAbsPath }, // library_verifier / supervisory_committee 指向空沙箱占位目录
     agentOptions: {
       provider: config.provider,
       model: config.model,
       reasoningEffort: ROLE_EFFORT_MAP[role] // explorer/surveyor/verifier='high'; companion/works='medium'; logistics/supervisory='low'
     },
     setup: async (agentCtx, agent) => {
       agentCtx.tools.restrict({ allow: ROLE_ALLOWED_TOOLS[role] }); // Schema 级物理裁工具

       });
       if (role === 'explorer') {

       }
     }
   });
   try {
     await handle.agent.followup(startupManifest);

   } finally {
     await handle.dispose(); // 写回 SQLite 即彻底销毁，释放槽位与上下文
   }
   ```
2. **Question-Fair 公平调度器（默认 6，硬上限 $\le 10$）**：读取 `config.json` 中 `max_concurrent_workers`（默认 `6`，强校验 `<= 10`），按子题 `question_id` 活跃节点数公平轮询分配探索槽位；伴随、后勤、图书馆、工造、监察等治理短会话独立触发，互不侵占一线科学槽位。

### 3.3 `TokenMeter` 水位采样与 37% 回合间隙顺序控制流

1. **精确采样（无 $T_{\text{base}}$ 扣减，分母 `500000`）**：
   - 在 `tools/result` / `tools/post-execute` / `agent/pre-step` 读取 `ctx.tokenMeter.contextPressure(agent.session)`；
   - 步间优先取 `pressure.projectedTokens`（已实算表面增量），若 Step 0 为 `undefined` 则调 `ctx.tokenMeter.measure(agent.session).totalTokens`；
   - 计算 `pressure_pct = pressure_tokens / 500000`（`37% = 185,000`、`70% = 350,000`），原子同步至 SQLite `lineage_nodes.pressure_tokens`，彻底消除 JS/Python 双时钟脑裂。
2. **37% 回合间隙顺序控制流（禁止工具内阻塞套娃或异步并发注入）**：
   - **触发条件**：`pressure_pct >= 0.37 && eval_count >= 1 && first_reflection_unlocked == 0`；
   - **串行切换**：`run_isolated_eval` 先正常返回成绩单 $\to$ 控制面在当前 `tools/post-execute` 返回收束提示（或以 DSH `concludesTurn: true` / `agent/turn-stopping` serial hook 拦截）使探索者干净进入 `idle`（`whenIdle()`） $\to$ 控制面从 `sessionQuery` 提取去思维链黑匣子轨迹，并从 `holiday_prompts.yaml` 第 **`1–28` 条中随机抽取 1–2 条候选**推入 **`lineage_companion(REFLECT_37)`** 会话 $\to$ 同步完成 **2 轮 $\le 300$ 字问答**（经 `handle.agent.followup()` 与探索者交互时可临时收窄探索者为只读） $\to$ 伴随助手调 `record_reflection_and_unlock_pull` 当场置位 `first_reflection_unlocked = 1` 并结束 $\to$ 控制面放行探索者继续 `37%–70%` 阶段。
3. **70% / Cost Note / 崩溃交接**：达到 `350,000` Token 或触发 `_cache_advice` 边际成本倒挂时收束探索者并销毁 `handle`，拉起 `lineage_companion(HANDOFF_70)` 扫描工作区 `[Local-Sweep]`、Diff 与 `[Obs###]`，唯一调用 `submit_node_handoff` 写入谱系 DAG 并置 `AWAITING_TRIAGE`（若零实测崩溃则 `is_zero_eval_crash=true` 进 `scratch_log`）。
