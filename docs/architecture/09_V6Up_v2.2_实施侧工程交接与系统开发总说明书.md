## 二、DSH (`0.2.2-rc.3`) 控制面与双隔离沙箱实施规格 (`greatwall-v6up/dsh_plugin/`)

### 2.1 External Orchestrator：`ctx.agents.create()` 无 Root 编排
维持通过 Cordis `inject` 服务（`agents`, `tools`, `systemPrompt`, `tokenMeter`, `sessionProjections`, `sessionQuery`）拉起 7 角色一次性短无状态会话并在 `finally { await handle.dispose(); }` 销毁。**新增触发器与控制流修正**：
1. **`37%` 回合间隙控制流（废除 `eval_count >= 1` 阻塞！）**：仅检查 `pressure_tokens / 500000 >= 0.37 && first_reflection_unlocked == 0`，回合结束即切入 `lineage_companion(REFLECT_37)` 2 轮短问答并当场解锁内藏。
2. **学派聚拢事件实时计算**：每次 `triage_node` 或分支状态变更后，控制面确定性计算每道子题下各 `family_id` 活跃分支数与占比——一旦出现 **`branch_count_in_family >= 2 && (branch_count_in_family / total_active_branches) > 0.50`**，立刻触发 `FAMILY_CONCENTRATION` 事件唤醒 `logistics_coordinator` 执行强制 `orthogonal` 分流（**无任何高产豁免！**）。
3. **无人值守口径歧义红灯机制**：检测到 `ALERT_AMBIGUOUS_SPEC` 写入 `compliance_alerts` 并向桌面 UI/状态推送红灯警告，**事件总线严格维持原已签口径继续派单，绝不挂起或中断无人值守循环**。

## 三、Python 内核与 SQLite DDL 升级规格 (`greatwall-v6up/core_python/`)

### 3.1 数据库 Schema (`db_schema.py`) v3.0 核心升级
沿用外部 `$PLUGIN_DATA/workspaces/<ws_hash>/greatwall.db`、SQLite WAL、`rw_immediate_tx` 与外键约束，执行以下结构对齐：
1. **新增 `parse0_contract` 表**：存人类审签的六项启动表单（`contract_id`, `goal_and_completion_md`, `subquestions_json`, `question_order_json`, `initial_instruments_json`, `seed_families_json`, `total_budget_json`, `min_commitment_window_sec`, `delivery_spec_md`, `human_signed_at`）。
2. **升级 `observations` 表 & 新增 `async_eval_jobs` 表**：
   - `obs_status` 枚举改为完整覆盖三档四态三判：`VALID_PASS` / `MEASURED_REJECTION` / **`VALID_UNDECIDED`** / `CANDIDATE_ERROR` / `INSTRUMENT_ERROR` / `INFRA_ERROR` / `PENDING_REVALIDATION` / `INCOMPATIBLE`；
   - 绑定 **`instrument_id TEXT`**, **`instrument_version INTEGER`**, **`tier TEXT CHECK(tier IN ('official','heavy'))`**, **`tracks_json TEXT`**（彻底兼容无标量多轨道指标！）；`probe` 档仅记 `probe_diagnostic_logs` 表，不污染 `observations`；
   - **`async_eval_jobs` 表**（服务 `heavy` 异步档）：`job_id PK, obs_id, branch_id, status ('QUEUED'|'RUNNING'|'COMPLETED'|'FAILED'), budget_charged INTEGER DEFAULT 0, created_at, updated_at`，支持进程重启后按 `job_id` 幂等续接取回、不重复扣费。
3. **升级 `lineage_nodes` & 新增 `lineage_dead_ends` 表**：
   - `lineage_nodes` 增加 `mechanism_summary TEXT`（`<100` 字）、`evidence_grade TEXT CHECK(evidence_grade IN ('NONE','ARTIFACT_ONLY','MEASURED'))`、`requires_json TEXT`（仅限确定性 `L3-###` / `OBS:<instrument_id>:PASS`）、`premise_revoked INTEGER DEFAULT 0`、`revise_count INTEGER DEFAULT 0`（Stage 1/2 共用）；分支生命周期状态清晰区分 `ACTIVE` / `PENDING_REVIEW`（送审只读冻结）/ `ACTIVE_REVISING`（`REVISE` 返工）/ `SEALED`（终判结案）；移除 `bound_state_version` 与 `local_sweeps_json` 强制要求；
   - **新增 `lineage_dead_ends`（只追加真相表）**：`dead_end_id PK, question_id, branch_id, node_id, category ('SCIENTIFIC_REFUTATION'|'IMPL_FAILURE'|'ENV_FAILURE'), scope_condition_md, failure_mechanism_md, bound_obs_id, created_at`。
4. **升级 `internal_research_ledger` & `review_queue`**：
   - `internal_research_ledger` 增加 `l3_entry_kind TEXT`（`'POS_THEOREM' | 'NEG_COUNTEREXAMPLE' | 'BARRIER_PROOF' | NULL`）、**`goal_coverage TEXT CHECK(goal_coverage IN ('FULL_GOAL','PARTIAL_OR_LEMMA','EQUIVALENT_REDUCTION'))`** 与 `l2_category TEXT`（`'REFUTED' | 'UNRESOLVED_OBJECTION'`）；**彻底屏蔽 `CANDIDATE_ERROR` 修补耗尽入库 `L2`**；
   - `review_queue` 支持三态裁决 `ACCEPT | ACCEPT_NARROWED | REVISE | REFUTED` 及 `revision_requests_json`。
5. **升级 `domain_hooks_by_question` $\to$ `instruments` 表**：
   - 字段：`instrument_id, question_id, instrument_role ('VERDICT'|'PROBE'|'ENV'), instrument_rel_path, instrument_sha256, version INTEGER, calibration_suite_rel_path, health_status ('HEALTHY'|'UNHEALTHY'), consecutive_error_count INTEGER, artifact_schema`；**彻底删去强制 `baseline_rel_path` 与 `< 5.0` 保真硬字段**！
6. **反转 `epistemic_edges` 默认值**：`CLAIM_DECLARED` 边类型默认写入 **`MOTIVATING_REF`**，仅 Stage 2 `edge_type_overrides` 显式升级为 `REQUIRED_PREMISE` 才触发下游重审传播。
