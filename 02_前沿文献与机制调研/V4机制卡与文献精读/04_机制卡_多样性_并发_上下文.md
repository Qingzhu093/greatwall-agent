## 1. 机制卡 1：行为新颖性搜索（Novelty Search）

- **来源**：Lehman & Stanley, *Evolutionary Computation* 19(2):189-223, 2011；§3-4（行为表征与算法）、§5-8（迷宫与双足）、§9.1（局限）、附录 Table 1。
- **证据等级**：**A-实验**（两组独立控制任务，40/50 次重复，与 fitness-based NEAT、随机选择三方对照；但实验域是控制任务，不是代码或研究任务）。
- **它到底怎么运作**：给每个个体算一个行为表征 b(x)——迷宫是机器人仿真结束时的二维坐标，双足是"每秒质心离初始点的平方偏移"级联向量（§8，p.26）。新颖度 ρ(x) 等于 b(x) 到"当前种群 ∪ 历史 archive"中 k 个最近邻的平均距离（k=15，Table 1）。ρ(x) 超过阈值 ρ_min 的行为存入 archive（迷宫初值 6.0、双足 1.0）。选择压力只按 ρ 排序，不读目标分；"是否过关"由另设的判定器检测，与选择解耦（§4）。
- **论文报告的数字**：中等迷宫——新颖性搜索与目标搜索都 100% 成功，但评估次数 18,274 对 56,334（快约 3 倍，p<0.001），网络连接数 24.60 对 66.74；困难欺骗迷宫——新颖性 97.5%（39/40）、35,109 次评估、33.46 连接，目标搜索 7.5%（3/40），随机选择 10%（4/40）；双足 50 次——平均行走 4.04m 对 2.88m（p<0.01），最佳步态 13.7m 对 6.8m，振荡步态 80%，目标搜索"超过 40% 收敛到非振荡步态"，连接数 87.52 对 272.90（p<0.001）。§6.2 档案规模：archive 限到与种群同大小（250）后重跑困难迷宫 40 次，**40/40 全解，平均 38,324 次评估（sd=42,229），与无界 archive 无显著差异**。
- **适用条件与失效边界**：原文 p.14 明说"最适合：目标地形有欺骗性、行为表征直观、环境对可能行为有内在约束"。§6.3 拆掉外墙后，新颖性搜索 100 次只解 5 次，目标搜索 2 次——**两者都不行**。§6.4.3 若用"目标分数"当行为表征，困难迷宫只解 11/40（好于目标搜索的 4/40，但远差于正常表征的 39/40）。
- **它解决的具体失败模式**：目标函数在欺骗性地形上把探索预算吸进死胡同；"垫脚石"因暂时降低目标分被淘汰；为翻墙而膨胀网络结构（bloat）。
- **代价/副作用**：搜索面更宽、评估更多；archive 的 k-NN 计算随规模增长；找到的解"能用但不最优"，需要再用目标优化精修（§9.1 明确建议把 novelty 与 fitness 做成多目标）。
- **对长城 Agent 的启示**：**改造为**"研究路线的新颖性记账"，不能照搬"抛弃目标"。理由有二：原文 §9.1 自己写"若读者推断出 novelty search 比目标搜索更好，我们就失职了"；它反对的是"目标函数能识别垫脚石"这一假定，而不是"目标没有用"。
- **若采纳，最小可验证形式**：固定 3-5 个研究问题，各跑 3 条路线；为每条路线产物算行为向量，比较"按 archive 稀疏度选择续投"与"按当前总分选择续投"两种策略，2 轮后看"新可检验结果数/总动作数"与盲评质量。

## 2. 机制卡 2：Archive（新颖性档案）与 QD/MAP-Elites 的区别

- **来源**：Lehman 2011 §4（archive 机制）、§9.1（多目标准备）；MAP-Elites 本体（Mouret & Clune 2015）**未在本任务材料中读原文**，只用综述二手转述。
- **证据等级**：archive 结构为 **A（原文机制事实）**；与 MAP-Elites 的对照为 **C-二手/框架**，需补读原文。
- **它怎么运作**：Novelty Search 的 archive 是一个**行为坐标集合**，准入只看"这块区域够不够稀疏"，不记录谁是谁的前身，也不保存每区最优。QD/MAP-Elites 把行为空间切成格子，每格只留质量最高的个体；选择压力同时含"每格质量"与"覆盖格数"。一句话：NS 是"只有覆盖、无局部质量"，MAP-Elites 是"每格局部质量 + 全局覆盖"。
- **关于"垫脚石层层嵌套"**：原文没有树结构。archive 是无序点集；"stepping stones" 只是 §9.1 的隐喻（"目标函数的问题在于识别不出垫脚石"），**不保证 A 是 B 的前置，也读不出继承链**。用户草案里的"成果卡有父成果"是另一件东西：那是显式的 DAG/谱系，不是 novelty search 自带的。
- **适用条件与失效边界**：行为维度可枚举、格子边界有意义时才适合 MAP-Elites；维度未定就网格化会把真正的新行为切碎。原文对"行为混淆"的结论（§6.4）是：好的混淆要尊重垫脚石，坏的混淆（按目标分混淆）会直接毁掉搜索。
- **它解决的失败模式**：纯目标搜索的覆盖塌陷；纯新颖性搜索的"只覆盖不精修"。
- **代价**：archive 只增不减会成为垃圾场；格子化带来维度灾难与边界选择成本。
- **启示**：**采纳 archive 作为"覆盖度量"，拒绝把 archive 当"成果继承图"**；用户想要的"层层嵌套"应落在成果卡的 parent/适用条件字段上，并另做续投决策。
- **最小可验证形式**：同一批成果卡，分别用"k-NN 稀疏度"与"每格最优"两种排序选下一动作，比较 2 轮后的覆盖数与质量。

## 3. 机制卡 3：多智能体多样性坍塌（Diversity Collapse）

- **来源**：Chen et al., ACL 2026 Findings, arXiv:2604.18005；§2.2（20 主题×50 会话=1000 份提案/设定，温度 0.7）、§2.3（Vendi 等指标）、§4-§5（结构/规模/拓扑）、附录 I/J/K/L。
- **证据等级**：**A-实验**（多主题、多结构、2×2/2×3 因子、跨模型复现、人类评估校验；但任务仅为"科研提案文本生成"，多样性和质量由 embedding 与 LLM-as-Judge 度量，外推到"代码树/研究执行"是 E）。
- **它怎么运作**：比较五种角色结构（Naive/Leader-Led/Horizontal/Interdisciplinary/Vertical）× 三种拓扑（Standard 全连接顺序发言、NGT 首轮盲写、Subgroups 子群隔离后汇聚）；指标 Vendi Score（有效语义模式数）、结构无序度 1-φ、PCD、词汇独特性、建设性冲突率 R_crit（LLM judge 1-10，≥7 为真批判）。
- **报告的数字**：Horizontal 组 Vendi 8.08，Interdisciplinary 4.65，Leader-Led 4.72；质量区间只有 7.88-8.50（跨学科质量最高 8.50，差异约 0.6/10，远小于多样性 74% 的相对差）；N=3→7 时 Vendi/N 从 1.03 跌到 0.47；提示词层面（身份+语气+交互）只解释 9.2% 方差，结构效应在温度敏感性分析中 η²=0.420（注意：两者不是同一个 ANOVA）；tone 不显著（p=0.172, η²=0.023）；扁平拓扑下 Senior 反而比 Junior 更多样（说明坍塌来自"专家身份+层级权威"的组合）；异构模型混编使跨学科组 +34.0%（p=0.0003, d=2.33）、Leader 组 +14.6%（p=0.071，不显著）；人类专家与 Vendi 排序一致率 87%（1-φ 82%、PCD 81%，Table 1）。NGT 初始多样性最高、Subgroups 在中后期出现"弹性反弹"并维持最高且最稳的 R_crit——**这两项只有趋势图，正文无单一数字**。
- **机制解释（结构耦合 + 阿谀）**：层级权威把下属的语义向量拉向 Leader（sycophancy），全连接拓扑让先发言者成为后续所有人的锚点（信息级联）；2×2 因子实验排除了"语气/身份本身"，把效应归给"专家身份 + 层级权威"的组合（附录 I/K）。
- **适用条件与失效边界**：开放式创意发散；模型对齐越强，结构性干预能突破的"同质化地板"越高（GPT-5.1 上结构干预仍难突破）；单会话内可以"局部扩散"，但跨会话/跨路线仍收缩。
- **它解决的失败模式**：堆 Agent 不增多样性（林格曼效应）；Leader 锚定与阿谀；全连接信息级联过早共识；对齐压缩长尾。
- **代价**：盲写与子群隔离增加协调与汇聚成本；异构模型增加部署成本；指标依赖 embedding/judge。
- **启示**：**采纳**"盲写隔离期 + 子群 + 垂直梯队"，但**改造**为探索阶段的约束，而非终局评审结构；主持在盲写前不得给方向，否则盲写失效。
- **最小可验证形式**：同一模型同一题目，三组（Leader 全连接 / 盲写+子群 / 垂直梯队）各 20 次；指标 Vendi、R_crit、人工盲评 20 对；检验盲写是否提高"非重复成果卡比例"。

## 4. 机制卡 4：长程工具 Agent 的上下文工程（原子对剪枝 + 进度摘要）

- **来源**：Microsoft Research, arXiv:2606.10209；§3.4 Algorithm 1、§4.2-4.6（主实验）、§4.7-4.9（敏感度/泛化）、§5（失败分类）。
- **证据等级**：**A-实验**（50 任务×5 独立运行，多费用类别泛化，跨 GPT-5/Sonnet 4.5；但单一企业 ERP 场景，非研究型任务）。
- **它怎么运作**：最小操作单元不是 token，而是"助手工具调用 + 工具返回"这一对。设历史里工具返回数为 c，需剔除 d=max(0, c-N)；正序扫描、遇到要剔除的工具返回就把它与紧邻的前一条助手调用**成对**移出（保证 API 语法完整）；对刚滑出视界的最近 W 条做**一次**轻量摘要，插在最早被剔除的位置；system 与用户任务始终保留；任务是否完成由独立 harness 从 ERP 数据库回读判定，不看 agent 自述。
- **报告的数字**：50 题完全核销率 C2 全量 71.0% → C3 纯剪枝 79.0% → C4 剪枝+摘要 91.6%；总 token 1,480,996 → 535,274 → 553,374（C4 比 C2 少 62.7%）；耗时 14.56h → 5.39h → 5.79h；失败模式：陈旧状态引用 34→6→4，过早终止 9→18→3（纯剪枝翻倍，加摘要后降 83%），未完成任务总数 73→53→21。参数膝盖点 N=5、W=3；W=5/W=-1 只多 0.4pt 却多 4%-11% token（附录 H，按综述转述，未逐表核对）；跨类别 C2→C4 提升 +19.0 到 +20.6pt；Sonnet 4.5 上 88.0%→92.0%→94.5%，token 降 37.3%（附录 I，按综述转述）。
- **适用条件与失效边界**：需要"高频状态更新 + 冗长结构化工具返回"的企业软件；窗口长度由业务动作步长决定（N=5 恰覆盖约两个记账循环），换域要重新定；摘要只解决"进度感知"，不解决模型能力、科目映射、浮点残差。GPT-5 无用户模型时 8% 的基线是模型停顿行为，不是上下文工程导致的（C1 只作动机）。
- **它解决的失败模式**：context rot、陈旧状态误导、纯剪枝后的"顺行性遗忘"（提前交卷）、输入 token 成本。
- **代价**：每次截断多一次摘要调用（占 token <4%）；窗口过窄会丢大局观；摘要本身可能失真（论文未报告摘要错误率）。
- **启示**：**改造为**"研究 Agent 的工作记忆协议"：上下文只留最近 N 个"动作-观察"对 + 进度锚点；长期证据/成果卡放外部存储，不塞进上下文。用户草案"主持只读摘要不读原始轨迹"方向一致，但必须区分"过程态"（可裁）与"证据"（不可裁）。
- **最小可验证形式**：一个 30+ 步的长程任务，比较全量历史 / 最近 5 对+摘要 / 只保留摘要，指标：完成率、token、引用过时结果的错误数。

## 5. 机制卡 5：推理期两级并行（TIPEX）

- **来源**：Xu et al., ICML 2026, arXiv:2608.05791；§3（框架）、§4.2-4.5（主实验/消融/失败分析）、Table 1/2/3、附录 A.1/A.2。
- **证据等级**：**A-实验**（GAIA L1-L3，Magentic-One 基线，分层重复，GAIA2-mini + DeepSeek-v3.2 泛化；单基准、任务非科研型）。
- **它怎么运作**：Tier-1 副本并行——n 个独立副本（RIG 同 prompt 随机采样；OHG 由元规划器合成方法论正交的 n 套策略），执行完由 Judge 按"答案确定性/证据强度/逻辑一致性"三维各 0-2 分打分；编排有 GS（等全部）、FVES（首个有效即停）、TKS（等 k=ceil(n/2) 个有效候选再评分）。Tier-2 结构并行——单条轨迹内动态 DAG，算因果就绪前沿，按 SS/BP/AP 三种粒度派发；硬依赖失败熔断该链，独立分支继续。
- **报告的数字**：L1 准确率 43.2%→56.5%（OHG+TKS，Oracle 60.9），L2 25.8%→38.7%（OHG+GS，Oracle 48.4），L3 9.2%→11.5%；时延多数配置降 15%-40%（L2 320s→261.5s；L3 772s→268.4s）；token 普遍增 50%-150%；OHG 生成策略的平均余弦距离 0.294-0.322，RIG 仅 0.005-0.010；Judge 开销仅占总时延 4.29%-5.07%、总 token 3.90%-4.56%；但实际准确率与 Oracle 始终差 5-15pt。副本数 n=1→3 稳定增益，3→5 边际甚至负；BP→AP 使 L2 准确率 37%→25%、token 99k→124k；任务类型分化：代码任务结构并行 32.28% 高于联合 28.20%，Web/文件任务联合最好，多模态依赖副本；104 个失败里 64 个是推理/计算错误、24 个检索、11 个早期错误级联、5 个冗余执行。
- **适用条件与失效边界**：中等难度任务收益最大（L2）；极难任务受底座能力上限限制；Judge 质量决定 Oracle 优势能否兑现；拆得过细（AP）会因上下文割裂而负优化。
- **它解决的失败模式**：串行关键路径过长；单路径偶发失误；多方案无法及时比选。
- **代价**：token 增 50%-150%；调度与 Judge 复杂度；错误路线上的"高速并发"会放大损失（需前置 Plan Verifier）。
- **启示**：**采纳**两条：副本并行只买"覆盖率/鲁棒性"，结构并行只买"时延"；**多路线并行不是提高上限的手段**（与机制卡 7 命题 5 一致）。
- **最小可验证形式**：同一研究问题 n=1 与 n=3 独立路线，同一评估器；记录 Oracle 命中率、实际选中率、token 与时延，量化 Judge 鸿沟。

## 6. 机制卡 6：共享状态并发控制（陈旧读 / 丢失更新）

- **来源**：Yang et al., ICML 2026 Position, arXiv:2608.18092；§1-§3、Table 1/2、§4。
- **证据等级**：**C-框架/立场**。该文无自做实验；表 1/2 的数字是转引 CAID、CodeR、Silo-Bench、MAST、MegaAgent、SagaLLM，我在其表内核对到，但未核原始论文，不能当 A 级。
- **它怎么运作**：把 MAS 失效重述为经典并发异常：陈旧读（读时状态后被改）、丢失更新（后写覆盖前写）、陈旧更正（修正在执行后才到）、动作-消息脱节。根因是**时间不对称**：LLM 一次推理秒到分钟，工具读写毫秒，思考窗口内共享状态可能被改多次。设计空间：隔离级别（RC/RR/SI/Serializable）、悲观锁 vs 乐观验证、MVCC（读不阻塞写）、事务粒度（单动作 vs 子任务）、显式/隐式事务边界、锁粒度（文件 vs 函数/AST）；基础设施：worktree 隔离 + 合并期语义校验（测试/AST/类型）、KV-cache 检查点回滚；模型侧：并发感知基准、SFT/MARL、prompt 要求"写前刷新"、把子任务映射到正交资源。
- **论文转引的数字（C 级）**：MAS 失效率 41%-86.7%；CAID 隔离后 63.3% vs 无隔离 55.5%（单 agent 57.2%）；CodeR 有任务图 22% vs 无 10%；Silo-Bench 67.1% 失败归因并发冲突、高争用下 RCC 达 100%；过早提交占 37.2%、共识崩溃 29.9%、MAST 失配 36.9%；MegaAgent 并行调度 4505s→800s。
- **适用条件与失效边界**：多个 agent 读写同一共享可变状态时成立；原文明确 scope 限定——输入不相交的系统风险低。悲观锁会把长推理期变成串行；乐观回滚会烧掉分钟级推理的 token，可能活锁。
- **它解决的失败模式**：把并发 bug 误诊为"沟通/对齐不好"；多 Agent 写同一代码树/黑板/邮箱的静默覆盖。
- **代价**：隔离与校验的工程复杂度；锁粒度与推理时长的张力；数据库理论不能直接照搬（原文自己反驳"传统事务直接拿来用"）。
- **启示**：**采纳**"工作区物理隔离 + 读快照绑版本指纹 + 合并期语义校验 + 正交资源分解 + 比较前同步屏障"；**拒绝**"让 Agent 自己用自然语言协商锁"。
- **最小可验证形式**：两 agent 并发改同一成果库/同一文件，比较无隔离 / worktree+合并校验 / 版本指纹+冲突中断三组，指标：冲突率、作废 token、任务成功率。

## 7. 机制卡 7：自我改进的平台期（可达集二分）

- **来源**：Bobadilla-Suarez et al., arXiv:2609.34924；§3（定理 2、命题 3、推论 4）、§4（命题 5/6/7/19）、§5（Part B/C）、§7-§8。
- **证据等级**：**A（定理为数学证明；Part B 为 SWE-bench Lite 受控实验）**；Part C 生产数据为观察性，作者自己限定"支持描述、不支持机制"，所以机制归因只能算 **B**。
- **它怎么运作**：把"生成-批评-打补丁"每轮看作一个弱学习器。若"下一轮可能提出的补丁集合"（可达集 H_t）固定、质量函数 V 有界，则每轮改进量 η_t→0（定理 2）；若可达集持续扩张且每轮都有真实优势，才能突破任意上限（命题 3(ii)）。冻结权重只保证"最终有天花板"，不保证过程平稳（推论 4）。推论：best-of-k 的天花板恰好等于最强 worker 的天花板（命题 5，"宽度买速率不买预算"）；多数投票零错当且仅当每个任务的失败者数 m*<k/2（命题 6）；反复复用固定专家池的有效轮数上界 log(1/ε0)/(2γ²)（命题 7）；复用过的 worker 下一轮优势恰好归零（命题 19）。
- **报告的数字**：Part B 55 题×5 seed×4 轮=1650 条轨迹；30 个同族 worker 上 m*=30=k、23/55（42%）的题所有 worker 全错；模型档位解释约 49.7% 方差（partial η²=0.497），Haiku 44-49% vs Sonnet 85-89%；反馈模式无显著差异（p=0.61，但功效不足，需 7-9 倍样本）；80%-95% 的轮间转移是"完全没动代码"的平手（剔除填充后 Sonnet 13-21%、Haiku 52-59%），改坏 ≤2.9%；每轮改进量 Haiku 0.097→0.036→0.033，Sonnet 0.156→0.068→0.029。Part C 401 个真实会话、1211 commit、23 仓库：churn 几何衰减 ρ≈0.77；前 AI 时代 9395 个人类会话 ρ=0.86，形状相同——所以不能把衰减归因于 AI；Opus/Sonnet 存活率均 0.55，不可区分。
- **适用条件与失效边界**：冻结权重的 agentic coding；"可达集"是建模假设（M1/M2），未被经验测量；定理不建模"接受劣解"的退火；判据单向（宁可误报）。
- **它解决的失败模式**：局部最优平台期被误当作"再跑几轮就好"；多采样/多 Agent 被误当作"提高上限"；固定专家池被反复咨询。
- **代价/副作用**：真正扩张可达集需要新工具/新验证器/新问题分解，成本高；而且"扩求解能力"与"扩自评权力"是同一条管道，容易奖励黑客。
- **启示**：**改造**用户的核心假设：多路线并行 + 成果继承，如果不改变"能做到什么"，只买速度、不买上限；"成果发展额度"方向正确，但每个动作必须能指出"新增了什么工具/验证器/问题分解"。
- **最小可验证形式**：A 组只做多路线采样+继承；B 组额外给每路线新工具/新验证器；测每轮 η_t、平手率、平台出现轮数、最终质量；预注册"η_t 连续两轮低于阈值就改脚手架"。

## 8. 迁移到"长城 Agent"的设计推断 [E-推断]

### 8.1 代码树/研究路线的"行为维度"怎么定义
- **不能用的**：代码文本 diff、行数、prompt 措辞、成果卡字数。§6.4.3 已经证明"用目标分当行为表征"会让困难迷宫只解 11/40。
- **代码树可用维度（建议 4 个）**：(1) 固定测试套件的通过/失败向量；(2) 失败模式类别（编译/类型/超时/断言/性能）；(3) 结构统计（调用图规模、依赖数、圈复杂度）；(4) 运行轨迹中的中间断言结果。新颖性=这些向量在"archive ∪ 当前种群"中的 k-NN 稀疏度。
- **研究路线可用维度（建议 3 个）**：(1) 结论的适用条件集合（在哪些输入/预算/数据上成立）；(2) 可复现实验协议与已验证的探针结果；(3) 可迁移的工具/引理/反例。新颖性=在"条件-证据"空间中的稀疏度，不是"观点听起来不同"。
- **反廉价新颖性闸门**：任何只改变表述、不改变"条件-证据"向量的成果卡，不入选 archive；这与 §6.3 的"无约束空间里廉价新颖性会拖垮搜索"直接对应。

### 8.2 非冠军成果的续投
archive 只负责"覆盖"，续投要另设门：下一动作必须能产出**可检验的新内容**（新探针、新反例、新工具、新适用条件），而不是"再讲一次潜力"。这正好接上用户草案 §5 的"成果发展额度"，但要用"新行为/新可检验内容"验收，防止"临时新颖性"变成永久补贴。

### 8.3 多 Agent 并发写同一状态
把"成果库/前沿"当共享可变状态处理：每条路线独立目录（worktree）；成果卡一卡一文件、只追加不改写、带版本指纹；只有主持写"前沿索引"这一个共享文件；比较前先冻结版本（同步屏障）；合并时跑语义校验（测试/脚本/类型），不只看 diff。对应机制卡 6 的 C 级建议 + 用户草案 §10 的 Shared-Nothing。

### 8.4 上下文
把"最近 N 个动作-观察对 + 进度锚点摘要"作为会话层协议；证据卡与原始日志在外部存储，按需检索，不进上下文。注意：研究轨迹不是 ERP 表单，"旧推导"往往仍是有效证据，不能像剔除旧表单快照那样剔除它。

## 9. 本节最可靠的 3 条结论

1. **Novelty Search 在欺骗性控制任务上有强实验证据（困难迷宫 97.5% vs 7.5%，双足 4.04m vs 2.88m），但它不是"目标函数无用论"**：原文 §9.1 自述不该被读成"novelty 更好"，并建议用目标优化精修新颖性找到的解。[A-实验]
2. **多样性坍塌主要是结构问题，不是提示词问题**：交互结构（拓扑+权威+同构模型）比身份/语气解释更多方差；盲写、子群、垂直梯队是少数有实验支持的结构干预（Vendi 8.08 vs 4.65；异构模型 +34.0%，p=0.0003）。[A-实验，限科研提案生成]
3. **长程工具型 Agent 的首要问题是"上下文卫生"而不是"记忆容量"**：保留最近 N 对工具交互 + 对滑出窗口做一次摘要，在 50 题企业任务上把完成率 71.0%→91.6%、token 降 62.7%，且纯剪枝会让"过早终止"从 9 次翻到 18 次、加摘要后压到 3 次。[A-实验，单领域]

## 10. 本节最不确定的 3 个判断

1. **这些机制能否迁移到"代码树/研究路线"**：七篇论文没有一篇在代码树或科研成果上定义过"行为新颖性"；8.1 的维度是我的推断，评价器也不存在。迁移结论只能标 E，必须先做小规模对照。[E]
2. **Diversity Collapse 的外部效度**：20 个主题的科研提案、Vendi/LLM-as-Judge 度量、人类一致率 87%（不是 100%）；"语义多样"不等于"科学价值高"，NGT/Subgroups 的关键效应只有趋势图没有单一数字。把它当"A 级结论"用于所有 MAS 是过度外推。[A/B]
3. **"多路线并行只买速度不买上限"**：定理本身强，但"可达集"是建模假设，Part C 作者自己只说"描述成立、机制未定"；在研究系统中，"新工具/新文献"可能持续扩张可达集，使该结论失效或变弱。[A 定理 / E 外推]

## 11. 与用户已有设计可能冲突的点

1. **60% 目标推进 / 25% 成果发展 / 15% 组合的固定比例**：Novelty Search 的证据是"在欺骗性地形上，把多数预算给目标推进会被吸进死胡同"；比例应由平台期信号（η_t、平手率）动态触发，而不是固定。[冲突中→改造]
2. **核心假设"成果继承+跨谱系组合 → 长期收益"**：LocalOptima 命题 5/7 说，若继承不扩张可达集，多路线/best-of-k 只买速度；固定池有可计算的地平线。冲突等级**高**，建议给"成果发展"动作加硬验收：必须新增工具/验证器/问题分解，否则只算重采样。[冲突高→改造]
3. **"多路线并行"的收益预期**：TIPEX 显示 n=3→5 边际递减、AP 负优化、Judge 是瓶颈（Oracle gap 5-15pt）。若用户期待并行提高成果上限，证据不支持；它降方差、提覆盖率、压时延。[冲突高→降低预期]
4. **"同一基础模型承担多职能"**：Diversity Collapse 的 +34% 来自跨家族异构模型；同构模型换 persona 的多样性增益有限。冲突中，至少让红队/评审用不同家族模型，或明确接受多样性上限。[冲突中→改造]
5. **"主持只读摘要、不读原始轨迹"**：方向对，但微软的"成对剔除"只适用于"过时状态会致错"的工具型任务；研究证据不是表单快照，不能按同一规则裁掉。需区分"过程态"与"证据"。[冲突中→细化]
6. **垂直梯队/盲写/争论**：论文支持"盲写+子群+垂直"，但 Leader-Led 是坍塌最严重的结构之一；"主持"在盲写前给方向会毁掉盲写。用户草案已写"独立初稿前不提供其他路线结论"，需再加"主持也不发言"的硬约束。[冲突低-中]
7. **异步执行 + 共享前沿**：异步会扩大"读-写"时间窗（陈旧读/丢失更新）；用户草案的 Shared-Nothing 是对的方向，但"前沿索引"仍是单点共享写，需要版本指纹与同步屏障。[冲突中→补协议]
8. **"潜力分容易成为短视奖励"（草案 §6）**：LocalOptima 完全支持这一点；但"续投看新产物"需要可操作定义，否则会退化成"谁讲得动听谁拿额度"。[一致→补验收标准]
9. **"暂存/归档"**：草案说"停止不等于无价值"，与 NS archive 一致；但无准入阈值与去重的归档会变成垃圾场，反而稀释检索。[冲突低→补阈值]

## 13. 建议的最小验证清单（可按预算挑）

1. **方差 vs 结构**：同一模型，Leader-Led 全连接 vs 盲写+子群，20 次×20 主题，测 Vendi 与 R_crit。（低预算，验证 A 卡是否在你的场景复现）
2. **并行买什么**：n=1 vs n=3 独立路线，配同一评估器，测 Oracle 命中率/实选率/token。（中预算，验证"宽度买速率"）
3. **继承是否扩张可达集**：A 组继承成果卡，B 组继承+新验证器/新工具，测 η_t 曲线与平台轮数。（高预算，最关键）
4. **上下文协议**：30+ 步长任务，全量 vs 最近 5 对+摘要 vs 仅摘要，测完成率/作废 token/旧证据误用。（中预算）
5. **并发写**：两 agent 并改同一成果库，无隔离 vs worktree+语义校验 vs 版本指纹+冲突中断。（低预算，风险最高优先做）
