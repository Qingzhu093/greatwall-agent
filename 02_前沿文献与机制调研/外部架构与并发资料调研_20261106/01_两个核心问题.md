# 两个核心问题的文献地图

## 一、有效信息、语义对齐与避免平庸启动

“语义对齐”在这里至少有三个含义：任务接收者是否理解了相同目标和约束；不同路线的结论是否在同样条件下可比较；交流之后是否把独立思路压成同一种观点。前两个需要共同含义，第三个需要保留差异。向量相似度或统一 JSON 字段本身不能证明这三件事做到了。

### 1. 信息如何变成后续可用知识

**ACE — Agentic Context Engineering（2025，2026 修订）**

[原文](https://arxiv.org/abs/2510.04618)。本轮核对摘要和版本，前轮阅读相关正文。

研究把上下文作为会演化的策略手册，通过生成、反思与整理积累经验，关注反复重写造成细节丢失的问题。与“把历史压缩成越来越短的摘要”有直接对照价值。

阅读时重点：哪些经验来自环境反馈，哪些来自模型解释；新增内容怎样合并或删除；测试时学习与跨任务知识迁移如何区分。它没有直接证明能把不同科研分支的术语、假设和证明条件自动对齐。

**Manus 的 Context Engineering 经验（2025-07-18）**

[作者原文](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)。已查原文内容。

值得读文件系统记忆、保留错误信息、稳定前缀与缓存、避免模式模仿几个部分。其重点是实际 Agent 的上下文组织及运行成本，属于团队经验，不是证明某种记忆结构最优的消融论文。这里按国内创业团队起源收录，避免把历史归属当作当前所有权。

**OpenAI Harness Engineering（2026-02-11）**

[官方原文](https://openai.com/index/harness-engineering/)。核对正文。

把仓库知识变成 Agent 可访问的依据，强调环境和文档的可读性。它适合研究“哪些知识真正进入 Agent 的工作过程”；案例目标是软件交付，不能直接推出科研探索应采用相同约束。团队对效率的估计不等于随机对照结果。

### 2. 任务书怎样传递意图

**Anthropic 多 Agent Research（2025-06-13）**

[官方原文](https://www.anthropic.com/engineering/multi-agent-research-system)。已查正文。

重点读委派提示、任务边界、工具使用指导和输出要求。其主控将检索分解给子 Agent；这是较直接的任务派发经验。这里的 Research 主要是搜索与综合信息，不能把效果直接搬到长程数学证明或实验研究。

**Intelligent AI Delegation（2026）**

[原文](https://arxiv.org/abs/2602.11865)。摘要与元数据已核对。

讨论委派中的意图、责任、能力与边界，适合给“任务书遗漏了什么”建立概念框架。应按框架提案阅读，不能据此认定整套委派机制已经在长程科研里获得实证支持，也不必把它的治理内容全装进系统。

**Why Do Multi-Agent LLM Systems Fail?（2025）**

[原文](https://arxiv.org/abs/2503.13657)。摘要和原始页面已核对。

把失败区分为规格/系统设计、Agent 间不一致、验证和终止等类。它能帮助辨认“任务根本没对齐”和“研究路线本来不同”。失败分类不等于改进方案，更不能把每个分类都变成一个常驻裁判。

### 3. 如何避免平庸启动

**MLE-STAR（2025）**

[论文](https://arxiv.org/abs/2506.15692) · [Google 作者说明](https://research.google/blog/mle-star-a-state-of-the-art-machine-learning-engineering-agents/)。核对作者页和论文索引。

它把检索相关方法和有针对性的改进放进 ML 工程过程，是“先获得有效领域信息，再动手”的直接材料。重点看检索带来的收益与后续精炼的收益是否分开测量。任务是 ML 工程，不能推出对所有问题预注入同一种算法骨架都有效。

**Co-Scientist**

[论文](https://arxiv.org/abs/2502.18864)。初版题名 Towards an AI co-scientist；2026 修订题名 Accelerating scientific discovery with Co-Scientist。本轮核对最新摘要及官方介绍。

从研究目标与已有科学证据生成、批评、改进假设。适合查看起点材料如何进入生成阶段、候选怎样比较。模型内部排序和真正实验验证要分开看，不能把“胜出假设”视为已成立科学结论。

**需要继续核对的空白**：目前这些材料分别支持上下文积累、委派与检索增强，但本轮没有找到一项足以统一回答“语义对齐且不损失多样性，并长期避免平庸启动”的决定性实验。可以沿 task grounding、common ground、belief alignment、information provenance、research proposal diversity 继续查，而非只查 context compression。

## 二、激励什么，才可能扩大搜索空间

先区分“激励”的作用位置：训练奖励更新模型参数；推理期选择决定保留哪个候选、下一笔预算给谁；提示词里的鼓励改变生成条件。三者机制与成本不同。Self-Rewarding Language Models 属于训练研究，不能等同于给现成 Agent 加一句“大胆创新”。

你说的“行为吸引式／近源搜索”目前不强行定名。如果指寻找不同的行为，对应 novelty search；如果指在已有结果周围提出可做的新问题，对应 curriculum、conjecturing、local variation；如果指寻找人觉得有趣的方向，OMNI 更直接。下面按这些不同含义排列。

| 研究线 | 选择或激励的对象 | 核心来源 | 关键边界 |
|---|---|---|---|
| 行为新颖性 | 与历史行为不同 | [Lehman & Stanley 2011](https://doi.org/10.1162/EVCO_a_00025) | 什么算行为、距离怎么算很关键；文本措辞新颖不等于机制新颖 |
| Quality Diversity | 各行为区域内的好解 | [MAP-Elites 2015](https://arxiv.org/abs/1504.04909) | 行为坐标通常由人定义，坐标会限定探索视野 |
| 学习进展 | 正在变得可掌握的任务 | [Oudeyer 等 2007](https://www.pyoudeyer.com/ims.pdf) | 需要测量学习变化；持续随机噪声不等于学习进展 |
| 问题和解共同演化 | 新环境及其解，并跨环境迁移 | [POET 2019](https://arxiv.org/abs/1901.01753) | 主要证据来自模拟控制环境，科研问题生成未必有同样清晰的难度判断 |
| 人类兴趣模型 | 有趣且值得学习的任务 | [OMNI 2023/2024](https://arxiv.org/abs/2306.01711) | 很贴近“学术 taste”，但模型觉得有趣不等于科学原创或重要 |
| 邻近猜想与课程 | 当前证明者勉强能证明的问题 | [STP 2025](https://arxiv.org/abs/2502.00212) | 同时训练猜想者与证明者，不能直接搬其收益到固定模型编排 |
| 技能积累 | 新任务与可复用程序技能 | [Voyager 2023](https://arxiv.org/abs/2305.16291) | Minecraft 有明确环境反馈，迁移到科研的证据仍需另看 |
| 程序演化 | 能被外部评估的程序变体 | [FunSearch 2023](https://www.nature.com/articles/s41586-023-06924-6)、[AlphaEvolve 2025](https://arxiv.org/abs/2506.13131) | 需要有效评价器，并非完全无目标探索 |
| Agent 自我改进 | Agent 自身的代码与历史候选 | [DGM 2025](https://arxiv.org/abs/2505.22954)、[ADAS 2024](https://arxiv.org/abs/2408.08435) | 改进对象是 Agent，不等同于解决某项科学任务 |

上述表是机制索引。本轮新检索的学习进展、Voyager、ADAS 仅到摘要/原始索引层级；POET 与 OMNI 核对原始摘要，尚未完成全文和消融分析。

### 几个不能混在一起的评价概念

- 新颖性：与以前不同；依赖比较集合和表示。
- 惊奇：与预测不一致；可能来自噪声或模型无知。
- 信息增益：减少特定不确定性；必须说明减少的是谁对什么的不确定性。
- 学习进展：某种能力或预测随经验改善；需要时间上的比较。
- 有趣程度：符合人或模型的价值判断；依赖偏好与领域知识。
- 可迁移性：对另一问题确实有用；往往事后才能确认。

因此“鼓励探索”还不是完整的研究命题。读论文时应检查它到底量化哪一项、通过什么选择机制起作用、是否真正影响后续资源，以及最后怎样评价贡献。这里暂不合成奖励函数，也不指定权重。

### 跟你提到的数学案例更接近的材料

[Mathematical exploration and discovery at scale](https://arxiv.org/abs/2511.02864)，Georgiev、Gómez-Serrano、Tao、Wagner，2025，摘要已核对。覆盖 67 个数学问题，结合程序搜索、构造与进一步证明工具。它与 STP 分别代表“探索数学构造”和“自生成猜想训练证明者”，值得对照，不能统称为同一种无目标搜索。

OpenAI 数学多 Agent 案例的[官方过程说明](https://openai.com/index/navier-stokes-solution/)提到相关问题成果和跨组启发；这是组织过程自述，不是新颖性奖励的消融证据。单凭成功故事无法识别贡献来自模型、算力、题目选择还是交互机制。

## 可按兴趣选择的阅读路线

- 想先看任务起点：MLE-STAR → Anthropic Research → ACE → Delegation。
- 想先看探索激励：Novelty Search → MAP-Elites → 学习进展 → POET → OMNI。
- 想先看真正科研：Co-Scientist → 数学探索论文 → AI Scientist-v2 → 独立复评。
- 想看新问题如何自己长出来：STP → Voyager → POET → OMNI。

这些顺序是资料导航，不代表推荐你选定某条研究路线。
