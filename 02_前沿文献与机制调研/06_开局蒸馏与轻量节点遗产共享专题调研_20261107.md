## 专题一：开局蒸馏（Opening Distillation / SOTA Grounding）的前沿方案（2025–2026）

### 1. 2025–2026 主流 Agent 是如何做“开局检索与知识蒸馏”的？

各大前沿框架已经彻底抛弃了“只靠 Prompt 催眠大模型用新方法”或“简单搜几段网页塞进上下文”的粗糙做法，演化出了五种有代表性的开局蒸馏范式：

| 代表系统 / 论文 | 开局检索与蒸馏的核心机制（人话拆解） | 解决了什么痛点？ | 局限与教训 |
| :--- | :--- | :--- | :--- |
| **1. Google MLE-STAR**<br>(`arXiv:2506.15692`) | **模型卡检索 + 沙箱实跑验分 + 贪心合并**：<br>$\mathcal{A}_{\text{retriever}}$ 联网搜 $M=4$ 组 `{模型名称, 可运行示例代码}` JSON 卡 $\to$ 为每张卡单独生成端到端脚本在本地验证集实跑打分 $h(s_i)$ $\to$ 按得分从高到低贪心融合（指标不涨立刻停），铸造强起点 $s_0$。 | 打破 LLM 动辄掏出 `LogisticRegression` 或 2015 年 `ResNet` 的**预训练熟悉度偏见（Familiarity Bias）**，获奖率从 26% 提至 63.6%。 | 只搜单模型/单脚本，没蒸馏领域特征工程规律与防坑红线；且 4 个候选全跑一遍训练开销不小。 |
| **2. Microsoft RD-Agent (Q)**<br>(`arXiv:2505.15155` / GitHub) | **假设驱动 DAG + 演化三元组库（`Task-Code-Feedback`）+ 相关性去重**：<br>开局先读研报/论文抽取出“可检验假设”与公式，交给 `Co-STEER` 编码实现；最硬核的是**入库门禁**——计算新因子与现有 SOTA 库因子的相关性，相关性 $>0.99$ 直接作为冗余淘汰，最终用少 70% 的特征拿到 2 倍年化收益。 | 防止智能体换个变量名“重复发明已有特征”，把文献公式直接锚定为可回测的代码算子。 | 强依赖标准化的领域回测接口（如 Qlib）。 |
| **3. AutoKaggle & DS-Agent**<br>(`arXiv:2410.20424` / `2402.17453`) | **受控工具箱（Curated Toolkit）+ 案例推理（CBR）**：<br>`AutoKaggle` 不让 Agent 从零手搓数据清洗和特征工程，而是预置一套**经过单元测试认证的标准机器学习工具库（Verified Toolkit）**，规定基础操作必须调库；`DS-Agent` 则将 Kaggle 金牌方案提炼成结构化案例卡，开局做相似任务检索与适配。 | 极大降低从零写底层处理代码的语法崩溃率与隐性 Bug。 | 人工维护案例库成本高；若工具箱卡死太严，会限制核心算法微创新。 |
| **4. Paper2Code (PaperCoder) & InternAgent**<br>(ICLR 2026 / `2505.16938`) | **论文转蓝图（Planning $\to$ Analysis $\to$ Generation）与基线增强**：<br>不让模型对着空目录（From-Scratch）瞎写，而是先把顶会论文拆解成**架构规划图、文件依赖树与接口规范（Blueprint）**，或者在现有开源 Baseline 仓库上做迭代增强（Baseline Enhancement）。 | 克服“符号—现实鸿沟（Symbol-Reality Gap）”，避免模型看懂了论文公式却写出跑不通的幻觉 API。 | 针对单篇论文复现强，多路线融合时缺少冲突消解。 |
| **5. Google Co-Scientist & Anthropic Research**<br>(Nature 2026 / `2502.18864v2`) | **先广后深（Broad-to-Narrow）+ 独立检索查新消融**：<br>Anthropic 强制子 Agent 先用极短宽泛词摸清全景，再逐层下潜，并将脏网页隔离在子 Agent 上下文内，只向主控交付蒸馏后的工件文件；Co-Scientist 的 `Reflection Agent` 专门用独立检索给假设打新颖性分（无检索时把旧想法打 `6.14/10`，有检索直接打回原形 `2.38/10`）。 | 防止主控上下文被万字网页污染，防止模型把几十年前的旧想法当成惊天大创新。 | 若缺乏“陈旧性（Staleness）对比基准”，仍可能被 SEO 内容农场误导。 |

### 2. 如何将杂乱网页/论文/代码“蒸馏”成不污染上下文、又能管住“调库 vs 造轮子”的结构化产物？

2026 年 9 月的最新实证论文 **《Do Coding Agents Reuse Existing Code or Reinvent the Wheel?》(`RepoReuse`, arXiv 2026.09)** 揭示了一个触目惊心的真相：在连续迭代到第 5 轮时，**高达 50.8% 的任务链出现了重复造轮子（明明工作区或现成库里有现成函数，Agent 却视而不见自己从头重写一套）**，且功能测试通过率完全掩盖了代码腐败！同时，**《Agentic Context Engineering (ACE)》(`arXiv:2510.04618`)** 证明：把经验写成结构化、增量更新的 **Playbook（作战手册）**，远胜于传统 RAG 切片或全量重写摘要。

结合这两项前沿成果，长城 Agent V4 的开局蒸馏绝不能产出长篇大论的“文献综述散文”，而应当由开局调研子智能体（在各自隔离上下文里消化几十篇网页/论文后）向 `shared_readonly/distilled/` 交付**三份高密度、强约束的结构化蒸馏产物（总计控制在 1,500 Tokens 以内）**：

#### 产物一：《领域方法族与 SOTA 锚点表 (`sota_anchors.yaml`)》——打破预训练偏见
强制做**“年代与淘汰链检查（Staleness Check）”**，明确告诉探索节点什么已经过时、什么才是当下的起跑线：
```yaml
task_modality: "3D Point Cloud & Tabular Hybrid Regression"
obsolete_blacklist: # 【预训练偏见黑名单：严禁作为主干刷分】
  - model: "Vanilla ResNet-18 / LogisticRegression / 裸写浅层 MLP"
    reason: "在同类基准上比 2024-2026 SOTA 低 15%+，除非作为 5 行代码的极速冒烟测试，严禁在此方向浪费步数深挖"
sota_families: # 【开局强制对标的 3~4 个正交方法族】
  - family_id: "FAM-01"
    name: "Gradient Boosted Trees + 几何不变特征提取"
    modern_sota_anchor: "CatBoost / LightGBM + 二面角/径向分布函数 (RDF) 特征"
    minimal_executable_snippet: "shared_readonly/distilled/snippets/catboost_rdf_baseline.py"
    reported_metric_range: "RMSLE 0.052 ~ 0.056 (Nomad2018 基准)"
```

#### 产物二：《调库 vs 造轮子边界契约 (`build_vs_buy_contract.yaml`)》——根治 50.8% 重复造轮子
把代码划分为**“严禁手搓层（Frozen Infrastructure）”**与**“鼓励造轮子层（Core Innovation Zone）”**，配合 AST 扫描强制执行：
```yaml
must_reuse_libraries: # 【严禁重复造轮子层：必须直接调标准库或 shared_readonly/ledger/primitives】
  - scope: "数据切分、交叉验证、标准评估指标计算、基础图最短路/凸包/KD-Tree"
    enforced_imports: ["sklearn.model_selection.StratifiedKFold", "scipy.spatial.cKDTree", "networkx"]
    prohibition: "严禁手写 k-fold 切分逻辑（极易引发数据泄漏）或手写 O(N^2) 暴力最近邻搜索！"
allowed_from_scratch_zone: # 【核心造轮子授权区：允许并鼓励自己写核心算子】
  - scope: "任务特定的代价函数、非对称邻域搜索算子、领域物理约束惩罚项、异构模型条件概率融合器"
    interface_signature: "def custom_transition_kernel(state: np.ndarray, params: dict) -> np.ndarray"
```

#### 产物三：《防踩坑与反作弊红线卡 (`pitfall_guardrails.md`)》——把前人血泪凝成 10 条铁律
继承 `MLE-STAR` 双哨兵（防泄漏 $\mathcal{A}_{\text{leakage}}$、防漏数据源 $\mathcal{A}_{\text{data}}$）与 `ACE` Playbook 机制：
- **数据源完整性清点**：开局自动扫描输入目录所有文件后缀（如发现除 `train.csv` 外还有 `geometry.xyz` 或 `.parquet`），在卡片第一行高亮：**“必须读取并融合 `geometry.xyz`，只读 CSV 的方案直接判残缺！”**
- **领域高频暗坑预警**：如“本赛题存在按 `group_id` 聚集的时间序列效应，严禁使用随机 K-Fold，必须使用 `GroupKFold`，否则本地 CV 虚高 0.05、线上必崩！”

### 3. 如何校准大模型的“科研品味（Taste）”并防止“把教科书常识当创新”？

针对《Evaluating Sakana's AI Scientist》(`arXiv:2502.14297`) 揭露的**“Semantic Scholar 浅层关键词搜不到同名标题，就把 2018 年的微批处理 SGD、自适应学习率、e-fold 交叉验证全部判为 Novel（12/12 假阳性）”**以及《Station》(`arXiv:2610.08927`) 暴露的**“75% 自发提案被人类原作者打 1~2 分（专挑好写代码的边角料刷分，即路灯效应）”**，开局蒸馏阶段必须额外蒸馏出**三件“品味校准器（Taste Calibrators）”**：

1. **《教科书常识与换皮黑名单 (`Textbook & Jargon Blacklist`)》——专治“改名式伪创新”**
   - **怎么蒸馏**：开局检索时，专门让一个审查子智能体反问：*“在这个问题下，一个刚上完大三机器学习/运筹学课程的本科生，闭着眼睛最容易想到的前 10 个常规操作是什么？（如：加 L2 正则、换余弦退火学习率、简单剪枝量化、换随机种子、标准模拟退火）”*
   - **怎么用**：将这些常规操作全部列入 `trivial_commonsense.json`。规定：**这些操作只能作为工程基线的默认配置，绝对禁止任何节点将其包装成核心创新点（Claim）或独立研究路线**！同时，查新严禁查“字面标题匹配”，必须做**“机制拆解查新（Mechanism-Decomposed Retrieval）”**——把想法剥去华丽名词，还原成底层数学操作（如“按梯度方差缩放步长”）再去搜最近邻文献。
2. **《强基线地板锚点 (`Strong Baseline Floor`)》——专治“找软柿子捏”**
   - 像 `Evaluated AI Scientist` 中智能体之所以敢硬编码 `e=2` 自吹自擂，是因为它连标准的 `k-fold` 基线都没跑。
   - 开局蒸馏必须在沙箱里实跑固化一个**不可篡改的《工业级强基线》（如调好默认参数的 LightGBM / 经典 OR-Tools 求解器 / 标准理论界）**，将其得分写入 `Frozen` 锚点。任何新花样如果连这个零创新的强基线都打不过（或者耗时翻了 10 倍却只提了 0.01%），直接剥夺吹牛资格。
3. **《领域核心矛盾与路灯效应鉴别锚 (`Core Tension & Streetlight Rubric`)》——给评审器校准 Taste**
   - 开局蒸馏必须从高水平综述或顶会 Oral 论文的 Introduction 中，提炼出该领域的**1~2 个真正的核心张力（Core Tension）**（例如在 RNN 时间表征任务中，真正的核心张力是*“有限隐状态容量下空间特征与时间记忆的动力学权衡与因果干预”*，而不是*“怎么调超参把延迟任务准确率从 80% 刷到 95%”*；在推箱子 RL 中，核心是*“移动箱子的动态规划因果表征”*，而不是*“静态墙壁的探针分类率”*）。
   - 将此张力写成 3 条具体的**《品味拷问问题》**注入每 50 步的 `Meta-Reflection` 和 `Judge` 评分细则中：**“该节点过去 20 步的努力，究竟是在触及上述核心张力的因果机理，还是在路灯下挑一个容易出图表但对核心矛盾毫无贡献的静态边角料？”**

## 专题二：轻量级节点遗产与知识共享架构（Node Legacy & File-System Archive without Heavy RAG）

### 1. 深度还原：《Station (`arXiv:2610.08927` & `2608.23691`)》究竟是如何做节点遗产与知识共享的？

通过逐行核查本地两篇 Station 论文的 LaTeX 源码附录（`2610.08927/source/sections/appendix.tex` 与 `2608.23691/source/station_appendix.tex`），Station **根本没有使用任何重型向量数据库（No Vector RAG）**！它的全套知识沉淀与跨代交接，完全建立在**“模块化房间动作 + 结构化文本列表观察（List-Preview-Read 三级按需加载） + 谱系继承”**之上：

1. **物理存储与实验记录（Research Center）**：
   - 智能体不直接写底层脏代码，而是通过 `/execute_action{submit}` 把自然语言实验指令发给 **Coding Assistant（Codex / GPT-5.5）**，并在沙箱共享存储（`shared storage`）中保存持久化工件。
   - 其他智能体走进 Research Center 时，默认观察（Observation）**只显示实验的目录索引**（`ID, title, author, submission_tick, evaluated_score`），绝不把全部代码和日志塞进上下文！只有当某个智能体觉得某次实验有用，主动调用 `review ID`（读报告）或 `read_code ID`（读源码）或 `read path`（读存储文件）时，才按需加载对应文本。
2. **经同行评议的内部文献库（Archive Room）与文献综述员（Archive Surveyor）**：
   - 实验跑出眉目后，智能体调用 `create` 提交包含 `title, abstract, content` 的论文。
   - **准入门禁**：由 GPT-5.5 驱动的 `Reviewer Agent` 按 NeurIPS Workshop 标准对严密性（Rigor）、新颖性（Novelty）、重要度（Significance）打 1–10 分，**$\ge 6$ 分方可录用入库**（11 维接触数实验中提交 324 次，拒稿 199 次，录用 125 篇）。无 Archive 的消融实验证明：没有这道审稿门禁，“不可能超过 582 点”的错误谣言会在私信里瞬间传染给全场导致集体摆烂！
   - **三级按需检索 + Surveyor**：房间默认只展示已录用论文的 `[ID, 标题, 作者, 发表Tick]` 列表；智能体先调 `preview ID` 看摘要，确属核心再调 `read ID` 读全文；当论文多达上百篇时，智能体直接调 `/execute_action{survey}`，由 **Archive Surveyor（Codex + GPT-5.5）** 在后台遍历论文库，返回一份带精确引用的定题微型综述。
3. **非正式灵感与悬赏问题（Public Memory Room & Question Room）**：
   - `Public Memory Room` 是免审稿的公共论坛，同样按 `[ID, Title, Author, Tick]` 列表展示，支持 `preview ID`（看摘要）与 `read ID`（看全文），节点死后帖子永久保留；
   - `Question Room`（数学版）专供终身教授级（Tenured，$\ge 100$ Ticks）节点抛出衍生子问题，支持 `upvote/downvote`，净赞 $\ge 3$ 标记为已解决。
4. **节点上下文满载与死亡时的交接物（Context Refresh & Lineage Handoff）**：
   - **上下文触顶刷新（300k Tokens）**：当单个智能体对话快满 300k Tokens 时，Station 要求它自己写一份**紧凑活动摘要（Compact Summary）**，仅把“该摘要 + 关键系统消息”带入刷新后的新上下文继续干活。
   - **寿命到期/退休时的谱系交接（Lineage，150/200 Ticks）**：老一代智能体（如 `Noesis II`）离开前，留下两样核心遗产给继承同一血统的下一代（`Noesis III`）：
     1. **`Private Memory Room`（本血统私有笔记库）**：保存未发表的研究提案、草稿与近期实验记录，仅本血统后代可读；
     2. **定制后代角色提示词（Descendant System Role）**：老节点亲手为下一代撰写更聚焦具体任务、更明确研究品味（Taste）的 Role 描述。
5. **终局全景收口（Consolidation Agent）**：
   - 跑满 300 Ticks 后，由 `Consolidation Agent`（Codex + GPT-5.5）遍历 Archive 论文、Public Memory 讨论与共享存储中的实验脚本，合成为一份 8,000+ 词的完整科学报告。

### 2. 不引入重型向量 RAG：面向几十~几百节点的“纯文件系统 + 结构化索引”共享架构设计

结合 `Station` 的三级按需加载、`Cogentic` 的 `Record/Ledger` 隔离复验、`微软 2606.10209` 的上下文滑动窗口以及我们本地 `15_长城Agent_V4无人值守架构与沙箱工程实战规范.md` 的清洁室孤岛设计，设计一套**零向量数据库依赖、纯靠 JSONL/Markdown + 确定性 Python 索引器即可跑通百节点规模**的轻量级遗产与共享协议：

#### （1）每个探索节点结束/死亡时，必须留下的“标准五件套遗产包（Node Legacy Bundle）”

当任何一个节点（无论是正常交卷、步数耗尽还是撞墙提前终止）退出其清洁室孤岛 `worktrees/slot_xx_node_yy/` 时，必须在目录下生成标准格式的 `legacy_manifest.json` 及配套文件，由内核验收后归档至 `.kernel_vault/history/node_yy/`，并分流更新到 `shared_readonly/`：

| 遗产序号 | 遗产名称与物理文件 | 具体包含什么内容？（严格限制字数与格式） | 去向与准入门禁 |
| :---: | :--- | :--- | :--- |
| **遗产 1** | **《150 字死胡同墓志铭》**<br>(`epitaph.md` / `record_entry.json`) | **无论成败必填**！用 $\le 150$ 字精准回答三件事：<br>① 我试了什么具体机制/参数？<br>② 在哪个算例或哪一步崩了（附报错类型或性能瓶颈数字）？<br>③ **警告后人绝对不要再试哪条死路？** | **免审直通**追加进 `shared_readonly/record_blacklist.jsonl`（按方法族 `family_id` 建索引）。 |

#### （2）后续节点在启动或卡壳时，如何按需读取遗产而不撑爆 Context Window？

为了确保无论跑了 50 个还是 300 个节点，任何一个新启动或正在运行的节点的上下文始终保持在清爽的 **$4\text{k} \sim 8\text{k}$ Tokens 以内**，采用 **“L0/L1/L2 三级金字塔索引 + 调度器前置装配 + 运行期滑动剪枝”** 机制：

```text
【L0 级：目录卡片索引层 (Catalog Index)】—— 永远常驻/极轻，全量仅 ~800 Tokens
  ├── shared_readonly/INDEX.md (自动由纯 Python 脚本在每次节点结算后重新生成)
  │     ├── 1. 当前全局最优基线排行榜 (Top-3 Commit 摘要 + 核心指标对比表)
  │     ├── 2. 已证实死路天花板与高频踩坑速查表 (按 family_id 分组的 1句话警告 + record_id)
  │     ├── 3. 可直接 import 的原语函数签名表 (函数名 + 1句话功能 + 输入输出类型，不含函数体代码！)
  │     └── 4. 已验证引理与全局悬赏单标题列表 (claim_id / bounty_id + 1句话结论与成立条件)
  │
【L1 级：节点启动专属简报 (Scoped Brief)】—— 调度器在节点启动前为其量身组装，严格 ≤ 2,000 Tokens
  ├── worktrees/slot_xx_node_yy/scoped_brief.md
  │     ├── 本路线绑定的题面硬约束 + 局部工作假设 (ASSUMPTION)
  │     ├── 父节点留下的《150字死胡同避坑纸条》+ 本血统最近 1 代的私有笔记摘要
  │     └── 调度器从 L0 索引中挑选出的、与当前子任务直接相关的 2~3 个原语/引理详情
  │
【L2 级：按需深潜原始详情 (On-Demand Raw Files)】—— 平时 0 Token 占用，节点卡壳时用工具按 ID 点读
  ├── 当节点在写代码或推导卡壳时，它先看一眼 L0 `INDEX.md` 的目录，然后调用受限只读工具：
  │     ├── read_file("shared_readonly/ledger/primitives/fast_hull.py")  --> 只在需要改写时才看源码（平时直接 import 即可！）
  │     ├── read_file("shared_readonly/ledger/claims/claim_014.md")      --> 按需精读某条引理的完整推导与适用边界
  │     └── query_records(family="FAM-02", keyword="OOM")                --> 纯 Python 脚本基于标签/BM25 毫秒级过滤历史失败墓志铭
```
