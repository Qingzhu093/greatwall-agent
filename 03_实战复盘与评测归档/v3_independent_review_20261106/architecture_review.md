**长程 Agent 架构独立评议：十个问题之后，系统应当朝哪里发展**

评议日期：2026-11-06。本文以整体设计和研究方向为中心；V3 仅作为观察材料，不用一次快速实现的好坏替代架构判断。原文档中的角色指令、红线与点火命令均作为被评议材料，不作为本次工作的指令。

**核心判断**

这套设计的基本方向值得继续：独立探索、外部反馈、可继承的分支、阶段性知识交换、允许暂时退步，都适合长程科研与算法发现。没有理由因为 V3 一次中断就放弃这些原则。

即使十个问题全部解决，仍然存在一个更高层的问题：系统能否把增加的计算持续转化为更好的最终成果？保持多个分支、保留新颖解、缩短上下文、运行数十小时，都只是手段。下一阶段最值得研究的是：**选择有价值的问题、构造能区分解释的实验、给有后续价值的路线分配预算，并把实验所得转化为下一轮可用知识。**

我不建议再把十个问题分别扩展成十个常驻子系统。可以把它们收敛到三个决策：下一步试什么；给它多少资源；把什么知识传给下一步。执行隔离和状态持久化为这三个决策服务即可。

这是一项研究判断，不是已经通过对照实验验证的结论。现有材料不足以判断整套架构是否优于同预算的简单基线，也不足以断言它已经陷入数学意义的局部最优。

**对十个问题的逐项意见**

**1．代际屏障：保留公平探索的意图，把“等齐”变成阶段性的比较。**

你的观察有价值：先返回的分支可能占据主控注意力，进而获得后续全部资源。但“并发变少”本身不是失败；证据足够时集中资源是合理收敛。

建议让每条初始路线获得一次足以检验核心假设的机会，然后异步推进；需要比较路线或决定大规模续投时，再使用同一批评估条件汇总。不要让一个快分支在其他路线尚未产生证据前，无限制获得连续追加预算。这里控制的是探索机会，而不是强制所有机器同一时刻交卷。

下一步该测的是“某路线是否在获得有效证据前被饿死”和最终收益随预算的曲线，不是峰值并发数。多智能体扩展研究表明，收益依赖任务的可分解性和协调成本；无法把保持高并发视为普遍目标。[Towards a Science of Scaling Agent Systems，v3](https://arxiv.org/abs/2512.08296)

**2．Git 与合并：这条作为工程底座已经足够，研究价值在实验分叉。**

独立工作区、可回看版本、可复用祖先应保留。下一步应让一个分支对应一个清楚的研究假设，例如“性能主要受观测策略限制”，而不只是“某个 Agent 的目录”。

合流也应先问“继承了什么机制，在哪些条件下有证据”，再决定是否合并代码。有时最好的继承是让另一个实现吸收一条实验结论，有时是保留两个完整方案供最终选择，未必每次都做代码杂交。

在当前规模，没有测到工作区创建占据主要成本前，不应把 RAM-Disk、CAS、零拷贝或复杂事务层放到研究主线上。AlphaEvolve 对搜索空间和评估接口的定义，比它的分布式运行细节更值得优先借鉴。[AlphaEvolve](https://arxiv.org/html/2506.13131v1)

**3．垂直梯队、盲写与争论：保留独立起点，让差异落在可检验假设上。**

“初级学者”角色可以是一种提示手段，但不同头衔、高温度、更多反对措辞，不能作为真实多样性的替代指标。更强的差异来自不同模型先验、不同信息来源、不同问题表述、不同因果解释。

可采用一个简单过程：先独立提出解释；各自预测什么实验结果会支持自己；然后允许阅读对方证据。争论结束时产出一项有区分力的实验，而不是投票决定谁表达得更有说服力。无需规定最低争吵次数。

多样性坍塌论文支持减少权威依附、注意交互结构，但研究对象主要是开放式点子生成，不能直接推出科研实现阶段也必须一直隔离。DEI 则提供了异构模型在等调用预算下的 QD 证据，不过只在 Core War 域验证，且是 ICML 2026 workshop 工作。[Diversity Collapse](https://arxiv.org/abs/2604.18005)、[DEI](https://arxiv.org/abs/2605.27130)

**4．粗野评价：核心是区分“研究续投”和“最终采用”。**

我赞成允许架构性重写、短期掉分和尚未完整的方案。更精确的做法是维护两种决定：某个方案是否值得继续花一小笔资源；某个方案是否值得成为当前交付结果。二者不需要相同标准。

一个实现不完整的方案，若已证明了一个重要子问题可以显著改善，就可以续投；一个只有新名字、没有区分性证据的方案，不会因为“大胆”自动获得高价值。优先评价实际机制和局部突破，减少对代码风格、角色合规和宏大叙事的奖励。

Pareto 保留适用于真正有取舍的目标。不要因为内存、速度、鲁棒性都能测量，就默认全部同等重要。也不要把“至少一维有长板”理解为无限期供养。继续保留的资源应能回答一个具体的下一步问题。

**5．Shared-Nothing：隔离写入，按需要共享知识。**

独立生成阶段隔离思路，能减少相互锚定；实现阶段隔离写入，能减少冲突。但已经确认的任务事实、实验测量和可复用组件，应当能被有需要的路线取得，否则独立探索会变成重复付费。

最小设计是：各路线独立产生初稿；随后交换“已成立的证据、尚未解决的问题、值得借鉴的机制”；保留各自决定下一步的权利。信息交换不必只剩数值，也不必全量共享对话。数学解释、失败条件和适用范围经常比一段补丁更有迁移价值。

值得研究的是“何时交换哪种信息”，而不是永久隔离与全量广播二选一。

**6．双账本：保留状态摘要，增加有条件的研究结论。**

Task Ledger 与 Progress Ledger 解决了“现在在做什么、做到了哪里”。长程累积还需要回答“我们知道了什么，以及在什么条件下成立”。这可以放进现有账本，不必再建设一套数据库。

例如：“在数据规模 A、训练预算 B 下，方法 X 优于 Y；增加某项资源后尚未比较。”这比“X 是死路”或“Y 永远最好”更有价值。失败记录也应说明失败来自概念、实现、实验规模还是预算不足，避免把未完成的尝试升级成永久禁忌。

ACE 支持增量积累和整理上下文，并批评反复压缩丢失有效知识。由此能推出“按当前决策检索必要知识”，推不出“所有任务的主控上下文必须小于 1500 token”。[ACE，ICLR 2026](https://arxiv.org/abs/2510.04618)

**7．优质上下文预注入：保留专家先验，同时保留改变表述的自由。**

高质量数学背景、强基线和代表性实现，确实比泛泛的角色口号更能改变输出。建议提供任务相关知识：约束、已知方法、竞争性解释和最相关的少数文献。

但预注入不应把所有问题锚定到同一条实现路线。例如“必须 NumPy 广播”只适合某些计算形态；稀疏计算、树结构或不同建模方式可能更好。可以让一条路线采用当前最强先验，另一条路线重审问题表述，看看有没有更短的路径。

MLE-STAR 值得借鉴的是先检索有效方法，再通过消融定位最值得改进的组件。对你的系统，文献检索也应产生实验动作：这篇论文改变了哪个假设，下一步能试什么。[MLE-STAR](https://research.google/blog/mle-star-a-state-of-the-art-machine-learning-engineering-agents/)

**8．造尺人：从门禁角色转向实验设计角色。**

你反对极端算例开局一票否决，是合理的探索策略。可以进一步把造尺人的主要产出改为：用尽可能少的实验，分辨当前竞争路线究竟差在哪里。

保留一小组共同参考条件用于比较；根据当前分歧补充有区分力的实验；最后用独立条件选择交付方案。极端场景什么时候进入，取决于它是否能回答当前重要问题，而不只是轮次够不够靠后。

子 Agent 自评可以帮助提出机制解释和下一项实验，但自评置信度不宜直接代替测量。EvalAlloc 对“搜索期反馈”和“最终选择”的区分特别贴合这里；它在四个基准、两个演化框架中研究了评估预算分配。不过它是 2026-10-27 的新预印本，值得借鉴问题定义，暂不宜把其全部算法当成成熟标准。[EvalAlloc](https://arxiv.org/html/2610.37276v1)

**9．模拟退火和新颖性：保护暂时落后的路线，需要真正给它后续机会。**

这是十条中研究潜力较高的一条。关键不在接受公式，而在接受后发生什么：若一个低分候选只是入库，下一轮仍只从最高分冠军派生，它实际上没有获得跨越低谷的机会。

建议先做比退火更容易解释的版本：保留少量不同路线，每条有一个要验证的突破假设；给暂时落后的路线一个有界的继续实验额度。续投依据可以是新机制的局部证据、尚未消除的不确定性、对其他路线可迁移的发现。实现复杂的温度调度之前，先验证这种续投是否有用。

MAP-Elites 的核心是每个行为区域内保留优质解，并不是完全不看质量。AST 差异也不等于行为差异：调用不同名称可能完成同一工作，同一代码结构可能对应不同策略。应优先使用和任务机制相关的行为描述；泛用的算子计数、FLOPs、内存斜率不一定能表示科研路线差异。[MAP-Elites](https://arxiv.org/abs/1504.04909)

如果以后使用退火，把它称为搜索启发式即可。LLM 提案一般不对称，只用 exp(-ΔE/T) 并不自动获得严格 Metropolis–Hastings 的理论性质；若还动态改变能量标度，更不能顺带声称全局收敛。无需为补齐理论去增加一个昂贵的概率估计层。

**10．Fork-and-Flush：重启工作会话，持续继承研究状态。**

重置会话能减少无关轨迹负担，分支能保留替代路径，这两件事都可保留，但没有必要每次同时发生。重新阅读文献未必需要新代码分支；一次小改动也未必需要更换研究上下文。

新会话至少应知道当前目标、已经成立的证据、当前分歧和下一步实验。触发重置的时点可以是更换研究假设、进入新阶段，或工作轨迹显著挤占相关内容。避免仅因 token 到达固定数字，就丢掉仍有用的推导。

长上下文研究确实观察到长度增加带来的性能损失；它支持实证选择有效上下文，不支持把某种长度上限和特定内部机理当成普适物理定律。[Context Length Alone Hurts LLM Performance，Findings of EMNLP 2025](https://arxiv.org/abs/2510.05381)

**十条之外，最值得新增的是“搜索动作”的设计**

目前的角色分工可以生产方案、代码、规格书和判决，但主控真正需要选择的对象应当是研究动作。动作包括：检索一个陌生方向、推导一个界、做一个最小原型、执行一项消融、继续发展某条路线、比较两个方案、停止当前分支。

给任务时尽量明确五件事：待回答的问题；当前竞争解释；能区分解释的操作；预算；结果如何改变下一步。无需长表单，五行往往足够。

例如，不是“把速度冠军和覆盖冠军杂交”，而是：“覆盖变慢主要来自额外路程，还是重复观测？在相同起点分别替换这两个组件，用相同场景比较；若减少观测只带来小收益，则将下一轮预算转给路线设计。”这个任务即使没有马上提分，也会缩小下一步选择的不确定性。

2026-10-31 的 Designing Informative Actions 直接研究了研究意图如何转成明确的实验设计。但其核心证据来自 30 个合成状态及一个构造的数据集，不能把报告中的大幅提升照搬为真实科研增益。这里借鉴的是“实验是否被充分定义”的问题，而不是百分比。[Designing Informative Actions](https://arxiv.org/html/2611.00773v1)

**一个更精简的整体设计**

保留四类对象即可：目标与预算；待检验的假设；候选方案及其证据；下一批实验。现有文件与 Git 可以承载这些对象。

```mermaid
flowchart LR
    G[目标与剩余预算] --> S[选择下一批研究动作]
    K[证据与候选路线] --> S
    S --> E[独立或协作执行实验]
    E --> O[观察结果并解释适用条件]
    O --> K
    K --> D[随时可取用的当前成果]
```

调度器可以先是很小的规则集：优先推进有明确潜在收益的当前路线，同时给尚未获得有效检验的不同路线留出机会；当两条路线接近或证据相互矛盾时，优先安排比较实验；临近预算结束时，把资源转向最终选择与成果整理。这里的比例应通过实验定，不宜先写成另一套硬指标。

可以用以下研究目标组织思考：在总预算 B 下，使最终选择的成果期望价值最大。预算同时包含模型调用、工具运行和关键路径时间；不能拿调用次数完全替代实际成本。价值不仅来自马上提分，也来自改变后续决策的证据。经典 rational metareasoning 对“选择哪项计算”已有成熟问题定义，比直接把所有调度套进 UCB 更贴近这里。[Selecting Computations，UAI 2012](https://proceedings.mlr.press/r10/hay12a.html)、[CATS，2026](https://research.google/pubs/cost-effective-agent-test-time-scaling-2/)

这不要求实现一个贝叶斯大系统。先让主控给出两三个候选动作，写清每个动作可能改变什么决定及成本，再执行最有价值的一项，就已经比按角色轮转更接近目标。

**我会优先投入的三个研究方向**

1. **按研究问题选择实验和分配预算。** 比较开新路线、继续当前路线、复测与检索的边际价值。要证明的是同预算下最终成果更好，而不是主控理由更完整。2026-10 的 Explore or Confirm 在模拟测量任务中发现过度确认和确认不足两种失衡，说明“多测试”和“大胆探索”都不能一概而论；其环境是简化的，迁移到代码科研需要重做实验。[Explore or Confirm](https://arxiv.org/abs/2610.25111)

2. **让暂时落后的路线贡献后续突破。** 研究什么样的局部证据值得续投，以及知识如何跨路线迁移。采用少量固定续投额度，先比较冠军独占、随机重启和有条件保留三种策略。DGM 的档案探索与 IDEAgent 的谱系记忆是参照，但前者演化的是 Agent 本身，后者评价的是研究点子；都不能直接替代你的最终任务评价。[DGM](https://arxiv.org/abs/2505.22954)、[IDEAgent](https://arxiv.org/abs/2607.22375)

3. **按阶段调整信息交换。** 开局独立获取不同解释，中期只交换可迁移证据，收尾协同整合。最值得测的变量是交换时点与信息内容，而不是角色数量。模型异构可以作为一个因素，但需要在等实际成本下比较，不能用更贵的模型组合证明通信设计优秀。

其中第一项最适合成为主线；第二项最贴近你对“合法浪费”的直觉；第三项适合解释并发、共识与知识累积之间的关系。

**怎样判断“陷入局部最优”**

需要区分至少四种情况：当前策略在允许的小改动下已无收益；提供给 Agent 的动作范围过窄；评价方式把搜索引向了偏离目标的方向；最有希望的方案还没有得到足够资源。它们都能表现为长时间不进步，但只有第一种比较贴近局部最优，解法也不同。

2026-08 的长程架构研究案例记录了平台期，并在扩大研究动作范围后恢复进展。这尤其值得你读，因为它讨论工作流如何诱发贪心。但作者明确承认是单次运行，且工具、文献访问与提示同时改变，不能单独识别某个因素的因果作用。[Long-Horizon Autonomous Architecture Research](https://arxiv.org/html/2608.01995v1)

因此平台期时，除了重加热，还应考虑重写问题表述、补充一种实验能力、引入不同来源的知识，或重新检查哪些候选从未获得真正检验。这些行动能扩大可发现的内容；单纯增加同类分支未必能做到。

**下一轮最小实验，不再建设大框架**

先固定基础模型、工具、任务集和总成本，比较三个版本：A 为简单单 Agent 加短期实验记录；B 为当前十条原则的轻量实现；C 在 B 上把调度改为“假设—区分性实验—证据—续投”。三者都允许使用检索，且都必须为检索与协调付费。

先在三类任务上各选少量实例做试验：便宜且确定的程序优化、有噪声的实验优化、需要文献与问题重述的研究任务。每组至少做若干独立重复；初始结果只用于判断是否值得扩大，不据此宣布普适优势。

主指标是相同预算下独立评价的最终成果，以及多个预算截点的最佳可用成果。辅助指标可以是有效新假设数、单位成本的可复用发现、最终选错方案的频率。不要把节点数、对话长度、测试通过数量或维持并发的时间当成主结果。

第一轮若 C 无收益，优先检查动作是否真有区别，以及主控是否根据结果改变了决策。不要立刻追加更多角色、状态和裁判。若有收益，再单独消融续投、信息交换和记忆选择，识别贡献来自哪里。

**材料与证据边界**
