用户澄清任务重点后，停止继续扩展 V3 的实现审计。此文件保留已完成的证据，供需要时回查。本次没有修改 V3 或 AFEVA 既有源码。

**运行中断的直接证据。** 主控会话 29952cc0-692f-43b1-a2d7-23cbdcdda397 的完整 transcript 中，step 127 与 129 记录了 node_08 / node_07 的 RESOURCE_EXHAUSTED (429)，说明是平台额度耗尽，不能据此认定架构死锁或程序崩溃。北京时间 2026-11-06 01:55:14 开始，03:15:04 首次出现该额度错误，约 80 分钟；“5 小时限额”不是这次已经连续运行 5 小时。09:46 的后续对话是用户要求汇报。平台如何折算配额未查明，不从 transcript token 字段反推计费。

**原题与代理任务的不同。** 本机 B题.pdf 第 1 页要求一只机器狗；第 4 页说明机器狗位置通常不受目标区域限制，仅有坐标数值界。V3 默认两只狗，按最大个体时钟计时，并拒绝半径 1800 米以外的动作。多个求解器还读取 is_all_cleared，以沙箱真实源总数决定终止。这些是任务模型差异，不宜用增加异常处理来解决。应先明确研究究竟评价原任务，还是有意设定的双狗变体。

**仅用于理解反馈条件的诊断。** probe_v3.py 对 node_04 和 node_06，在现有双狗沙箱中执行 3 个场景等级 × 11 个 seed × 2 个终止信号条件，共 132 次运行；seed 为原有 42 和额外 0–9。masked_stop 仅让沙箱 is_all_cleared 恒为 False，不改原算法，也不构造更好的终止策略。记录每次结束状态，包括异常。这个实验不是正式单狗赛题成绩，也不是修复后的新算法。

| 观察 | 结果 | 应如何解释 |
|---|---|---|
| node_06，seed 42，Level 1 | 原条件 173.94 秒/源；屏蔽完成信号后 333.05 秒/源；均清除 12/12 | 成绩对额外停止信息敏感；不能把全部速度优势归于搜索策略 |
| node_06，seed 42，Level 2 | 177.52 → 308.65 秒/源；均清除 14/14 | 同上 |
| node_06，额外 10 个 seed，Level 3 | 原条件下 3/10 次全清；无运行异常 | 一组 seed 的满贯不能直接推广；不是一个总体成功率的精确估计 |
| node_04，seed 42，Level 1 | 重现 147.21 秒/源；屏蔽完成信号后不变 | 不能声称所有节点的成绩都受该信号同样影响 |
| node_04，seed 42，Level 2 | 清除到 7/14 时被现有沙箱的圆域边界检查中断 | 原指标文件缺少该场景，不能将其 Level 1 最快推广为全场景最快；原题本身也没有该圆域行动限制 |

probe_results.json 保存逐次数据。发生异常的运行所记录的 time / cleared 只是中断时的部分进度，不能用脚本摘要中的混合均值为节点排名。mask 条件下报告的内部 is_all_cleared 不用于判断成功，以实际 cleared / total 和 error 字段判断。

**实现与规范的边界。** AFEVA 通用运行时目录具有状态机、工作区、演化与 mock 测试模块；V3 主控轨迹主要调用平台子 Agent，通过提示词、文件和评测脚本推进。没有在已检查的调用中找到通用运行时被接入 V3 的证据。TEST_READY 中的 mock 验收能说明所测软件行为，不直接证明真实 LLM 的长程探索收益。这不是要求继续扩充运行时，而是说明下一次应在同预算对照中评价所选机制。

这些观察最多支持“需要准确理解搜索反馈”的判断，不足以说明十条原则已经失败。整体建议与文献依据见 architecture_review.md 和 literature_map.md。
