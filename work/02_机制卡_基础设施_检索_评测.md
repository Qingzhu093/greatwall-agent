## 2. 机制卡

### A1 编排者-工作者 + 上下文隔离
- 证据等级：D-自述（Anthropic 工程博客，内部评测，无方法学细节）
- 来源：Anthropic 工程博客（2025-06-13）§"多智能体系统的优势"、"架构概览"。
- 它怎么运作：lead agent 解析 query→制定策略→派生 subagents（各自独立上下文窗口）→子 agent 循环调用搜索工具→只把浓缩结果回传→lead 综合成报告；上下文隔离同时实现关注点分离。
- 报告的数字/现象：内部 research eval 上（Opus 4 主控 + Sonnet 4 子 agent）比单智能体 Opus 4 "outperformed by 90.2%"；BrowseComp 上三因素解释 95% 方差、**token 用量单独解释 80%**；agent 约 4×、多智能体约 15× 聊天 token。
- 适用边界：广度优先、可并行、信息量超单窗口、工具多；**不适合共享上下文或高相互依赖的任务（原文点名多数 coding）**；需模型智力过阈值。
- 解决哪个失败模式：单窗口上下文污染、路径依赖、串行搜索慢。
- 代价：15× token；协调复杂度；非确定性。
- 对长城 Agent 的启示：**采纳**上下文隔离与"只回传压缩结果"，**拒绝**把 90.2% 读成"多智能体必然更强"——该对比同时换了模型配比（Opus+Sonnet vs 纯 Opus）和 token 预算，是混杂比较。
- 最小验证：同一批查询，在**固定总 token 预算**下比较单 agent 与 1 主控+3 子 agent，指标用引用准确性+完整性+总 token。

### A2 预算伸缩 + 任务卡 + 先广后深
- 证据等级：D-自述（工程启发式，无对照实验）
- 来源：§03 提示词工程第 3、2、6 条。
- 怎么运作：把 scaling rules 写进 prompt（简单事实核查 1 agent/3–10 次调用；直接对比 2–4 子 agent/各 10–15 次；复杂研究 >10 子 agent）；每个子任务必须给目标、输出格式、可用工具与数据源、任务边界；搜索从短宽 query 起步逐层收敛。
- 解决哪个失败模式：简单问题过度投入、子任务重复与漏项（委派不清）。
- 数字/现象：早期简单查询拉起 50 个子 agent；一个子任务查 2021 车芯、另两个重复查 2025 供应链。
- 适用边界：数字随模型/工具漂移，是启发式不是硬规则。
- 失败模式：简单问题过度投入、子任务重复与漏项。代价：prompt 复杂度上升。
- 启示：**改造为**"预算策略表 + 子任务卡 schema（4 字段）"。
- 最小验证：A/B 带/不带任务卡，统计子任务重复率、漏项率、总 token。

### A3 Extended Thinking 作为可控草稿纸
- 证据等级：D-自述（行为描述 + 定性声称，无数字）
- 来源：§03 第 7 条。
- 怎么运作：模型在产出前输出额外可见 thinking token；lead 用它规划路线/选工具/判复杂度/定子 agent 数与职责；子 agent 在工具返回后做 interleaved thinking，评估信度、找 gap、改查询。
- 解决哪个失败模式：长程规划缺少可控中间推演；工具结果不复评就续搜。
- 数字：**未报告**（原文只说 "Our testing showed ... improved instruction-following, reasoning, and efficiency"）。
- 适用边界：依赖模型是否提供 thinking 能力；thinking token 计费、增加延迟。
- 失败模式：把 thinking 当记忆或日志；跨上下文丢失时 thinking 不保留。
- 代价：token 与延迟。
- 启示：**采纳**为规划层（模型支持时）；**拒绝**"thinking 模式=长期记忆/状态"的读法。
- 最小验证：同任务开/关 thinking，测子任务卡完整率（职责/格式/工具/边界四项齐全率）与 token。

### A4 持久化执行与断点恢复
- 证据等级：D-自述（工程做法，无恢复率等数字）
- 来源：§05 "Agents are stateful and errors compound"。
- 怎么运作：状态跨多次工具调用；不从头重启，从出错处恢复；模型侧把工具失败如实告知让其自适应 + 工程侧 retry logic 与 regular checkpoints 兜底。
- 解决哪个失败模式：长程运行中一次工具失败导致整条轨迹报废。
- 数字：**未报告**（无恢复成功率、checkpoint 间隔、MTTR）。
- 适用边界：长程、有副作用、工具不稳定时必需；短任务不值得。
- 失败模式：一步失败导致整条轨迹改变（原文结语）；错误复利。
- 代价：状态序列化、版本兼容、幂等改造。
- 启示：**采纳**为"步粒度检查点 + 幂等工具"，不要包装成"执行引擎"叙事。
- 最小验证：在第 k 步注入进程 kill、工具 500、超时各 5 次，测恢复成功率、重复副作用次数、恢复后任务完成率。

### A5 追踪、外部记忆与交接
- 证据等级：D-自述（工程做法，无对照）
- 来源：§05 调试段 + 附录 2。
- 怎么运作：① full production tracing 回放决策链，只看决策模式/交互结构元数据、不看对话内容；② 阶段完成即摘要写外部记忆；③ 逼近上限时派生干净上下文子 agent，用 handoff 延续，并可随时取回研究计划。
- 解决哪个失败模式：失败无法归因；上下文溢出丢失前面结论。
- 数字：未报告（只说对话可达数百轮）。适用边界：需调用级埋点与可检索的外部记忆。
- 失败模式：无追踪时分不清"查询差/来源差/工具失败"；上下文溢出丢前提。
- 代价：埋点与存储成本、隐私约束。
- 启示：**采纳**并拆成三类记录：调试轨迹 / 任务状态 / 成果产物。
- 最小验证：给 20 个失败 run 做根因分类，比较有/无 tracing 的定位时间与正确率。

### A6 同步执行的信息流瓶颈
- 证据等级：D-自述（定性描述，无量化代价）
- 来源：§05 "Synchronous execution creates bottlenecks"。
- 怎么运作：lead 同步等待整批子 agent 完成才进入下一阶段；实现简单，但 lead 无法中途 steer、子 agent 间无法协调、单个慢子 agent 阻塞全局。
- 解决哪个失败模式：尾部子任务拖垮全局（其现状即串行等待）
- 数字：**未报告**；"Straggler"是精读稿加译。相邻数字：并行化降耗时最多 90%、15× token。
- 适用边界：批处理式并行；任务越长、子任务方差越大，阻塞越明显。
- 失败模式：尾部延迟、信息流堵点。
- 代价：原文明确异步的三难——结果协调、状态一致性、错误传播。
- 启示：**改造为**"阶段屏障 + 超时/替换策略"，先同步后异步；**拒绝**"必须一开始就全异步"。
- 最小验证：人为把 1 个子任务拖慢 5×，比较端到端延迟；再测"超时后带部分结果继续"的质量损失。

### A7 工件系统：直写文件 + 轻量引用
- 证据等级：D-自述（定性收益，无数字）
- 来源：附录 3。
- 怎么运作：子 agent 调工具把完整成果写入外部文件/工件系统，只向协调者回传路径/ID 等轻量引用；协调者不必在自己上下文里背原始长文。
- 解决哪个失败模式：多层转述失真与上下文拷贝爆炸。
- 数字：未报告（只有定性：保真度更高、拷贝 token 更少）。
- 适用边界：结构化交付物（代码、报告、图表）；需要文件系统、权限与可解析引用。
- 失败模式："传话游戏"——多层转述导致细节失真甚至虚构。
- 代价：工件命名/版本/可达性治理；协调者要会"读引用"。
- 启示：**采纳**为"成果继承"的默认机制。
- 最小验证：同任务比较"全文回传"vs"文件+引用"，测 token 与最终引用准确率。

### A8 小样本评测 + LLM 裁判 + 人工
- 证据等级：D-自述（内部经验，无一致性数字）
- 来源：§04 与附录 1。
- 怎么运作：从约 20 个真实查询起步；LLM judge 按五维 rubric（事实准确性、引用准确性、完整性、来源质量、工具效率）打分；实测"单次调用输出 0–1 分 + pass/fail"比多裁判更稳、更贴近人类；人工抽查捕捉自动化漏掉的边缘案例；有状态变更的任务用终态评估+离散检查点。
- 解决哪个失败模式：长文产出无法规模化评估、改进无法比较。
- 数字：20 个查询；早期 prompt 微调可把成功率 30%→80%；人工发现早期 agent 偏好 SEO 内容农场而非权威 PDF。
- 适用边界：有明确答案的用例最有效；自由文本需校准；单裁判仍会漏硬伤（见 D1）。代价：judge 成本、rubric 维护、人工不可省。
- 启示：**采纳**"20 条起步 + rubric"，**改造为**"硬伤清单优先于风格评分"。
- 最小验证：20 条人工标注集，测 judge 与人工一致率、对已知缺陷的召回率。

### B1 方法族谱与动态重定向
- 证据等级：C-框架（提示词原文可核；无任何实验）
- 来源：OpenAI《用于证明圈双覆盖猜想的提示词》"Multiagent Search Heuristics" 第 1、3、4 条。
- 怎么运作：维护显式方法族谱，按**数学思想**（不是措辞）归类 agent；若过多 agent 聚拢到一族，立即把一部分重定向到未充分探索的形式化路径；不许"优雅归约"仅因此占据主导——停在等价强度引理上的路线不算接近完成。
- 解决哪个失败模式：多路搜索伪多样、群体扎堆到同一诱人但不完整的归约。
- 数字/现象：最多 64 个并发 agent；不采用"N 个 agent 负责策略 X"的固定分配。
- 适用边界：需要有可枚举的方法族与可判定产物；适合有明确命题的探索，不适合无结构开放任务。
- 失败模式：伪多样性（换措辞不换思想）、群体早熟收敛。
- 代价：需要分类 agent/元数据、registry 维护。
- 启示：**采纳**为"路线登记表"（对应用户"多路线并行"）。
- 最小验证：记录每轮路线族分布，测族覆盖数与最终最好解的关系；人为让 80% agent 挤一族，看重定向是否恢复多样性。

### B2 早期独立 + 延迟交叉授粉
- 证据等级：C-框架（提示词原文可核；无任何实验）
- 来源：同上第 2、5 条。
- 怎么运作：早期不告诉多数 agent 当前受青睐的方法，避免都收敛到"诱人但不完整"的归约；保留数条互斥路线多轮，等各自发展出真实强弱后再融合。
- 解决哪个失败模式：早期信息共享导致思维共振、早熟收敛。
- 数字：未报告。
- 适用边界：任务可拆成独立探索分支；预算小则难执行。
- 失败模式：思维共振、早熟收敛。
- 代价：重复劳动与 token 浪费（正是多智能体 15× 成本的来源之一）。
- 启示：**采纳**为信息隔离策略；与"共享上下文"的架构假设直接冲突。
- 最小验证：A/B 早期是否共享 favored approach，测路线多样性指标与最终最好解质量。

### B3 阻塞判定 + 对抗审计 + 硬产物 + 终止约束
- 来源：OpenAI CDC 提示词 "Multiagent Search Heuristics" 第 6–8 条与 "Termination & Strict Constraints"。
- 证据等级：C-框架（提示词原文可核）；“led to its proof” 为 D-自述、未验证。
- 怎么运作：卡在“定理级缺失引理”即标 blocked，只有新机制/不变量/构造才解封；对抗 agent 逐条查重数、闭途径伪装成圈、平行边 2-圈、非连通图、割点、归约引入桥、循环调用等价命题；只收引理/构造/方程/反例，驳回状态汇报、“很接近了”与“显然而然（routine）”；终止条件前置——只有完整证明过审才返回，不许交归约/部分结果，且先跑满 8 小时；公网只许查背景与标准定理，禁查“是否已解决”。
- 解决哪个失败模式：把归约/部分结果当完成；证明中边界条件漏检。
- 数字：64 并发上限、8 小时最低运行；“多次运行/失败次数/审计拦截率”均未报告。
- 适用边界：单命题、高价值、可判定；成本极高、依赖超长会话稳定；开放式写作需另立红队标准。
- 失败模式：把优雅归约当完成、循环论证、边界条件漏检、早退或用检索抄近路。
- 代价：审计耗 token 且可能过度否决；对不可判定问题会烧预算（原文无预算上限，这是缺口）。
- 启示：**采纳**“解封条件写死 + 交付格式写死 + 终止条件前置 + 禁查答案”；**补**预算上限。
- 最小验证：注入 5 个已知错误证明（含循环论证、重数错），测拦截率/误杀率；再统计“到上限仍未完成”与“误报完成”。

### C1 检索初始化 + 可执行基线 + 贪心融合
- 证据等级：B-实验弱（多任务多 seed，但检索组件未消融、基线跨来源）
- 来源：MLE-STAR arXiv:2506.15692 §3.1、附录 A.1；实验设置 §4.1。
- 怎么运作：retriever agent 用 Google Search 检索 M 组 {模型描述, 示例代码}（强制 JSON；示例代码弥补 LLM 对新库的不熟）；A_init 为每组生成端到端脚本、沙箱实跑验证集得 h；A_merger 按 h 降序贪心合并（简单平均），只在提升时接受、下降即停，得强基线 s0。
- 解决哪个失败模式：模型先验选型偏差（动辄 LogisticRegression/ResNet）。
- 数字：M=4；主结果 any-medal 63.6%（Gemini-2.5-Pro）、43.9%（Gemini-2.0-Flash），gold 36.4%/30.3%；单解生成耗时 14.1 h（AIDE 15.4 h，22 赛题×3 seeds 平均）。
- 适用边界：任务有可执行参考代码、有可自动计算的验证指标；检索质量决定上限；基准可能被预训练污染（附录用 25 条 discussion/7 赛题/75 对做 LLM judge 判"足够新颖"——注意这本身是 LLM 判定，非人工核验）。
- 失败模式：模型先验偏差（动辄 LogisticRegression/ResNet）、检索到幻觉代码。
- 代价：4 个候选基线都要真跑训练。
- 启示：**采纳**"检索→结构化模型卡→可执行基线→按验证分贪心合并"；**拒绝**"检索已被证明有效"的转述。
- 最小验证：同 baseline 下 M=0 vs M=4，3 seeds，测 any-medal 与模型选型分布——**这正是论文缺的消融**。

### C2 消融驱动的靶向精修
- 证据等级：A-实验（整体结果）；组件归因未做 = E
- 来源：§3.2；实验 §4.1（T=4 外层、K=4 内层）。
- 怎么运作：外层——A_abl 生成消融脚本（删/简化模块）→执行→A_summarize 出结论→A_extractor 选"影响最大的单个代码块"c_t（避开已精修块）+ 计划 p0；内层——A_coder 改块、字符串 replace 回原脚本、实测；A_planner 依据本块历史提下一计划；K 轮取最优进下一外层，只在实际提升时接受。
- 解决哪个失败模式：全脚本重写导致漂移/截断/不可归因。
- 数字：图 3 显示相对误差随步数下降（22 任务平均，**未给具体数值**）；14.1 h/解。
- 适用边界：代码可切块、指标可自动算、脚本骨架固定；不适合从零写系统；字符串替换要求块可精确定位。
- 失败模式：全脚本重写导致漂移/截断/不可归因（论文在 §1 归因于 AIDE 类方法）；局部最优。
- 代价：每个 block 都要真跑 K 次，训练成本高。
- 启示：**采纳**"消融定位→单块最小改动→指标门禁验收"，这是最可迁移的一条工程方法。
- 最小验证：对照"随机选 block"（论文没做），同预算比提升量。

### C3 智能体自主集成
- 证据等级：A-实验（Table 4，3 seeds/22 赛题）；无显著性检验，故“有保留”
- 来源：§3.3、Table 4。
- 怎么运作：并行 L=2 条流水线产出异构解；A_ens_planner 从均值/排序加权起步，逐轮提 stacking、动态加权、条件概率校准等方案；A_ensembler 实现并评测，R=5 轮取最优。
- 解决哪个失败模式：单解落入局部最优、异构解的互补性未被利用。
- 数字（Table 4，Gemini-2.0-Flash，3 seeds，mean±SE）：any-medal AIDE 25.8 → 单解 37.9 → Best-of-N 42.4 → 简单平均 43.9 → Ours 43.9；gold 12.1/25.8/28.8/25.8/30.3；above-median 39.4/57.6/62.1/60.6/63.6；**银牌 Ours 4.5 < 平均 12.1**。
- 适用边界：需要多条独立解与可融合的预测输出（分类/回归概率）。
- 失败模式：简单平均已接近上限（any-medal 打平）；"智能体集成优于平均"只在 gold/中位数上成立且差异约 1 个 SE。
- 代价：L 倍算力 + R 轮评测。
- 启示：**采纳**"多解 + 可验证门禁融合"，**把"优于简单平均"标为待验证**。
- 最小验证：固定总预算比较 best-of-N / average / agentic 三策略的 gold 与 any-medal，配 bootstrap 置信区间。

### C4 双哨兵：数据泄漏与数据遗漏检查
- 证据等级：B-实验弱（单赛例 n=1；无重复、无 seeds）
- 来源：§3.4；Table 5、Table 6。
- 怎么运作：A_leakage 在执行前抽取数据预处理块做静态/语义审查，发现用测试集统计量或目标变量就重写为"训练集 fit、测试集 transform"；A_data 在精修前对照任务描述检查数据源遗漏，补全加载代码；A_debugger 按 traceback 迭代修复，超轮次则用最后一个可执行版本继续。
- 解决哪个失败模式：指标虚高（数据泄漏）与数据源遗漏导致的欠拟合。
- 数字：Table 5（spaceship-titanic，单例）验证 0.8188→0.8677、测试 0.8033→0.7343；Table 6（nomad2018）RMSLE 0.0591→0.0559。
- 适用边界：代码可静态分析、任务描述结构化；规则有限；单例不可外推。
- 失败模式：奖励黑客（指标虚高）、数据视而不见。
- 代价：额外 LLM 调用；存在误报改写。
- 启示：**采纳**"确定性检查优先于 LLM 判断"这一分层思想。
- 最小验证：构造 20 个含泄漏/遗漏的脚本，测拦截率、误报率、修复后测试集正确率。

### D1 新颖性判定与 AI 评审的两种失效
- 来源：AI Scientist 复评 §2.3（Idea Generation）与 §2.6（Review Functionality）。
- 证据等级：B-实验弱（独立复评，单领域、样本小、无 ground truth 标注）。
- 怎么运作：新颖性——Semantic Scholar 每次 ≤10 条结果、最多 10 轮，抽标题/作者/会议/年份/引用数/摘要，**找不到清晰匹配即 novel=True**，novel 标签影响流程，另三个 1–10 分不参与后续。评审——从 PDF 抽纯文本（读不到图/表/附录）后输出结构化评审（分数、决定、理由）。
- 解决哪个失败模式：把常识当创新；评审抓小放大、漏硬伤。
- 数字：**12/12（10 生成 + 2 种子）判 novel**，至少 4 个是已有技术（micro-batching 有 Jain et al. 2018、adaptive LR、hybrid MF、e-fold CV）；原文脚注称此前测试偶尔判过 non-novel（引用勿删）。评审：自产 7 篇 **7/7 全拒**；人类 10 篇（5 真接收/5 真拒）**拒 9，含 4 篇真接收**，唯一接收的是真拒稿；漏掉 “Conclusions Here”、e=2 硬编码、116→115 秒却内存上升等硬伤。
- 适用边界：依赖 API 覆盖与关键词；评审纯文本、无复现实验；对格式敏感、对论证是否成立不敏感。
- 失败模式：常识当创新（假阳性把下游带偏）；评审保守偏见、抓小放大、与人类弱对齐。
- 代价：假阳性浪费全部下游实验；评审看似专业却不可作裁决。
- 启示：**拒绝**把关键词/单次 LLM 判定当新颖性或质量门禁；**改造为**“多源检索 + 引文级最近邻比对 + 硬伤清单 + 校准集 + 记录证据”。
- 最小验证：50 个已知新旧 idea 的校准集测 recall/precision（要求输出最近邻文献而非布尔值）；30 篇已知接收/拒稿测评审与人类的 kappa 及对注入硬伤的召回。

### D2 鲁棒性与成本
- 证据等级：B-实验弱（单领域、单模型、单模板）
- 来源：同上 §2.4、§2.5、§2.8。
- 怎么运作：人工必须提供 prompts.json、experiment.py、plot.py 与种子 idea；Aider 最多 5 轮补丁式修改；失败即中断。
- 解决哪个失败模式：代码脆弱、表面修改、自评失效。
- 数字：**5/12 实验跑不起来（41.7%）**；代码净增 6,260 字符基线上 +529（+8%）→118/83/66/21；7 篇手稿 6–8 页，引用中位 5 篇（2–9），34 条中仅 5 条（14.7%）为 2020 年后；4/7 排版破损、4/7 数值幻觉；$42 总、$6/篇；人工 25 小时≈3.5 小时/篇；快 3–11 倍。
- 适用边界：单一领域（绿色推荐）、gpt-4o、单模板、小样本。
- 失败模式：代码脆弱、表面修改、自评失效。
- 代价：钱便宜、验证贵；论文工厂风险（作者提出 RAML/RPML 标记与流程日志）。
- 启示：评测必须"重跑实验 + 数值对账"，成本不是瓶颈、验证才是。
- 最小验证：对任意 agent 产出跑"重跑+对账"检查，测数值幻觉检出率。

## 4. 专节：消融实验是什么、怎么读（以 MLE-STAR 为例）

**一句话**：消融就是**控制变量**——把系统里的某个组件拆掉或换掉，其余全部固定，看指标掉多少，从而把"整体有效"归因到某个组件。

**读一张消融表的 5 个问题**：
1. **唯一差异是什么？** 对照组之间只能差一个组件，否则不能归因。
2. **差异超过随机波动了吗？** 看 seeds 数、误差棒、有没有显著性检验。
3. **指标对齐声称的机制了吗？** 声称"提升金牌"就该看 gold，而不是只看 any-medal。
4. **有没有混杂？** 换数据、换模型、换预算、基准泄漏都会污染结论。
5. **样本量够吗？** 单赛题、单 seed 的"对照"只能叫案例，不能叫消融。

**MLE-STAR 实际做了什么**：
- **Table 4（集成策略消融）**：同一 Gemini-2.0-Flash、3 seeds、22 赛题。AIDE 无集成 25.8 → MLE-STAR 单解 37.9 → Best-of-N 42.4 → 简单平均 43.9 → 智能体自主集成 43.9（any-medal）。gold 依次 12.1/25.8/28.8/25.8/30.3；above-median 39.4/57.6/62.1/60.6/63.6；银牌 9.1/4.5/7.6/12.1/4.5。
- **能读出的**：① 去掉集成后单解仍大幅高于 AIDE（37.9 vs 25.8），说明增益不只在集成；② 集成确实抬高 gold（25.8→30.3）与中位数（57.6→63.6）。
- **不能读出的**：① "智能体集成优于简单平均"在 any-medal 上**打平**（43.9=43.9），在银牌上反而更差（4.5 vs 12.1）；② 所有差异约 1 个标准误（SE≈6.0），原文**无显著性检验**；③ 无法把增益拆给检索、定向精炼、字符串替换、checkers 中的任何一个。
- **Table 5/6 是两个检查器的单赛题案例**（n=1，无 seeds、无重复），属"存在性证明"，不是消融。
- **论文没做的 4 个消融**：① 关掉检索（M=0）；② 随机选代码块 vs 消融定位选块；③ 整脚本重写 vs 字符串替换；④ checkers 在 22 赛题上的全量开关对比。
- **术语陷阱**：MLE-STAR 里的 "ablation study"（§3.2 的 A_abl）是**工作流内部组件**，用来定位代码块；§4.2 "Ablation studies" 才是**论文评估章节**。两者同名不同物，转述时务必区分——这是用户"不太懂消融"最容易被绕晕的地方。

**顺便校准两处表述**：① 主表 Table 1 除 Gemini 行外，基线数字取自 MLE-bench 官方 GitHub 仓库而非作者重跑（o1-preview 16 seeds、GPT-4o 36 seeds），跨来源比较要降权；② 论文正文说模板 6,260 字符/255 行、表注写 225 行，原文自身有出入（不影响字符数结论）。

## 5. 对长城 Agent 的直接含义（全部 [E-推断]，未经验证）

### 5.1 "最小可恢复执行"到底需要什么（不要造"引擎"叙事）
组件清单：① **步级状态快照**（当前计划、已完成子任务、未决子任务、产物引用、预算消耗）；② **append-only 事件日志**（可重放、可审计，含 prompt/tool schema 版本号）；③ **幂等工具封装**（重试、超时、退避；重复调用不产生重复副作用）；④ **恢复协议**（区分"已完成可跳过"与"必须重放"的步骤）；⑤ **版本钉住**（运行开始时固定 prompt/工具/模型版本，避免中途升级炸在途运行）；⑥ **故障注入测试**。
最小验证：5 类故障 × 5 次，看恢复成功率、重复副作用次数、恢复后完成率。**没有这组数，不要写"具备容错能力"。**

### 5.2 门禁/盲评必须分层
第一层**确定性检查**（能否执行、引文是否可核、是否数据泄漏、数值是否与产物对账）；第二层**LLM 评审**（rubric、多评委、校准集，只做筛选/排序）；第三层**人工抽检**。依据：AI Scientist 的 reviewer 9/10 全拒却漏硬伤；Anthropic 的 LLM judge 有效但需 rubric + 人工；MLE-STAR 的规则化 checker 才有可判定性。验证：20–30 条已知好/坏样本，测每层召回率与误杀率，尤其是"注入硬伤"能否被第一层抓到。

### 5.3 评测设计的三条硬要求
① 先用 20 条真实用例起步；② 必须有"硬伤清单"（AI Scientist 的 41.7% 崩溃、57% 占位符/幻觉给出了清单样例）；③ 新颖性/质量类判断必须有校准集，禁止单次 LLM 输出或关键词匹配当门禁。

## 6. 本节最可靠的 3 条结论

1. **多智能体的收益主要来自"多上下文并行燃烧 token"，且成本是聊天约 15 倍**；90.2% 与 80% 方差都是内部自述数字，且 90.2% 的对比同时混入了模型配比差异。[D-自述 + E-推断]
2. **MLE-STAR 的可迁移内核是"可执行基线 + 消融定位单块 + 最小改动 + 指标门禁"的工程循环**，整体在 22 赛题×3 seeds 上优于 AIDE；但检索与定向精炼**都没有消融**，组件贡献未被识别。[A-实验（整体）／E（归因）]
3. **评测器本身必须被评测**：AI Scientist 的 AI Reviewer 全拒自产论文、拒掉 4 篇人类真接收论文、且漏掉所有硬伤；关键词新颖性判定把 12/12 个 idea 判为 novel。任何把 LLM 评审当裁决者的设计，都必须先过校准集。[B-实验弱]

## 7. 本节最不确定的 3 个判断

1. **"90.2% 提升主要来自 token 扩展而非架构"**：原文把 token 用量作为解释变量（相关，不是因果），且没控制 token 预算；我倾向"token 是主因"，但这只是对自述数据的再解读。[E]
2. **"OpenAI CDC 的调度启发式真的有效"**：我们只有提示词原文，没有证明、没有失败次数、没有对照；"led to its proof"未经验证。可迁移的是"规则写得够硬"，不是"这套规则已被证明能解决难题"。[C/D 边界]
3. **"多路线并行在长城 Agent 的科研任务上划算"**：材料全部来自检索/数学/竞赛三类任务，科研任务的价值密度、评价器可得性都不同；并行度与收益曲线在这里是空白。[E]

## 8. 与用户已有设计（V1/V2/V3、探索架构草案 0.1）可能冲突的点

> 声明：我**没有读**用户既有设计，以下仅按任务描述中四个关键词做预判，需 archaeologist / Lead 校准。

1. **多路线并行**：若设计中把"路线数量"当架构卖点，材料反对——无任何证据支持"路线越多越好"；Anthropic 明确说多智能体只适合广度优先、超单窗口、工具多的任务，且成本 15×；OpenAI 的 64 并发是单命题+超高预算特例。建议改为**预算驱动、按族覆盖、可 blocked** 的路线管理。
2. **成果继承**：若设计是"子 agent 把成果摘要回传、由主控汇总"，材料直接冲突——Anthropic 明确指出会产生"传话游戏"失真，改为工件直写 + 轻量引用；MLE-STAR 进一步说明"可执行 + 有验证分数"才是可继承的最小单位。
3. **门禁/盲评**：若设计把盲评/评审 agent 当最终裁决者，材料强烈冲突——AI Scientist 的评审 agent 在自产论文上 7/7 全拒却漏掉全部硬伤、在人类论文上误杀 4 篇真接收；MLE-STAR 的消融表在 any-medal 上“智能体集成”与简单平均打平，只在 gold 上小幅更高且无显著性检验。门禁应**确定性检查优先，LLM 评审只做筛选**。
4. **知识沉淀**：若把"知识库/经验沉淀"当核心增益，材料只到 C/E——Anthropic 未报告收益，MLE-STAR 检索无消融，AI Scientist 检索退化为关键词匹配。建议限定为"验证过的产物 + 可检索引用"并给出检索质量指标。
