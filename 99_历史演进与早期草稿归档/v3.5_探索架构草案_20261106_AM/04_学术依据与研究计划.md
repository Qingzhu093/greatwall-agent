# 学术依据与研究计划

检索与核对日期：2026-11-06。以下区分论文支持的机制、设计借鉴与尚未验证的假设。既有文献审阅见原综测目录 reviews/v3_independent_review_20261106，本版只保留决定架构的少数来源。

## 1. 核心依据

| 原始来源 | 能支持什么 | 本版如何借鉴及边界 |
|---|---|---|
| Lehman & Stanley, 2011, [Abandoning Objectives](https://doi.org/10.1162/EVCO_a_00025) | 在其迷宫和双足行走任务中，按目标适应度搜索可能受到欺骗，新颖性搜索表现更好 | 不要求每项动作提升当前总分；不推出无目标搜索普遍优越，也未证明本架构有效 |
| Mouret & Clune, 2015, [MAP-Elites](https://arxiv.org/abs/1504.04909) | 在用户选择的行为维度上保存多种优质解，描绘性能分布 | 保留不同机制的成果；首版不套固定网格，主观路线描述不等于严格 QD 算法 |
| Dong & Ma, 2025, [STP](https://arxiv.org/abs/2502.00212) | 猜想与证明相互提供训练信号，围绕证明者能力产生逐渐更难的猜想 | 从成果生成邻近问题；原论文更新模型参数，本架构以固定模型和外部记忆为主，不能借用其增益作效果承诺 |
| Novikov 等, 2025, [AlphaEvolve](https://arxiv.org/abs/2506.13131) | LLM 修改程序，借助演化与自动评价持续改进算法 | 保存可运行产物与评估证据；开放研究缺少同样明确的自动评分，需保留推导与人为判断 |
| Hay 等, 2012, [Selecting Computations](https://proceedings.mlr.press/r10/hay12a.html) | 用计算对后续决策的价值讨论元层选择，在特定选择问题中给出理论与方法 | 同时比较探索、确认、组合成本；首版使用可读判断，没有声称估计精确的信息价值或实现最优策略 |

这些工作的共同启发是：搜索过程需要更多可继承起点，眼前得分不足以解释所有中间步骤的价值。把它们组合为本设计属于独立推断。

## 2. 与用户提到的 OpenAI 数学探索的对应

OpenAI 的 [Navier–Stokes 项目说明](https://openai.com/index/navier-stokes-solution/)描述了多种问题表述、较容易的相关问题、不同路线探索，以及整理组内中间发现后跨组传播的过程。这提供“相关问题突破后重新分配资源，利用中间成果交叉启发”的实例。

该材料是机构自述，不是调度机制的因果对照实验。这里引用其公开的组织过程，不据此裁定数学成果的最终学界地位，也不将其解释为完全无目标的发现。本文更没有依据断言其使用了本设计中的预算比例或成果卡规则。

## 3. 最值得形成研究问题的部分

**研究主线：中间成果的继承方式能否改善长程搜索？**

比较只从冠军方案派生、从多个候选派生、从有条件的研究成果派生并允许组合。关注成果是否改变后续可执行动作，以及这种改变是否带来最终收益。

其中一个有区分度的假设是：对于有明显模块或引理结构的任务，“可组合的成果”比单纯的行为新颖性更能识别有用踏脚石。困难在于组合价值具有延迟，事先难以判断。首版先记录实际下游使用，再研究能否预测。

第二个问题是：什么时机交换什么信息，能兼顾独立发现和知识迁移？比较独立初稿后交换、持续共享与一直隔离，基础模型和总成本保持一致。

不把预算比例、角色称谓或使用 Markdown 本身包装成研究贡献。真正可能成立的贡献是成果继承与组合机制，以及它相对简单搜索的可重复收益。

## 4. 同预算实验

先做少量试运行检查过程，再扩大样本。正式比较固定模型版本、可用工具、初始材料、执行上限和总实际成本。每种方法都计入主持、检索、摘要与证据审阅的开销。

| 版本 | 方法 | 回答的问题 |
|---|---|---|
| A | 单 Agent，短实验记录，允许检索 | 多角色和调度是否值得成本 |
| B | 多路线，保存候选，按当前表现续投 | 普通并行搜索能做到多少 |
| C | B 加成果发展额度与成果继承 | 保护并发展中间发现是否有用 |
| D | C 加显式跨谱系组合 | 组合动作是否贡献独立增益 |

尽量匹配总成本，也报告墙钟时间，避免把更多并发或更多调用当成机制优势。对于真实昂贵任务，可先跑 A、B、D；出现增益后再用 C 定位来源。

任务选择三类：可自动评价的程序优化；有实验噪声的优化；含文献、推导或问题重述的研究。挑选一些有自然中间组件的任务，也包含结构不明显的任务，观察适用范围。

试运行建议每类少量实例、每条件三次独立重复，仅用于发现流程问题和估计方差。正式样本量依据试运行方差与关心的最小收益确定，不用三次运行宣称普适结论。

主指标：固定预算下独立评价的最终成果，以及不同预算截点的最佳已确认成果。开放研究需预先写评价尺度，尽可能隐藏方法来源，由有领域知识的评审判断，并报告分歧。

辅助指标：

- 成果被后续动作实际使用的比例与成本。
- 非冠军谱系进入最终方案或关键推导的情况。
- 组合是否优于相关父方案，以及失败原因。
- 主持和整理占用的预算。

这些指标用于解释机制，不用于运行中给 Agent 刷分。成果被引用不等于具有因果贡献；必要时删除对应成果并重新运行相关部分，检验作用。

## 5. 失败如何影响设计

如果 D 不优于 B，首先检查是否存在可继承内容、后续动作是否真正读取使用、组合是否只在措辞上发生。若过程确实执行而无收益，应接受在该任务与预算下机制不划算，缩减发展或组合额度。

若小预算下协调开销大，保留单 Agent 的成果继承循环。若收益只在某类任务出现，把任务结构作为适用条件。若成果发展产生大量无用内容，优先改善候选选择和问题大小，而不是增加裁判层。

本版最关键的可否证判断：在足够长、存在可组合中间结构的任务中，成果继承加显式组合能否在等实际成本下超过普通多路线搜索。没有出现这种收益时，不能仅凭故事完整或档案丰富宣布成功。
