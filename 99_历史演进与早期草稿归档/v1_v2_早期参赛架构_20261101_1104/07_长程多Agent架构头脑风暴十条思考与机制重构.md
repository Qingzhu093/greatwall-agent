# 长程多 Agent 架构头脑风暴十条思考与机制重构

> **文档属性**：团队核心思想记录与机制重构提案（源自实战经验与理论批判）  
> **核心导向**：直面大模型长程探索中的**“早熟收敛、思维惰性、虚假共识与单线退化”**，重塑真实的并发探索与演化动力学。  
> **编写原则**：精简凝练、去公关化话术、忠实保留实战反思与学术直觉，具备高可读性与落地可操作性。

---

## 1. 调度机制：代际强制对齐栅栏（Epoch Barrier）破除“时序拉直”

- **问题本质**：在缺乏代际强制对齐栅栏的情况下，异构并行的子 Agent 耗时各异。早先返回的数据打破了并行时序，驱动主控急于推进下一步，将原本并发的探索在时间线上被动拉直为单线串行事件流。
- **重构机制**：
  - 引入**显式代际时钟轮（Epoch Barrier Lock）**；
  - 状态机强行卡死：在当前代所有 $K$ 个子任务未出具正式报告或达到硬超时前，主控严禁启动任何下游衍生节点；
  - 杜绝“谁跑得快就顺着谁往下推”的注意力劫持。

---

## 2. 版本控制即基础设施（Git-as-Infrastructure）与合并语义校验

- **Branch-per-subtask 模式**：
  - 彻底抛弃共享工作区；
  - 为每个并发执行的子任务分配独立的 Git 工作树（**Git Worktree**）或轻量沙箱；
  - 每个 Agent 拥有独立的物理副本，彼此彻底隔离，从根源消除文件占用与终端写竞争。
- **合并期语义校验（Validation-at-Merge，参考 CAID 框架）**：
  - 严禁纯文本式的无脑 Git Merge；
  - 子分支合并前，必须执行三步走门禁：① 语法树解析（AST Parser）；② 类型检查与 linter；③ 自动化测试套件执行；
  - 只有在合并后的工作树上通过语义校验与测试，才允许正式合流主干，否则直接拒绝并打回修复。

---

## 3. 探索塌陷根除：垂直梯队、盲写期与点子王平等“争吵”机制

精读 **ACL 2026 Findings** 论文 *Diversity Collapse in Multi-Agent LLM Systems*，提炼对抗早熟收敛的硬核解法：

- **无拘无束的初级学者效应（Unbound Junior Effect）**：
  - 纯专家组与 Leader 集中制会导致解空间多样性（Vendi Score 暴跌至 4.65），下级智能体本能讨好 Leader（虚假共识陷阱 The Sycophancy Trap）；
  - 团队必须采用**垂直梯队（Vertical Architecture）**：必须保留 1~2 个无权威包袱的“初级探索智能体”，赋予极高采样温度，专攻发散探索区（Zone of Divergence）。
- **NGT“盲写隔离期”（Blind Ideation Phase）**：
  - 第 1 轮所有 Agent 必须独立生成完整提案，物理切断上下文输入，杜绝先验污染。
- **子群分治与晚期交锋（Subgroup Federation）**：
  - 隔离为 2~3 个独立小群，各自独立迭代 2 轮后，再拉通进行高烈度辩论；
  - 在 Prompt 中显式设定批判硬指标：**严厉惩罚“我同意上一位观点”等阿谀型回复，设定最低建设性冲突阈值**。
- **点子王阶段性平等对话机制**：
  - 点子王不应常态化无序干扰，而应**阶段性出现**；
  - 当 Worktree 演化积累若干节点、迎来正式版本后，唤醒多个点子王。他们先充分理解当前 Work，然后开展**平等的、以扩展解空间为目的的“吵架辩论”**，彻底粉碎虚假共识。

## 4. 奖励算法与评判智能体（Grader）重构：“粗野”评价替代过度保守

- **反思过度规范**：
  - 传统所谓的“改动极小化、无外部副作用”本质是工业流水线防呆逻辑，在算法攻坚中是扼杀创新的紧箍咒；
  - 必须采用**“比较粗野的评价（Rough & Bold Evaluation）”**：只要算法在全局速度或极限收敛上有突破性表现，哪怕代码结构激进、占用内存较高，也应给予高额度探索奖励。
- **小米 MiMo-V2.6 的借鉴与局限**：
  - 其揭露的 **Reward Hacking 与安全保守策略**（模型在静态稀疏奖励下自发选择跑满航程刷时钟）极有警示意义；
  - 其 **Groupwise Agentic Grading（成组评分）** 的细粒度因果审计可以借鉴（抓取空跑刷时钟的伪进化），但不能照搬其过于规整的对齐框架，给算法探索戴上新枷锁。

---

## 5. 工作空间绝对物理隔离（Shared-Nothing）

- 彻底落实 **无共享架构（Shared-Nothing Architecture）**；
- 严禁任何子 Agent 跨目录读取其他正在运行的 Agent 的半成品代码；
- 所有的跨分支信息传递，只发生在阶段性结束后的只读日志和指标摘要层面。

---

## 6. 总 Agent 认知减熵：Task Ledger 与 Progress Ledger 双账本

- **注意力过载机理**：主控在工作内存中同时追踪多个不兼容算法的状态与报错栈时，认知负荷爆炸；单线串行是模型自发“消灭并发以降低状态熵”的生理本能。
- **双账本彻底解耦**：
  - **Task Ledger（事实与任务队列）**：记录当前待探索的算法假说与物理依赖关系；
  - **Progress Ledger（结构化进度）**：仅记录当前各 Worktree 的完成状态与客观指标；
  - 主控上下文严禁浸泡长篇底层调试日志，让主控认知负荷恒定在极低水平。

---

## 7. 预注入高质量上下文 vs 极简任务书批判（对 Context Engine 持保留态度）

- **双重误区纠偏**：
  - 极简任务书（裸派）会导致 **平庸先验衰减（Default Prior Degradation）**，模型本能写最死板的条件循环；
  - 但市面上的 `Context-as-RAM` / 自动化流水线如果过于繁复，反而容易沦为形式主义套话；
- **实用主义做法**：
  - **预注入高质量思维底座（Demonstration Inoculation）**：在关键任务启动时，垫上严谨的应用数学推导与 NumPy 高效广播范式，唤起模型的专家直觉；
  - 保持实用克制，不强推复杂抽象的 context engine 流程。

---

## 8. 造尺人尺度纠偏：严禁极端算例过早介入，引入子 Agent 自主评价

- **实战血泪**：造尺人设计变态的 Level 3 贴边背向极端边界算例并过早一票否决，直接扼杀了 308 秒的速度冠军 `node_02`，导致全场被迫陷入笨重防守；
- **尺度解毒**：
  - 极端边界算例必须降级为中后期演化的加权项，严禁开局一票否决；
  - **引入子 Agent 自主评价与多角度自评**：允许求解器根据自身数学机理，自报置信度与潜在突破点，由多元评审决定是否保留种子，打破单一静态脚本的独裁。

---

## 9. 引入模拟退火机制：构建鼓励大规模“合法浪费”的探索通道

- **本质认知**：算法质变绝非单调递增，复杂地形中局部最优周围尽是深谷；必须以一定概率接受劣解，才能跨越势垒；
- **机制落地**：
  - **模拟退火降温时钟（Metropolis Acceptance）**：在演化前期设置高温度系数 $T$，哪怕新算法跑分短期下降（$\Delta E > 0$），也按 $P = \exp(-\Delta E / T)$ 概率保留；
  - **新颖性搜索沙箱（Novelty Search Sandbox）**：开辟不看当前分数的特区，考核标准唯一锁定为“算法数学范式、行为空间与现有节点的正交性”，制度化地保护“有价值的弯路与浪费”。

---

## 10. Fork-and-Flush 的真实物理化：拒绝单会话长程衰减

- 主控与子 Agent 严格实行“周期性清栈重置”；
- 真正的 Fork-and-Flush 不只是发一句新消息，而是**物理 Git 分支切换 + 会话状态重置**；
- 历史经验只通过轻量化的摘要文件（Summary Card）向下移交，不背负历史会话的 Context Rot 沉没成本。
