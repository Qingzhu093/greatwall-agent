## 1. 总控和调度器都用 Agent：同意，但「手」要是代码

你说得对：两个都应该是 Agent，都该有模型，区别只是任务分工。我上一版把调度器写成「代码为主」，是想强调**算术和一致性不能交给 LLM**，不是否定它是 Agent。更准确的说法是：

| 角色 | 是 Agent 吗 | 上下文 | 频率 | 能做什么 | 不能做什么 |
|---|---|---|---|---|---|
| 总控 Orchestrator | 是，LLM | 长（8–10k） | 低（每决策代） | 选方向、批准生长、定预算、处理冲突 | 不做机械调度 |
| 调度 Agent Scheduler | 是，LLM | 短（2–4k） | 高（每动作） | 排队、分配、合成 brief、检查约束、升级冲突 | 不改研究方向、不重算预算 |
| 确定性工具层 | 不是 | — | — | 记账、锁、worktree、超时、事件日志、校验 | 不做判断 |

**核心原则：Agent 做判断，代码做执行。** 调度 Agent 可以决定「先跑 A 再跑 B」「把 C 的 brief 加上 D 卡」，但它调用的是代码工具去扣预算、建 worktree、加锁；代码返回的账目是最终依据，LLM 不能口算覆盖。

接口：调度 Agent 输出一个 plan（动作、预算、依赖、brief 草稿），代码层校验（预算够不够、依赖成不成立、worktree 有没有冲突），通过就执行，不通过退回或升级给总控。这样既保留两个 Agent，又不会出现「LLM 记账记错」的灾难。

两个失败模式要防：
1. 调度 Agent 慢慢变成第二个总控（scope creep）——用权限清单和上下文预算卡死；
2. 总控绕过调度直接派活——禁止，所有派发必须经过调度队列，否则无法审计。

## 2. 「初级探索智能体」这个思想有吗？有，而且有论文

有。你在 07 号文档里记的「无拘无束的初级学者效应（Unbound Junior Effect）」来自 **Diversity Collapse（arXiv:2604.18005，ACL 2026 Findings）**。我核对了原文：

- **Horizontal（初级研究者扁平协作）**：Vendi 8.08，最高；
- **Leader-Led（资深权威带队）**：Vendi 4.72，接近 Naive 基线，出现「引力坍塌（Gravitational Collapse）」；
- **Vertical（资深+中级+初级混合）**：质量和多样性折中，作者称「Goldilocks zone of divergence」，分布仍有「Zone of Divergence」（语义距离 > 0.10）；
- 关键机制不是「初级」本身，而是**「专家身份 + 层级权威」的组合**：在扁平拓扑下，Senior persona 反而比 Junior persona 更多样。所以坍塌来自权威结构，不是来自资历。

所以你的「1–2 个初级探索智能体 + 极高温度」是**合理的工程近似**，但要知道它近似的是什么：它近似的是「无权威、扁平、允许发散的局部结构」。更贴近论文结论的做法是：

- 给这 1–2 个初级探索者一个**独立的小房间**：彼此扁平，没有资深 Agent 在场，blind writing，高温度，单独预算；
- 主团队用 **Vertical**（资深给方向、初级做探索），不要用 Leader-Led（资深拍板、初级附和）；
- 不要指望「温度」单独起作用；角色、拓扑、谁在场，比 temperature 更重要。

## 3. 元反思的 Agent 与阶段设计

我上一版给了触发、问题池、写回，但没给「Agent 本身怎么设计、这个阶段怎么进出」。补上。

### 3.1 两种模式

| 模式 | 谁来做 | 成本 | 适用 |
|---|---|---|---|
| **同 Agent 换模型** | 执行者自己，模型临时切到另一个家族，人设改为外部评审 | 低 | 每 N 个动作的轻量反思；保持连续性 |
| **独立反思 Agent** | 单独的 Agent，读执行者的 trace 与成果卡，不读其对话全文 | 中 | 每 M 个决策代的高风险复盘；独立性更强 |

建议两者都用：轻量用同 Agent 换模型（Station 的做法），重审用独立 Agent（避免自我合理化）。

### 3.2 阶段定义

| 项 | 设计 |
|---|---|
| 触发 | 每 N 个动作 / 每 M 个决策代 / 停滞 / 准备换向 |
| 进入条件 | 当前动作已收尾；有至少 3 条成果卡或失败记录可复盘 |
| 隔离 | 禁止工具调用、禁止提交实验/论文；只读 trace 摘要、成果卡、路线状态、预算、过程指标 |
| 时长 | 限时/限 token（例如 1 次反思 ≤ 3 轮、≤ 8k tokens） |
| 输出 | reflection.md：当前方向、最近动作摘要、是否 attractor、是否该换向、换向需要什么新证据、下一步 3 个动作、要更新的卡/路线/预算 |
| 写回 | meta-prompt、private notes、route plan、pivot policy、成果卡状态；不写回不算完成 |
| 退出 | 把 1–3 条具体变更交给调度 Agent，进入下一个执行阶段 |
| 事后检查 | 反思后 N 个动作内的深化率、pivot 率、attractor 占比、重复率、采纳率 |

### 3.3 反思 Agent 的输入包

- 任务契约摘要（不是全文）；
- 最近 N 个动作的「动作-观察」摘要（不是原始日志）；
- 当前路线状态与预算；
- 3–5 张关键成果卡（含失败卡）；
- 过程指标：pivot 次数、attractor 占比、重复率、验证通过率；
- 问题池（5–6 个）。

输入包控制在 6–8k tokens；太多会变成「再读一遍历史」，太少无法判断。

### 3.4 反思 Agent 的提示词骨架

    You are no longer the executing researcher. You are an external senior researcher reviewing the agent's last N actions.
    You have no authority to run experiments or submit results.
    Review only from the evidence in the input package. Do not solve the task.
    Answer the selected questions, then produce a write-back block with:
    - current direction / is it an attractor / should it pivot;
    - what new evidence would justify a pivot;
    - next 3 actions (type, budget, expected signal);
    - which result card / route / budget to update.
    Never make a global impossibility claim.

### 3.5 失败模式

- 反思变成 attractor：用「反思」逃避做事 → 限时限 token，连续两次无行为变化就降频；
- 只反思不写回 → 强制输出 write-back 块，调度 Agent 拒收没有写回的反思；
- 反思太频繁 → 打断深度工作；按预算区间而不是按 tick；
- 反思 Agent 和被审 Agent 同一个模型 → 自我合理化；至少换模型族，或换人设 + 独立输入包。

## 4. 邻域新颖性：不要为了正交而正交

你这个问题很关键：新颖性搜索如果只奖励「完全正交」，会把大量「往旁边走一步就能解决」的问题逼成无效发散。设计上要把「新颖」拆成两层：

### 4.1 两层距离

| 层 | 参照 | 奖励什么 | 典型动作 |
|---|---|---|---|
| **局部新颖** | 父节点 | 在父节点附近做一个有信号的改动 | 换一个假设、改一个约束、换一个数据结构、补一个边界条件 |
| **全局新颖** | archive/族谱 | 进入一个没被覆盖的行为区域 | 换方法族、换问题表述、跨领域迁移 |

默认应该**奖励局部新颖**；全局新颖只在局部平台期或族分布过窄时给额外预算。

### 4.2 「往旁边走一步」怎么定义

把行为维度定成可枚举的几维（算法任务示例）：

- 方法族（信息增益/几何排除/序列检验/聚类/…）；
- 关键假设（源数已知/未知；噪声已知/未知；单狗/双狗）；
- 数据结构/表示（栅格/粒子/Voronoi/图）；
- 评价条件（Level 1/2/3；预算；场景规模）；
- 复杂度档位。

**「旁边一步」= 只改其中一维，其他维保持**。这样行为距离可测，也不会掉进「为了不同而不同」。

### 4.3 预算分配（参数，不是教条）

| 类型 | 预算 | 准入条件 |
|---|---|---|
| 局部（local） | 60–70% | 有明确指标提升或新条件证据 |
| 邻域（adjacent） | 20–30% | 只改一维；有「为什么可能有效」+ 一步测试 + kill 条件 |
| 正交（orthogonal） | 5–10% | 只在局部平台期/族过窄时开放；必须给新机制/新不变量/新分解 |

每个新节点在创建时声明 `delta_type: local | adjacent | orthogonal` 和 `expected_signal`；调度 Agent 按类型分配预算，不允许「正交」拿走大部分预算。

### 4.4 反「正交自嗨」闸门

- 正交节点必须回答：为什么现有族解决不了？新机制是什么？最便宜的反例测试是什么？
- 没有产物的「新颖」不发探索信用；只有「新测试/新引理/新工具/新条件/新反例」才算；
- 正交失败要进 Record，写清「在什么条件下不行」，防止换个说法再来一遍；
- 局部连续失败 N 次，才允许升级到邻域/正交；不要一上来就换族。

### 4.5 和 Lehman 的「行为混淆」对上

Lehman 原文说：行为表征的混淆要「尊重垫脚石」——把无关差异合并，把有意义的小步保留。对应到你的系统：

- 不要把「代码风格/变量名/日志格式」算进行为距离（这是坏混淆）；
- 要把「假设、条件、方法族、测试通过模式」算进去（这是好表征）；
- 判断标准不是「距离大不大」，而是「这一步有没有让下一步更可能发生」。

一句话：**默认往旁边走，少数情况才跳；跳的时候要给新机制，不是给新说法。**
