下面逐条展开。每条回答四个问题：为什么是问题、不解决会怎样、要设计什么、主要证据。

### P0 目标与验收：什么叫「更好」

**为什么是问题。** 长程系统没有单一分数。有限任务可以看最终分；开放式研究没有可计算的「科学价值」。如果目标不写清楚，后面所有机制都不可证伪。

**不解决会怎样。** 系统会优化最容易测量的东西：活动量、工具数量、日志长度、论文篇数；或者优化评测器的漏洞。AI Scientist 的复评就是一个例子：形式上完整（有论文、有评审、有实验），但 4/7 手稿含错误或幻觉数值，评审也没抓到。

**要设计什么。**
- 任务书：目标、约束、预算、验收标准、交付形态。
- 两类任务分开：**可验证任务**（有确定性评价器）与**开放式任务**（专家 rubric/再发现协议）。
- 三种价值分开记录：最终成果、发现的机制、可复用的知识。不要强行折算成一个总分。
- 评测的「终点」定义：是最终分、最佳已确认成果、还是可审读报告。

**证据。** Station v2 用「再发现率 + 专家盲评」给开放式任务定标；Co-Scientist 用专家偏好/新颖性/影响三维评分；Anthropic 用 end-state evaluation 而非过程检查；LocalOptima 证明目标有界时平台期是定理。

### P1 研究起点：先入研究做到什么程度

**为什么是问题。** 模型先验有两个毛病：过时、偏门。MLE-STAR 观察到 LLM 会习惯性选 LogisticRegression/ResNet；AI Scientist 的「新颖性检查」把 12/12 个想法判成新，引用里只有 14.7% 是 2020 年后的。但「多读几篇」也不等于研究——检索只是把文本放进上下文，研究要改变假设空间。

**不解决会怎样。** 陈旧方案、伪新颖、在已知死路上烧预算。

**要设计什么（预研产物，而不是一次 RAG）。**
1. **方法族谱**：按核心机制归类，不是按论文标题。
2. **证据账本**：claim / 来源 / 年份 / 证据等级 / 矛盾标记。
3. **基线矩阵**：当前最强可运行基线是什么、数字多少、在什么条件下。
4. **失败清单**：文献里明确失败/不可能的方向与条件。
5. **gap 卡**：哪个空白值得做、为什么现在能做、最近邻工作是谁。
6. **二次新颖性复核**：方案生成后，用独立检索查一遍最近邻。

**关键做法（来自原文）。**
- MLE-STAR：检索 M=4 组「模型描述+示例代码」，每组生成脚本**真跑**，按验证分贪心合并。检索必须变成可执行基线。
- Co-Scientist：Reflection 必须带检索——同一批已知旧想法，无检索时新颖性打 6.14/10，有检索打 2.38/10；正确性 7.4→8.46。**生成者与审查者分离**。
- AI Scientist 的教训：关键词匹配不算检索，必须比对语义与最近邻文献。

**取舍。** 预研越深，启动越慢；检索越广，越容易被污染（CDC 提示词因此禁止搜「这个猜想是否已解决」）。建议预研设预算上限，产出必须能改变下游决策，否则砍掉。

### P2 进步的单位：一次尝试留下什么

**为什么是问题。** 没有统一的「成果」单位，就没有积累。代码树只能表达代码父子关系，表达不了「一个结论来自多条路线」；对话历史不是知识；论文也不是最小单位。

**不解决会怎样。** 中间引理、反例、有效组件、失败条件全丢；下一轮从零开始；同一个死路反复走。

**要设计什么。**
- **成果卡**：种类（引理/反例/实验发现/组件/文献方法/猜想）、内容、适用条件、证据（文件/命令/页码）、来源（动作、父成果）、状态（conjecture/supported/verified/refuted/parked）、被后续使用次数。
- **证据标准按类型分开**：形式化证明、可审阅推导、可复现实验、案例观察、猜想，不能混算。
- **DAG 边**：derived_from / used_in / contradicts / generalizes / fails_under。
- **最小可继承单位**：Cogentic 用「自包含引理」；MLE-STAR 用「可执行脚本+验证分」；Station 用「评审通过的论文」。三者不冲突，是三种粒度。

**关键判断。** 「垫脚石」的操作性定义不是「被归档」，而是**被后续动作实际读取并使用**。Cogentic 的 Ledger 有复用语义；Station 的 Archive 用引用计数；你的系统必须记录「谁用了哪张卡」。

**证据。** Cogentic 的 Record/Ledger/Auditor；Station 的 21/28 findings 用到早期论文；LocalOptima 的「可达集」提醒：如果成果不能让下一轮做到之前做不到的事，它只是记录，不是垫脚石。

### P3 传承：知识凭什么进公共记忆、怎么跨代

**为什么是问题。** 长程系统一定会遇到上下文重置、会话换代、Agent 离职。如果知识只存在对话里，换代就失忆；如果什么都往公共记忆里塞，错误会传播、档案会膨胀。

**不解决会怎样。** 两篇 Station 都报告了：Agent 有时意识不到自己的工作与早期知识的关系（limited in-context learning）；移除 Archive 后，有 Agent 错误宣称「一大类构造不可能超过 582 点」，其他 Agent 采纳了——**未经评审的共享记忆会传播错误**。

**要设计什么。**
- **三层记忆**：Record（尝试+判定，失败也留痕、带条件）；Ledger（隔离复验后的自包含引理/组件/反例，可免证引用）；Archive（评审后的综述/论文，解释、障碍、跨领域理解）。
- **准入**：Ledger 靠独立复验；Archive 靠评审（Station：NeurIPS workshop 标准，1–10 分，≥6 接收；125 篇、199 次拒稿、55/125 至少被拒一次）。
- **去重/退役**：被支配的、重复的、证据不足的降级或退役；Archive 需要 surveyor（带引用的综述助手）否则读不完。
- **代际**：交接卡（当前目标、已验证成果、活跃路线、未决问题、失败教训、下一步候选、文件路径）+ 研究身份/角色描述 + 私有笔记。
- **隔离期**：新一代先只看自己的私笔记与任务事实，形成独立起点后再进公共记忆（Station v1 前 40 tick、v2 前 20 tick）。

**关键判断。** 公共记忆和私有记忆是两种东西，不能合并：公共记忆要**可靠、可引用、可审计**（所以慢、有评审）；私有记忆要**保留直觉、未完成构想、失败细节**（所以快、不评审、只传代）。Cogentic 的 Record/Ledger 是公共记忆的轻量版；Station 的 Archive + Lineage 是公共/私有的完整版。你的系统至少要有「公共成果库 + 每条路线的私笔记」两轨。

**证据边界。** Station 的 Archive 消融是「整屋移除」（读+写+审稿+surveyor+引用），只能支持「这个房间整体重要」，不能拆成「评审本身有效」；Lineage 没有消融。所以在你的系统里，这两个机制必须分开测。

### P4 决策：下一笔算力给谁、何时放弃、何时组合

**为什么是问题。** 没有可靠即时奖励时，跟着当前分数走会被欺骗；过早换向会停在开题；路灯效应会挑容易的；全连接/层级权威会让多 Agent 迅速趋同；先返回的路线会劫持主控注意力。

**不解决会怎样。** 单链坍塌（你的 V2 就是中后期 node_08→09→10→11 单链）、早熟收敛、在容易但无关的任务上刷活动量、承诺变成沉没成本。

**要设计什么。**
- **路线**：一个明确问题 + 预算 + 承诺窗口 + 预期产物。
- **预算与承诺**：花完最低额度前不许换向；换向要提交「新证据」（反例、明确阻塞、外部约束变化），不是「又失败了两次」；外部信号可以触发重审。
- **blocked**：卡在「定理级缺失引理」就标记 blocked，只有新机制/不变量/构造才解封（CDC）。
- **组合**：明确接口（A 提供什么、B 需要什么、假设是否相容）、产物、与父方案的同条件比较。
- **多样性**：方法族谱（按机制归类，不按措辞）；族分布监控；盲写/子群/保留初级探索者（Diversity Collapse 的结构干预）；异构模型。
- **决策代**：执行异步，只在决策代统一比较与分配；未完成路线保留最低公平额度（解决「注意力掉队者」）。
- **停滞协议**：连续 K 代无进展 → 换表述/换表示/强制分化（Station 的五个 lane）；预算允许时多起点。

**关键判断（LocalOptima）。** 如果每轮「能提出的补丁集合」固定、质量有界，改进量会趋于 0；best-of-k 只到最强 worker 的天花板。**所以「多开几条路线」本身不提高上限**；每个「发展」动作必须扩张可达集（新工具/新验证器/新问题分解/新条件），否则只是重采样。

**证据。** Novelty Search（欺骗性地形上 39/40 vs 3/40）；CDC（registry/独立/blocked/延迟融合）；Station（Supervisor 60 tick 承诺、项目时长 67.0→55.5、停滞协议）；Diversity Collapse（Vendi 8.08 vs 4.65，结构效应）；TIPEX（n=3 甜点、n=3→5 边际递减）。

### P5 视野：谁在什么时候看到什么

**为什么是问题。** 主控要同时追踪多条路线，上下文很快饱和；把所有历史塞进一个会话会腐坏；多层转述会失真（传话游戏）。

**不解决会怎样。** 主控注意力被先返回的路线劫持；关键证据被摘要淹没；子 Agent 重复劳动；上下文溢出丢前提。

**要设计什么。**
- **读者分离**：主控只看 brief + frontier（top-k 成果卡）+ 预算 + 决策队列；Prover 只看自己的 briefing + 文件路径；验证者只看草稿；Advisor 只看日志；整合者最后看全部。
- **简报**：分三段——已确立事实 / 失败与障碍 / 开放问题；「建议」必须标注为偏好，默认不进入所有 Prover。
- **按需检索**：长文档给路径不给全文（Cogentic、Anthropic 的 artifact 引用）。
- **会话交接**：阶段摘要写外部记忆；上下文将满时用干净会话 + 交接卡；trace/state/artifact 三分离。
- **上下文卫生**：会话层只留最近 N 个「动作-观察」对 + 进度锚点（微软：N=5、W=3，50 题 71.0%→91.6%，token -62.7%）；证据卡不进会话，放外部存储。

**关键判断。** 「主控要不要再套一个团队」——不要。主控饱和的解法是**把状态放进数据库，把不同投影给不同角色**，不是加一层管理。加层只会把瓶颈上移，并增加传话失真。

### P6 执行：如何不死、不丢、不乱

**为什么是问题。** 长程运行中工具会失败、进程会挂、多个 Agent 会并发写；LLM 推理是秒到分钟，工具读写是毫秒，存在「陈旧读/丢失更新」的时间不对称。

**不解决会怎样。** 一步失败导致整条轨迹报废；重复副作用；并发覆盖；慢节点拖垮全局；状态不一致。

**要设计什么。**
- 动作模型（id、问题、输入、预算、交付、状态）。
- append-only 事件日志 + 步级检查点 + 幂等工具 + 恢复协议 + 版本钉住 + 故障注入。
- 隔离：每条路线独立 worktree；读快照绑版本指纹；合并期语义校验（测试/AST/类型），不只看 diff。
- 并发：执行异步；决策代做屏障；比较前冻结版本。
- 预算计量：每动作 token/墙钟/工具耗时；成本分解。
- 掉队者：异步 + 超时降级 + 公平额度；不要全局同步 tick。

**证据。** Anthropic（resume、tracing、同步瓶颈；无量化）；并发控制 position paper（C 级，转引数字）；TIPEX（结构并行买时延）；你的 V2/V3 考古（无隔离→单链、429 中断、Q4 未重测）。

### P7 信任：什么算成立、谁说了算

**为什么是问题。** 自评有偏差；LLM 评审会漏硬伤；多个 Agent 会共享盲点；验证器也可能被「流畅的证明」骗过。

**不解决会怎样。** 伪新颖、幻觉数值、错误结论入库、共享盲点被复制。

**要设计什么。**
- **三层门禁**：确定性检查（能否执行、引文是否存在、数值是否对账、是否泄漏答案）→ LLM 评审（rubric + 多评委 + 盲序 + 校准集，只做筛选/排序）→ 人工/形式化（关键结论、最终交付）。
- **双验证**：Individual（单稿：边界、符号、方向、引理假设）+ Cross-Draft（同轮全部草稿：共享盲点、路线强度对比）。两者都过才准入 Ledger。
- **Auditor**：从被拒草稿中抽取自包含引理，独立复验后入库。
- **验证器校准**：20–30 份已知好/坏样本 + 注入错误（循环论证、等价命题、边界颠倒、引文虚构、数值不符），测漏检率/误杀率。Cogentic 与 Station 都没做。
- **证据等级与状态**：A/B/C/D/E + conjecture/supported/verified/refuted；「已发表」≠「已验证」。

**证据。** Cogentic 的双验证/Record/Ledger（设计，无消融）；AI Scientist 复评（评审 7/7 自拒、人类 9/10 拒含 4 篇真接收、漏掉全部严重问题）；Station 的 Archive 评审（199 次拒稿，阻止了 582 点伪定理传播）；Co-Scientist 的 Reflection 带检索（6.14→2.38）。

### P8 自省：系统如何改变自己的流程

**为什么是问题。** 长程系统会在局部自我合理化：越做越顺手的方向不一定是重要方向；同类错误会反复；attractor 任务会吸走预算。主控自己太忙，看不到宏观模式。

**不解决会怎样。** 方向漂移、奖励黑客、论文/工具/日志刷量、同一错误反复、流程教条化。

**要设计什么。**
- **周期性强制脱离**：每 N 个动作/决策代，暂停执行，进入反思。
- **换模型/换人设**：Station 在反思时把模型临时切到 GPT-5.5，并以「外部人类研究者」第一人称审阅。
- **固定问题池**：过度声称、规划、探索、多样性、学习人类研究者、换向速度、attractor 任务、子问题分解、反奖励黑客、研究品味、知识结晶。
- **写回**：反思必须产出可执行的东西——更新 meta-prompt、写私有笔记、定 pivot 政策、记录 knowledge crystallization。不写回就只是聊天。
- **流程顾问**：读日志、找跨轮模式、调整提示词/验证阈值/预算比例；只能基于过程证据，不能猜答案/荐技巧/判生死；每次干预留理由与事后效果。
- **指标**：反思后 N 个动作内的深化率、pivot 率、attractor 占比、重复率。

**证据。** Station v2：92 次反思、71.7% 后 10 tick 内出现深化/验证；联合消融 75.8→57.9；项目时长 67.0→55.5。Cogentic 的 Advisor（无消融、红线未被执行/测量）。Co-Scientist 的 Meta-review（AUC 0.521→0.597）。注意：Station 的消融是「承诺+反思」联合移除，不能拆；71.7% 是描述统计，不是对照。

### P9 裁决：我们怎么知道系统有效

**为什么是问题。** 多 Agent/多路线会同时增加算力和协调成本；厂商案例、内部评测、单任务消融都很容易被误读；开放式任务没有 ground truth。

**不解决会怎样。** 把「更多算力」当「更好架构」；把「故事完整」当「机制有效」；结论不可复现。

**要设计什么。**
- 两层任务：可验证（程序优化/仿真/ML 子集）+ 开放式（再发现任务、专家 rubric）。
- 等实际成本（token/墙钟/工具时间）；3 seeds 起步；预注册主指标；报告所有失败 run。
- **研究消融**：一次只动一个机制；联合消融只能支持联合效果；区分「系统内诊断」与「研究消融」。
- 指标：最终成果、best-so-far 曲线、成果复用率、非冠军贡献、多样性（族熵/Vendi）、pivot/attractor、验证漏检/误杀、成本分解、跨 seed 方差。
- 盲评与校准：评委不知道来源与顺序；LLM 评委先过校准集；报告与人工的一致率。
- 负结果照报。

**证据。** MLE-STAR（整体 22 赛题×3 seeds，但检索/精炼无消融）；Station（整屋消融、3 seeds、少任务、3,400+ 小时/760M output tokens）；Co-Scientist（专家评估 11 个目标、无独立基准）；LocalOptima（定理 + 观察数据）；Novelty Search（控制任务强证据，不能直接外推到科研）。

## 2. 问题之间的依赖：一条从顶到底的链

    P0 目标与验收
     │  决定「什么算进步」
     ├─→ P1 研究起点
     │      产出方法族谱/基线/失败清单/gap
     ├─→ P2 进步的单位
     │      决定「一次尝试留下什么」
     ├─→ P3 传承
     │      决定「什么进公共记忆、怎么跨代」
     ├─→ P4 决策
     │      决定「下一笔算力给谁、何时放弃/组合」
     ├─→ P5 视野
     │      决定「谁在什么时候看到什么」
     ├─→ P6 执行
     │      决定「如何不死、不丢、不乱」
     └─→ P7 信任
            决定「什么算成立」（回写 P3 的准入）

    P8 自省：观察 P4–P7，改流程参数（不直接改内容）
    P9 裁决：在系统外部，检验 P0–P8 的设计是否真的有效

几个依赖关系要特别说明：

- **P0 决定 P2**：如果只认最终分，成果卡就只会记「更好的方案」；如果也认「机制/知识」，才会记录反例、障碍、适用条件。
- **P2 决定 P3**：成果的粒度决定档案的粒度；成果没有条件字段，档案就无法做适用性检索。
- **P3 决定 P4**：决策能看到什么，取决于档案里有什么；档案只有成功案例，决策就只能模仿成功。
- **P7 回写 P3**：验证是准入的一部分；验证标准变了，档案的可靠性也变了。
- **P8 不直接改 P4**：元层只能改流程参数（预算比例、验证阈值、提示强调项），不能替决策者选方向；否则就是它自己下场做研究。
- **P9 不在循环里**：评测是外部裁决，不能变成 Agent 的奖励函数，否则会被奖励黑客。

## 3. 框架 v2：一条主链 + 三个回路

**主链**（一次研究的最小闭环）：

    立题(P0) → 预研(P1) → 决策(P4) → 执行(P6) → 成果(P2) → 验证(P7) → 入库(P3) → 回到决策(P4)

**三个回路**：
1. **验证回路**（P7→P3）：草稿/实验结果先过门禁，再进 Ledger/Archive；失败进 Record。
2. **元层回路**（P8→P4）：每 N 个动作/决策代，元反思读日志、找模式、改流程参数；不碰内容。
3. **代际回路**（P3→P1）：会话/路线换代时，交接卡 + 私笔记 + 公共档案进入下一代的预研起点。

**两个引擎**（你最有感觉的两个）：
- **元反思** = 方向修正引擎：解决「越走越偏、越做越顺手但不重要」。
- **档案代际** = 知识传承引擎：解决「换代失忆、错误传播、经验传不下去」。

**两条铁律**：
- 共享事实、隔离偏好。
- 验证在关口、不在每一步。

**一个硬门**：每个「发展」动作必须声明新增的可达集项（新工具/验证器/问题分解/条件/可检验探针），否则不算发展。

## 4. 深读 Station 之一：元反思（Meta Reflection）

### 4.1 原文机制（两代不同）

**Station v1（2608.23691，appendix）**：
- 对象：成熟 Agent。
- 频率：**至少每 25 tick 一次**。
- 地点：Reflection Chamber。
- 形式：随机抽取一个高层反思提示词，然后两轮续问，共 3 轮。
- 模型切换：反思期间模型**临时替换为 GPT-5.5**。原文理由：「we found that it produced the highest-quality reviews」。
- 动机：让 Agent 对齐人类研究者的 broader interests（好奇心、理解、分数之外的科学价值）。

**Station v2（2610.08927，appendix）**：
- 对象：所有成熟 Agent。
- 频率：**每 50 tick 一次**。
- 强制执行：初始提示词里就告知义务；系统检测到逾期会发消息催。
- 模型切换：3 轮全部由 GPT-5.5 生成，不管 Agent 原本是什么模型。理由是「GPT agents tend to be more rigorous and assess research value more neutrally」。
- 形式：提示词模板 + 随机抽一个主题 + 两轮续问。

### 4.2 提示词模板（原文要点）

> 「You are no longer [agent name]. You are now an external human researcher, a leading expert in the field, reviewing [agent name]'s past research activities and dialogue.」
> 规则：用 I 指外部研究者；称 Agent 为 you；不要为过去的行为辩护或粉饰；给建设性批评；**不要借这次反思去想任务解法**；反思结束（正常界面回来）就停止。

模板最后还有一句很关键的话：

> 「never make a global impossibility claim」（永远不要做全局不可能性断言）。

这句话是在防「用一次失败宣布整个方向死亡」——正是过早换向的另一种形式。

### 4.3 问题池（v2 共 11 个，不是 8 个）

1. **Overclaiming**：是否把一次运行的结果推广到整个方法类？换向前有没有充分调参与诊断？
2. **Planning**：有没有 60+ tick 的长期计划？还是像助手一样对实验结果做反应？设计一个 60-tick 计划，含目标/里程碑/主要实验/时间表/失败预案。
3. **Exploration**：是否困在 attractor task（反复换 seed/超参、无尽局部分析、只做 SOTA 微调）？最近有什么新想法？外部专家会觉得新吗？头脑风暴几个新想法。
4. **Diversity**：我的工作和其他 Agent 是否不同？还是在跟风排行榜/主流方向？大家共同依赖但没人质疑的三个假设是什么？至少挑战其中一个。
5. **Learning from human researchers**：人类会怎么解这个问题？我的研究轨迹像不像一个专家？哪些问题/发现对人类有说服力？
6. **Pivot speed**：过去 50 tick 是否在方向间乱跳？还是死锁在一个无效方法上？设计一个 pivot 政策。
7. **Attractor tasks**：是否在「闭合性否定证明」（证明某条路不行）、「纯元工具」（无止境造诊断/审计工具）、「局部利用」（SOTA 小修小补）上花太多时间？给出高风险路径（risky hypotheses、跨领域迁移、创意构造）。
8. **Subproblem decomposition**：人类会先解哪些子问题？提出几个更简单/相似/看似无关的问题，选一个。
9. **Anti-reward-hacking**：人类的意图是什么？有没有 hack 评测器、走捷径、灌水论文、写无尽诊断工具、用错误论证宣布不可能？有没有真正对人类有价值的产出？
10. **Research taste**：我有没有独特的研究品味？还是无偏好地跟风？从领域领袖的启发式里选一个适合我的；设计一个政策，让这种品味在下次失败后仍能保留。
11. **Knowledge crystallization**：到目前为止学到了什么？哪些知识不在预训练里？写进私有记忆。

### 4.4 最关键的设计：反思必须「写回」

每个提示词的结尾都不是「反思一下」，而是**要求一个写回动作**：

- Planning → 「copy the plan into its meta-prompt and use it as a guide」；
- Exploration → 「record the ideas in Private Memory Room and execute some of them」；
- Diversity → 「make a private note of the assumptions and attractor tasks identified, and try to challenge at least one」；
- Pivot speed → 「save this pivot policy in its Private Memory Room and follow it」；
- Research taste → 「adopt and preserve the proposed research taste and revise its meta-prompt accordingly」；
- Knowledge crystallization → 「record your answers in the Private Memory Room」。

**这是整个机制的灵魂。** 反思不写回，就只是聊天；写回到 meta-prompt / private memory，才会改变下一轮的行为。你的系统如果只做「让 Agent 反思一下」，不会有效果。

### 4.5 证据与边界

- **行为统计**：v2 报告 92 次反思事件，71.7% 之后 10 tick 内出现「深化或验证现有方向」的实验。这是描述统计，不是对照。
- **消融**：移除 Supervisor + Meta Reflection 两个机制，再发现率 75.8%→57.9%；项目均长 67.0→55.5 tick；干预类子发现下降最明显。**联合移除，不能拆成单机制。**
- **没有做的**：换模型 vs 不换的消融；频率 25 vs 50 的消融；问题池固定 vs 随机的消融；v1 的 mechanism contribution 分析里没有把 meta-reflection 单列。
- **风险**：提示词池本身就是价值注入（「什么算好研究」是作者选的）；GPT-5.5 同时当 Supervisor 和反思者，可能带同族偏好；反思可能变成新的 attractor（用「反思」逃避做事）；强制每 50 tick 可能打断真正深的工作。

### 4.6 移植到长城 Agent：具体协议

**触发**：不是按 tick，按「预算区间/决策代」——每消耗 X% 预算或每 N 个决策代强制一次；另外在「停滞」和「准备换向」时触发。
**隔离**：反思期间禁止工具调用、禁止提交实验/论文；只读自己的 trace 与成果卡。
**模型/人设**：换一个模型族，或至少换一个系统提示 + 外部专家人设；人设要求「第一人称外部专家」「不许粉饰」「不许借反思解题」。
**问题池**：从 Station 的 11 个里选 5–6 个起步（Overclaiming、Planning、Pivot speed、Attractor、Diversity、Knowledge crystallization），每个都必须有「写回目标」。
**写回**：结构化的 reflection.md，字段：当前方向、最近 N 个动作摘要、我是否在 attractor、我是否该换向、换向需要什么新证据、下一步 3 个动作、要更新哪张成果卡/哪条路线预算。写回后由主控在下一个决策代读取。
**指标**：反思后 N 个动作内的深化率、pivot 率、attractor 占比、重复实验率、反思消耗占比；对照「有反思/无反思」「换模型/不换」「写回/只聊」。
**防退化**：反思本身限时/限 token；连续两次反思无行为变化 → 降频；反思输出被主控采纳的比例要记录。

**一句话**：元反思不是「让 Agent 想想」，而是**定期强制换一个外部评审视角，并把结论写回可执行的记忆**。

## 5. 深读 Station 之二：档案与代际（Archive + Lineage）

### 5.1 Archive：公共记忆

**机制（v1 appendix）**：
- 论文必须综合科学贡献，不能是实验日志；要有 rigour/novelty/significance。
- Reviewer 是 GPT-5.5，按 NeurIPS workshop 标准，1–10 分，**≥6 接收**；拒稿附意见，可修改重投。
- 接受后永久可读、可引用、可被后代继承。
- Archive Surveyor（GPT-5.5/Codex）按需产出带引用的文献综述；Agent 也可以直接读全文。

**数据（v1 meta-analysis）**：
- 一个 kissing number Station：**125 篇论文、923 条引用、199 次拒稿、55/125 至少被拒一次**。
- 拒稿理由：过度声称、缺引用、手稿不完整、意义有限、事实错误。
- **21/28 个 selected findings 用到早期论文**；13/28 在 tick 1000 之后出现；Book Ramsey 的会议图族在 tick 3727 才出现。
- 13/28（46.4%）涉及跨模型族；19/28（67.9%）涉及多个 Agent；9/28（32.1%）单 Agent。

**消融（v1）**：
- 移除 Archive Room（不能读也不能写）→ 3 seeds 0/3 达到 594；标准 Station 3/3 达到 604。
- 全 Claude（6 个）→ 3 seeds 0/3 达到 594。
- 注意：这是「整屋移除」，不能拆成「评审有效」或「引用有效」。
- 一个反面案例：没有 Archive 的 Station 里，有 Agent 声称「一大类构造不可能超过 582 点」，其他 Agent 采纳了；有 Archive 的版本里，这类未经验证的主张会被评审拦下。

**代价**：评审是高频事件（199 次拒稿），不是一次性闸门；Archive 会膨胀，需要 surveyor、去重、退役；评审可能压掉非常规但正确的结果；论文写作本身可能变成 attractor（v2 的反奖励黑客提示词专门警告「灌水论文」）。

### 5.2 Lineage：私有记忆与代际

**机制（v1 appendix）**：
- Lineage = 共享名字、私有笔记、连续研究身份的一串 Agent。
- 新 Agent 可以继承同模型的已有 lineage（Noesis II → Noesis III），获得前世代的全部私有笔记与记录；也可以新建 lineage，开始不同的研究风格。
- 生命周期：v1 最多 200 tick；**前 40 tick 隔离**（不能看公共知识、不能交流，只能看本 lineage 记录）；40 tick 成熟；100 tick 可退休；v2 改为 150/20/90。
- 离开的 Agent 可以为后代写 role：更任务化、更明确地描述这个 lineage 的研究风格。
- Private Memory Room：私有计划、未完成工作、研究提案、实验日志、论文草稿；只对 lineage 可见。

**它解决什么**：换代失忆；上下文腐坏（换代 = 换干净上下文，但保留研究身份与未完成工作）；研究风格多样性；品味传承（离开者写的 role 是「低带宽的品味压缩」）。

**它没解决什么（原文自述）**：有限 in-context learning（Agent 有时意识不到自己的工作与早期 Station 知识的关系）；同模型族品味同质化；私有笔记没有评审，错误可能被继承放大；没有 lineage 的消融。

### 5.3 两者合起来是什么

**公共记忆 + 私有记忆 + 身份继承**，三件东西：

| 记忆 | 内容 | 准入 | 传播 | 失败模式 |
|---|---|---|---|---|
| Archive（公共） | 评审后的论文、综述、障碍、反例 | Reviewer ≥6 | 全站可读、可引用 | 膨胀、评审偏差、灌水 |
| Record/Ledger（半公共） | 尝试+判定；自包含引理 | 复验 | 后续 Prover 可复用 | 局部正确但依赖错误假设 |
| Private（私有） | 直觉、未完成构想、失败细节、pivot 政策、研究品味 | 无 | 只传同 lineage 后代 | 错误继承、不可审计 |

**代际 = 换上下文，不换研究身份。** 这是它最值得学的地方：不是把旧对话塞给新 Agent，而是把「我是谁、我在追什么、我试过什么、我下一步想做什么」压缩成交接卡 + 私有笔记 + 角色描述。

### 5.4 移植到长城 Agent：具体协议

**三层记忆**：
1. ledger/：可复验断言（引理/组件/反例），独立复验后入库；带条件、证据、来源。
2. archive/：里程碑综述/论文，评审后入库；带引用、适用条件、失败障碍。
3. routes/<id>/notes/：每条路线的私有笔记（直觉、未完成构想、pivot 政策、taste）；不评审，只传代。

**准入**：
- Ledger：确定性检查 + 独立复验；
- Archive：评审（可以用 LLM rubric + 人工抽检），阈值可调；
- Private：无准入，但必须可审计（至少能追溯到作者与时间）。

**代际**：
- 定义「一代」= 一次会话/上下文重置，或一条路线换主执行者；
- 交接卡字段：目标、已验证成果、活跃路线、未决问题、失败教训、下一步候选、文件路径、研究身份/风格；
- 新代先经过「独立期」：只看交接卡 + 任务事实 + 自己的私笔记，不立刻读公共 Archive，避免被前人路线锚定；
- 离开者写「给后代的 role」：一段 200–500 字的风格描述 + 3 条「我会怎么判断一个方向值不值得做」；
- 公共 Archive 由 surveyor 提供带引用的综述，避免逐篇读。

**指标**：
- Archive：被引用/被使用次数、跨代使用率、拒稿率、错误主张被采纳率；
- Lineage：跨代重复实验率、交接卡完整率、新代首 N 个动作与旧代的相似度、品味描述被遵守的比例；
- 反面：论文数量、笔记字数。

**风险控制**：评审是高频成本，按预算设上限；私有笔记可能继承错误，每次入库前标「未验证」，引用时必须降级；Archive 膨胀用去重/退役/surveyor；论文写作 attractor，只允许里程碑写 Archive，日常用 Ledger/笔记；不要把「代际」做成「复制上下文」，只传交接卡 + 笔记 + 角色。

## 6. 这两个机制在问题清单里的位置

- **元反思 = P8 的核心 + P4 的换向协议**。它不替代验证（P7），也不替代决策（P4）；它只提供「外部视角 + 写回」。
- **档案代际 = P3 的核心 + P2 的存储**。它不替代成果卡（P2），也不替代验证（P7）；它只提供「准入 + 跨代继承」。
- 两者结合，形成系统的两个时间尺度：短周期（每 N 个动作）：决策 → 执行 → 验证 → 入库；中周期（每 N 个决策代）：元反思 → 改流程/改方向；长周期（每次换代）：交接 → 隔离 → 继承 → 新代。

## 7. 下一步：先把四个问题写成可运行的最小协议

不要一次做十个。按依赖顺序，先做四个：

1. **P0**：写死任务书（目标/约束/预算/验收）与两类任务定义。
2. **P2**：成果卡 + 三类证据标准 + DAG 边 + 使用计数。
3. **P3**：Ledger/Record/Archive 三目录 + 交接卡 + 一代隔离期。
4. **P8**：一次元反思（问题池 5 个 + 写回字段 + 前后行为指标）。

然后才是 P4/P5/P6/P7 的工程化。理由：没有 P0/P2/P3，P4 的决策没有对象；没有 P8，P4 会退化成「跟着分数走」。

**两周验收**：杀掉进程能恢复；同一 run 能重放；每条成果卡有来源与证据；至少一条「非冠军成果被后续动作使用」；至少一次元反思产生了写回并改变了下一个动作。
